## Why

版块态势页的矩阵只表达「量」：每格是当日非综合稿线索数，颜色是行内相对热度。用户能看出哪条泳道这阵子热，却看不出「哪一天出了大事」。关键事件注记（`topic_key_event_markers`，人工确认口径）已经存在并按话题 + 日期落库，但矩阵不下发、也不展示它；2026-11-21 实测该版块 5 条 confirmed 事件里 4 条挂在候选话题上，矩阵只画 active 泳道，等于事件被折叠进「当日其他话题」，不先选中那天就看不见。

需要的是**同一张矩阵骨架的另一个读数**：行还是话题、列还是日期，把格子换成「这段时间的关键事件名称」，像生命线一样铺在时间轴上。不是给量视图加装饰，而是加一个同级视角。

## What Changes

- 版块态势页主舞台新增同级视图切换：`矩阵 / 追踪`（现有）↔ `关键事件`（新）。两者共用**同一个时间视窗控件**、同一份行序与同一组选中状态（选中话题 / 选中日）；时间范围由用户在同一控件里选（14 天 / 30 天等）。
- 关键事件视图渲染规则：
  - **只渲染持久化话题（active）**，行序沿用矩阵现有排序（`lane_heat` 降序 → 全窗线索合计降序 → topic ID 升序）；候选话题（candidate）**不占行**，其事件不在本视图呈现；
  - 行内为一条横向日期轴，事件节点落在 `source_period_date` 当天，节点旁直接显示事件名称（`title_snapshot`）；
  - 同日多条事件竖向叠放；相邻事件标签上下交替避让，不截断成三字残句；
  - **长窗（观察窗超过 30 天）仍显示事件名称**：标签收起只由「堆叠层数超上限」触发，MUST NOT 因天数长就整体收成光点（2026-11-23 用户实机反馈修订，见 design D7）；
  - 无事件的日期为空白轴，不画节点、不伪造 0；
  - 只透 `state='confirmed'` 的注记（与生命线回看口径一致），`suggested` 永不进入本视图。
- 选中行为沿用既有受控契约：点话题行 → 与矩阵同一个选中泳道；点事件节点 → 与矩阵同一个选中日；下方阅读区不再新造第二份状态。
- **右轨发起的选中切回矩阵**：从右轨（当日其他话题 / 话题条目）选中话题时，主舞台切回「矩阵 / 追踪」视图并把该泳道滚入视野 + 高亮——候选话题在本视图不占行，不切回就是死选择（2026-11-23 用户实机反馈修订，见 design D14）。本视图内部的选中仍留在本视图。
- 时间范围共用：矩阵支持 7/14/30/365 档与自由区间；要看某一时段的 30 天，就在同一时间视窗里切 30 天，关键事件视图随之重算，MUST NOT 维护第二套跨度状态。
- 事件卡闭合到来源文章：展开确认时冻结的关联文章（`article_ids_snapshot`）→ 点文章走既有站内阅读（`ArticlePreviewModal`）→ 关闭回到原卡，形成「事件 → 文章 → 阅读」闭环。
- 后端新增版块级批量读：窗口内全部 confirmed 关键事件（按话题 + 日期聚合），供本视图一次取全；不改变现有「按单个话题读」的端点语义。
- 空事件版块（无 confirmed 注记）仍保留视图切换入口（同级视角不随数据消失），视图内如实说明「这段时间没有确认的关键事件」并指向日报阅读台的确认入口，MUST NOT 用一条空轴冒充有内容。

**非目标（Non-Goals）**：

- 不在本视图内提供注记的确认/取消/编辑动作（那是日报阅读台 `KeyEventMarkerActions` 的职责）。
- 不把 `suggested` 或系统派生的结构事件（突增/复苏/首次出现）混入关键事件口径。
- 不把候选话题（candidate）的事件并入本视图；候选转正后自然出现在对应行。
- 不改变矩阵视图自身的格值、色深、行序、休眠判定与当日其他话题计数。
- 不改动 `GetTopicLifeline` 的既有响应形状。

## Capabilities

### New Capabilities

（无——本次是现有能力的扩展，不新建 capability。）

### Modified Capabilities

- `workshop-board-console`：新增「关键事件视图（话题行生命线）」需求——视图切换、持久化话题行集合、事件节点与名称标签、标签避让、空态与降级、与矩阵共用时间视窗与选中状态。
- `topic-key-event-markers`：新增「版块级关键事件批量读」需求——按版块 + 窗口返回 confirmed 注记，按话题 + 日期聚合，供矩阵级视图一次取全；现有 topic 读端与写端语义不变。

## Impact

- **前端**：`front/app/features/tags/components/console/`（主舞台视图切换、新视图组件、事件标签布局）；复用 `observationLanes` 行序与 `visibleAxis` 日期轴模型，不新建第二份行序实现。
- **后端**：`backend-go/internal/topicgraph/handler/` 与 `repository/`（新增版块级批量读端点，复用 `topic_key_event_markers` 索引 `idx_topic_key_events_topic_state`）。
- **数据**：只读既有 `topic_key_event_markers`，无 schema 变更、无迁移。
- **API**：新增一个 GET；既有端点不变。
- **破坏性**：无。
