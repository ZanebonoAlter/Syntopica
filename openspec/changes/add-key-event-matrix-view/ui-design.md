# UI 设计契约：关键事件视图

## User Journey

- **入口**：`/tags/:boardId` 版块态势页 → 顶部视图切换组新增「关键事件」，与「矩阵 / 追踪」「文章归档」同级。
- **主任务**：扫一眼「这段时间哪几天有做出确认的关键事件、事件叫什么」。时间范围与矩阵共用同一控件，要看 30 天就在那里切。
- **次任务**：点某天的事件 → 选中该日，下方阅读区显示当天全部关键事件（标题 + 摘要 + 所属话题）；点行头 → 选中该话题，与矩阵共用同一个选中态。
- **不承担**：注记的确认 / 取消 / 编辑（日报阅读台 `KeyEventMarkerActions` 的职责）。

## Information Architecture

```
版块态势页（workspace）
├── 面包屑：主页 › 叙事工坊 › 版块名
├── 版块栏（左，独立滚动，不变）
├── 主舞台
│   ├── 视图切换组：[矩阵 / 追踪] [关键事件] [文章归档] [研究工作台]
│   ├── 时间视窗（与矩阵**共用同一个控件**：7 / 14 / 30 / 365 档与自由区间；切换带出两侧视图）
│   └── 关键事件视图（替换矩阵网格区域）
│       ├── 行头列：话题名 + 状态徽标（持久化）+ 事件数与最近事件日
│       ├── 日期轴列：与矩阵同一 `visibleAxis`，逐列对齐
│       └── 行内：横向生命线 + 事件节点 + 事件名称标签（长窗收起）
├── 下方阅读区：当日关键事件列表（选中日驱动，与矩阵共用 selectedDate）
└── 治理右轨（不变）
```

- 行集合与矩阵同源：**只渲染持久化话题（active）**，按现有行序（`lane_heat` 降序 → 全窗线索合计降序 → topic ID 升序）各占一行；候选话题不占行、其事件不在本视图出现。
- 时间范围共用：不维护第二套跨度状态，避免两张表时间尺度不一致。

## Interaction Contract

| 操作 | 触发 | 结果 | 反馈 |
|---|---|---|---|
| 切换视图 | 点「关键事件」/「矩阵 / 追踪」 | 保留选中话题、选中日、观察窗，只换主舞台内容 | 分段按钮 `aria-pressed` 切换 |
| 选中话题 | 点行头 | 与矩阵同一个 `selectedLane`，下方阅读区跟随 | 行头高亮 + 左侧强调条 |
| 选中日 | 点事件节点或标签 | 与矩阵同一个 `selectedDate`，下方阅读区切到该日关键事件 | 节点描边 + 整列淡底 |
| 查看事件全文 | 选中日内联 | 展开该条 `summary_snapshot` 全文，其余收束 | 就地展开，不弹层 |
| 展开关联文章 | 事件卡「关联文章 N 篇」 | 卡内展开文章列表（标题 + 来源 + 日期） | 按钮变「收起文章」 |
| 打开文章预览 | 点文章行 | 走既有站内阅读链路（`ArticlePreviewModal`）打开全文 | 遮罩层；Esc / 关闭回到原事件卡，滚动位置不变 |
| 右轨选话题 | 点右轨「当日其他话题」/ 话题条目 | **切回「矩阵 / 追踪」视图**，并把该话题泳道滚入视野 + 高亮（候选话题在关键事件视图里没有行，不跳回就等于选了个寂寞） | 分段按钮切回矩阵；该泳道左强调条 + 高亮 |
| 失败重试 | 错误条上的「重试」 | 重新拉版块级关键事件 | 按钮内 loading 文案 |

- **无危险操作**。本视图只读，不提供任何写动作。
- 切换视图 MUST NOT 重置 `selectedLane` / `selectedDate` / 观察窗；也从 URL 恢复（与矩阵同一套 query）。

## Interaction Decisions

| ID | 决策 | 模式 | forbidden | 状态 |
|---|---|---|---|---|
| D1 | 矩阵与关键事件视图切换 | `page` | `dialog`, `drawer` | `pinned` |
| D2 | 事件详细内容（摘要 / 所属话题）的呈现 | `page` | `dialog`, `drawer` | `pinned` |
| D3 | 事件标签重叠避让 | `page` | 省略号截断（`text-overflow: ellipsis` 于标签本体） | `open` |
| D4 | 右轨选话题后的视图联动（切回矩阵 / 追踪） | `page` | `dialog`, `drawer` | `pinned` |

- D1 依据：用户 2026-11-21「同级视角 / 类似 tab 切换视图」。P 判据：视图是同页信息的两种读数，不是独立任务，故 `page` 而非 `panel`。
- D2 依据：保留时间轴上下文，就地更新下方阅读区；弹层会切断「事件在轴上的位置」与「内容」的对应关系。
- D3 为待评审的布局规则，不是交互模式变更；候选方案见 Prototype 的「标签避让」区。
- D4 依据：用户 2026-11-23「我选了右侧的泳道等应该跳转回矩阵追踪视角」。P 判据：右轨选中动作的落点是**泳道行**，泳道行只存在于矩阵 / 追踪视角 → 事件视图里跳过去无处可落，属于「换视图」而非「开浮层」。
- D4 适用范围：右轨「当日其他话题」/ 话题条目等**从右轨发起的选中**；本视图内部的选中（点行头、点节点）仍留在本视图。
- 时间范围不单列为决策：用户 2026-11-21 明确「时间选择器和矩阵这边共用一个即可」，两侧共用同一控件。

## Data Provenance

| 数据项 | source | 说明 |
|---|---|---|
| 话题行（名称 / 状态） | `api GET /semantic-boards/:id/lane-dynamics` | 现有端点；只取 active 行原序 |
| 日期轴 | `派生 visibleAxis（观察窗起点 + 可见日数）` | 与矩阵共用 |
| 事件名称 | `表 topic_key_event_markers.title_snapshot` | 仅 `state='confirmed'` |
| 事件日期 | `表 topic_key_event_markers.source_period_date` | 已按天 |
| 事件所属话题 | `表 topic_key_event_markers.topic_label_snapshot` | 确认时快照，不反查实时改名 |
| 事件摘要 | `表 topic_key_event_markers.summary_snapshot` | 选中日内联展开 |
| 关联文章 | `表 topic_key_event_markers.article_ids_snapshot` → `api GET /articles/:id` | 确认时冻结的 ID；标题/来源/日期走既有文章读取与缓存 |
| 当日事件计数 | `派生 按 source_period_date 计数` | 同一天多条 |

## 明确不做

- 不在关键事件视图内出现「确认 / 取消 / 编辑注记」按钮（此类动作只出现在日报阅读台）。
- 不显示 `suggested` / `dismissed` 状态的注记。
- 不渲染候选话题（candidate）行，也不把候选话题的事件并入本视图。
- 不把系统派生的结构事件（突增 / 复苏 / 首次出现）混进本视图的事件节点。
- 不在 `<768px` 渲染关键事件视图与其切换按钮（窄屏只渲染版块摘要，沿用现有降级）。
- 不在事件标签上用省略号把标题截成「黄仁勋婚外…」这类残句。
- 不新增第二份 `selectedLane` / `selectedDate` 状态。
- 不改变矩阵视图的格值、色深、行序、休眠判定、当日其他话题计数。
- 不在本视图内嵌第三种阅读器；文章预览只走既有 `ArticlePreviewModal`。
- 不硬编码任何亮色/暗色字面色值；颜色一律走 `--color-*` 语义变量（双主题）。
- 不以「观察窗天数」作为收起事件名称的唯一依据（长窗必须仍看得见事件名）。
- 不在本视图内处理来自右轨的话题选中：右轨选中一律切回「矩阵 / 追踪」视图再落点。

## State Matrix

| 状态 | 触发 | 呈现 | 恢复路径 |
|---|---|---|---|
| loading | 首次进入 / 切版块 / 换观察窗 | 主舞台骨架，行头与轴占位；视图切换仍可点 | 数据到位自动替换 |
| empty（无注记） | 窗口内 0 条 confirmed | 日期轴与行集合**照常渲染**（避免布局跳），行内只有无节点的空轴；轴上方一行说明「这段时间没有确认的关键事件 · 在日报阅读台标记」 | 去日报阅读台确认后刷新 |
| empty（无泳道） | 版块无持久化话题 | 显示「该版块暂无持久化话题」（诚实空态，不补候选行） | 无 |
| error | 版块级事件读取失败 | 视图内错误条 + 「重试」；MUST NOT 冒称 0 条，MUST NOT 用空轴代替失败 | 点重试；失败保留上次成功内容并标注陈旧 |
| stale | 刷新失败但已有内容 | 保留内容 + 「刷新失败，展示上次数据」条 | 重试 |
| success | 有 ≥1 条事件 | 行内节点 + 名称标签；选中日整列淡底 | — |

## Layout Contract

- **layout mode**：`workspace`（继承版块态势页；`AppPageShell mode="workspace" :gutter="0"`）。
- **目标视口**：1440×900 与 1920×1080；两档均要求无页面级横向滚动。
- **栏宽与溢出**：版块栏与治理右轨宽度不变；主舞台占满可用宽度（`workspace` 无固定上限）。列宽 = `max(64px, 主舞台可用宽 / 可见日数)`：超宽屏（2560）下 14 天约 165px/列、30 天约 77px/列，**均分填满**；视口不足以 64px 为下限，画布撑宽由**舞台容器内部横向滚动**承接（行头 sticky，滚动时自动把选中日拉入视口），MUST NOT 产生页面级横向滚动。标签收起**按堆叠层数上限**判定，不按观察窗天数一刀切：层数 ≤ 4 层时照常显示事件名称；只有层数超上限（行高超 246px）才退化为「节点 + 当日事件计数」，名称由选中日阅读区承担。
- **横向平移**：舞台空白处按住左键拖动即平移（与新建泳道画布同手感）；位移未超 5px 不回退为平移，避免误触节点/标签。
- **行高**：基础行高随行头内容（话题名 2 行 + 事件计数）约 70px；有事件的行按标签避让层数增高（每层 +44px，**上限 4 层 → 行高封顶 246px**）；无事件行保持基础行高并使用虚线轴。
- **长窗（观察窗 > 30 天）**：MUST NOT 因为天数长就整体收起事件名称——用户 2026-11-23 实测「55 天窗口只剩光点，啥都看不见」。可见日数再多也只是**列更宽更稀**，名称照常显示；真正收起与否只看**堆叠层数是否超上限**。
- **窄屏**：`<768px` 不渲染本视图（与矩阵同一降级路径）；切换按钮一并隐藏。
- **双主题**：亮/暗两套主题 MUST 复用产品语义变量（`--color-bg-base` / `--color-text-*` / `--color-border-*` / `--color-accent` / `--color-warning`），MUST NOT 写死色值；节点、标签、选中列、文章预览层在两套主题下都要单独过一遍对比度。
- **dialog**：本视图自身不新增弹窗；文章预览复用既有 `ArticlePreviewModal`（`md` 档 560 / `lg` 档 760，随既有实现）。

## Prototype

- 路径：`ui-prototype/index.html`（可点 HTML 静态原型，不连真实 API，数据来自 `fixture.json`）。
- 覆盖：矩阵 ↔ 关键事件切换、时间视窗共用（7/14/30 天）、6 条持久化话题（候选不占行）、同日多事件叠放、相邻标签避让、选中日联动、空态与失败态。
- **原型定位（用户 2026-11-21 明确）**：`ui-prototype/` 只做**功能布局与骨架参考**，不是 1:1 像素级实现基线；实现以本文件合同与本 change 的 specs/design 为准，间距、字号、装饰按产品主题与既有组件规范落地。
- 原型内**不出现**注记写动作，不出现 `suggested` 事件。

## Acceptance

- agent-browser 断言：时间视窗与矩阵共用；行数 = 6 条持久化话题（不出现候选行）；11-18 行出现 3 个事件标签；点节点后下方阅读区出现同日 3 条事件标题。
- 切到 30 天：列宽仍为 64px，舞台内出现横向滚动，选中日自动滚入视口，标签不重叠。
- 1440×900 与 1920×1080 两档截图，确认无页面级横向滚动、标签不重叠、列与行头对齐。
- **长窗断言**：观察窗切到 > 30 天（55 天量级）时，事件名称**仍可见**（不整体收成光点），行高未超上限；层数超上限的行才显示「节点 + 当日事件计数」。
- **右轨联动断言**：在关键事件视图里点右轨「当日其他话题」任一条 → 视图自动切回「矩阵 / 追踪」，且该话题泳道被滚入视野并高亮。
- 与批准原型的差异说明写入 `ui-verification/report.md`；信息架构 / 主流程 / 布局模式有变时重置 `ui-approval: pending`。
