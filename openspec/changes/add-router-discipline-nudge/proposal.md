# 主线程该派出去的活：可观测信号 + 显式豁免

## Why

用户的诊断（原话）：

> 其实这种活按照规范应该让子线程来，避免上下文污染的，这个就是我后面想说的各自干各自的事
> 注意也要能豁免并上报理由，例如改小 bug

「主线程只调度不写实现」在仓库里是既有纪律，但它是**靠自觉**的。实测一次会话：

| 指标 | 数值 |
|---|---:|
| 主线程工具调用 | **995 次** |
| 子线程派发 | 25 次（多数是 review，探索与实现派得极少） |
| 其中「读 721 行源文件 / 改三个函数 / 调 15 轮 smoke」这类活 | 全部在主线程 |

**关于成本对比的更正（review R-3）**：立项初稿写过「主线程 $44.96 vs 子线程 $0.015，单价差 2600 倍」——**这个数是错的**。`session.rollup.models` 的口径是「当前会话 jsonl 里 assistant 消息按 `message.model` 聚合」，即主线程自己切模型的桶；`subagent.dispatch` 的 `cost` 字段全部为 null，子线程成本在派发账本里根本没有。两个数还分属不同口径（后者是前者的一部分），相除没有意义。**本 change 因此只保留可核对的计数事实**（995 vs 25），不引用任何成本倍数。

**这与本仓库刚修掉的 `ui-stage` marker 是同一个病**：任何「让执行者自己判断要不要做」的规范都有同一个漏洞——它可以选择不做。区别只是 marker 漏申报，这里漏派发。

## What Changes

### 1. 把「该派的」缩到两个可观测信号

不去判「这个任务该不该派」（主观、必然吵架），只观测两处**行为事实**：

| 信号 | 阈值 | 为什么是它 |
|---|---|---|
| 单次 `read` 行数 | > 200 行 | 规范本就写「主线程 read 仅限约 200 行内定点核对」，只是从来没守卫 |
| 同一文件连续 `edit` | ≥ 3 次 | 说明进了「改—跑—挂—改」调试循环，这正是最该外包的形态 |

### 2. 软提醒，不阻断

`.pi/extensions/router-discipline.ts` 在信号出现时 `steer` 一句提醒（每会话每类各一次），说明该派 explore 还是 general-purpose，并附成本对比。**不阻断**——小修确实常常不值得派，硬拦会误伤。

### 3. 豁免必须带理由，且进事实库

```bash
bash scripts/harness/router-discipline.sh --excuse "改一个 typo，单行改动，不值得派子线程"
```

- 理由**非空**才算豁免（空理由无效）
- 豁免写入 per-session 文件，扩展读到后静音本会话提醒
- 同时记一条 `policy=router-discipline` / `action=bypass` / `reasonCode=router-excused` / `detail=<理由>` 到事实库

与 `ui-skip` / `doc-impact-excuse` 同一纪律：**显式留痕优于隐形跳过**。marker 可以不写，豁免必须写出来。

### 4. 分工判据写进规范

`开发执行规范.md` §主线程纪律 补一张五行的表：探索/实现/验证外包，判断/验收留主线程。

## 不做的事

- **不做硬阻断**：连续 edit 超限就 block 会误伤真·小修，而这类误伤每次都有人要绕过，最后变成一排 `--force`
- **不用 LLM 判「这个任务够不够大」**：那只是把主观判断换个位置，还多一次调用
- **不统计「派发比例」做门禁**：比例高低不等于质量，可能只是 task 拆得粗细不同
- **不接管 `session.rollup` 的成本记账**：已有，本 change 只在提醒文案里引用它的实测值

## Impact

- **新增**：`.pi/extensions/router-discipline.ts`（约 150 行）、`scripts/harness/router-discipline.sh`（约 60 行）
- **文档**：`开发执行规范.md` §主线程纪律
- **零前端 / 零后端改动**
- **风险**：提醒本身耗费 token（每会话最多 2 条短消息，可忽略）；豁免文件在 `.pi/tmp/`（gitignore）不留仓
- **可回检**：`router-excused` 事件的理由文本可事后抽查，判断豁免是否被滥用

## 已知残留

- 阈值（200 行 / 3 次）是经验值，不是标定值。若发现频繁误报，改常量即可，不必走 change
- 只能观测 `read` / `edit` 两个工具。用 `bash` 的 `cat`/`sed` 读大文件绕不过提醒——这是既有边界（shell 通道不在多数门禁覆盖范围），也是本 change 明确接受的
