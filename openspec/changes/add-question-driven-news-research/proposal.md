# 面向普通读者的问题驱动新闻研究

## Why

个人读者不应先懂政治、经济研究方法，才能从新闻中获得解释。现有信号研究已有聚合材料、手动触发与报告工作台，但选题偏重异动，研究只开放七类数据源，容易把军事、政策与社会问题转成现有工具能回答的价格问题：有数据、有报告，不代表回答了原题。

## What Changes

- 复用版块周期材料和泳道背景发现值得理解的“变化、解释、影响”问题；一个候选聚焦一个主问题，说明理解价值、尚未确认的部分及首个核查方向。不逐篇调用模型，不要求跨泳道，不固定推荐三条，不凑候选。
- 新发现保存版本化研究简要说明与相关存文的有限快照；正文只在候选形成后从本地按关联取样冻结，不送入发现模型。用户点击研究后先读这些来源核查前提，再决定补证或提前成文。
- 为新协议候选复用现有 Bocha 搜索；新增 signal 专用安全网页读取适配（复用 safefetch 与已有 readability 解析依赖），按本次问题和来源白名单取证。文字证据与数值证据并存，仍受40轮/40执行总上限和额外网页预算限制。
- 报告沿用 schema3 四种论证角色与工作台，不新增阅读流程；在原有区域说明“回答程度、已知/未知、来源与后续观察条件”。能直接解释就早停，关键证据缺失时明确未解决，不以弱代理替代原题。
- 本次来源文本、检索/读取记录与时间边界留在发现/报告/进展快照；搜索摘要不是正文证据，取回时间不是发布时间，不把事后网页伪装成当时已知。
- 旧候选（无新协议标记）仍走旧冻结研究协议；已有 schema2/schema3 与历史分析只读兼容，不猜填新字段、不回填正文。想用新能力需用户重新发现，旧候选“重新研究”不静默升级。
- 继续保留显式发现、逐条研究、忽略/恢复、运行态互斥与报告直接阅读，不增加评审操作。

### 不做

自动或定时付费研究、独立研究项目中心、持续跟踪状态机、多智能体辩论、因果图谱、逐篇价值评分、自由输入问题入口、泳道快捷研究入口、跨板块自动扩搜、全量历史重生成、泛化检索平台。报告观察条件仅为文字，不代表系统自动监控。

## Capabilities

### New Capabilities
- 无独立新能力域；扩展既有研究契约。

### Modified Capabilities
- `board-signal-reports`：问题型发现与来源冻结、带文字证据的有界研究、结果回答范围及旧协议兼容；补充来源安全与呈现要求。
- `research-data-sources`：调整 signal 研究专用工具授权，七源取数语义不变，允许新协议明确授权的来源检索/阅读；旧循环工具面不变。

## Impact

- 后端：`internal/dataenrichment/{service,repository,handler}`、`wire.go`；复用 `internal/platform/safefetch` 和已有 readability 库。候选增加可空 `research_brief` JSONB，发现 `input_snapshot` 和报告/进展 JSON 增量字段，不新增通用知识库或文章入库管线。
- 前端：既有 `boardSignals.ts`、`SignalCandidateList.vue`、`SignalReportView.vue`、`signalReport.ts` / `reportPresentation.ts`，在原候选详情和核查区增加文字与来源引用；不新增任何页面、弹窗、导航或多步操作。
- 配置：复用现有 Bocha 动态配置，无新供应商；未配置时本地来源仍可解释，外搜明确缺口。用户显式启动新协议研究可能产生 Bocha 调用费用，不仅是模型费用。
- 前置：`redesign-enrichment-research-workbench` 完成并同步主规格后进入 apply；本change的重叠 delta 以其 schema3/忽略/导航契约为基线，不能退回主spec尚存的旧schema2要求。另一个 `fix-board-ghost-false-positive` 及其它脏文件不归本change。
- 部署后：新发现的问题会带未知/核查方向，新研究可提前解释或明确证据不足；旧内容不变。仅需想用外搜时确认既有 Bocha 配置，想用新协议时重新发现；不要求批量重算或清理旧数据。
- 验证：三类真实故事（可回答、原文已回答、必要证据不可得）+ 一次旧协议兼容核对。真实运行须执行前单独获准样本/调用预算，不能用mock宣称研究效果。
- 规划纪律：本次只生成制品；子线程因档位/后台宿主不可用未启动，主线程完成只读调查与规划；实现阶段 review 仍需正常派发或显式留痕豁免，不冒充已独立审查。
