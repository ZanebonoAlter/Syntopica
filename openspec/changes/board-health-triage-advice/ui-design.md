## User Journey

2026-10-28 FB-2：用户指出 v1 仍堆卡片、后续引导不足，并明确选择「把描述修复也做成闭环」。本次改为问题处理主线并升级 major。**用户于本轮对 v2 明确回复「这个可以」，原型已批准，可按本合同进入正式实现。** 该批准对应问题索引、单项核对、共享描述修复、精简执行态及下一步引导；后续若改信息架构/主流程/布局须重置审批。

L1 右轨结论 → 既有「完整评语与依据」→ 紧凑待核对清单 → 选一项 → 看原因/证据 → 核对并编辑新描述 → 明确共享范围并确认 → 查看真实执行阶段 → 重试未完成步骤或处理下一项 → 下一轮体检核对效果。

## Information Architecture

不新建路由、不叠加抽屉；继续使用 BoardWideWorkface 的 health 工作面。工作面内部从四组纵向列表改为主从结构：
- 顶部一行交代本轮待核对数和处理进展，不再把评分做成主卡。
- 左侧紧凑问题索引只列 remove/rewrite：标签、具体问题、处理状态。不是四组彩色卡，也不是强制逐步向导。
- 右侧只展示当前项：问题是什么、原描述/最近邻证据、可编辑新描述、影响范围、主动作和下一步。
- keep/insufficient 合并进默认折叠的「其余标签」，仍保留独立语义与证据，不丢项、不伪造「全部健康」。
- 评分、统计、趋势在「本轮体检依据」按需展开，沿用后端原口径。无 triage 的旧快照按旧形态，不凭现有统计推导新诊断。
- 正式构成页继续可进入同一问题处理区；不得丢失组合、候选、来源、设置等旧入口。

## Interaction Contract

**描述修复（主链）**
1. 显示原描述与污染证据，建议文案可编辑；沿用辅助标签描述约束：trim 后非空、不纯重复标签、不超过 500 字符。输入错误就地反馈。
2. 确认前明确：这是共享标签；展示直接引用版块，更新会影响所有使用它的地方。全活跃话题标签的匹配更新可能连带改变其他版块归属，不能冒充仅当前版块受影响。
3. 主按钮「修复描述并更新匹配」→ 同一处理区行内确认 → 提交；确认前零写入。不是点击复制即完成。
4. 真实阶段为「生成新向量 → 原子保存描述与向量 → 更新版块匹配」。一旦进入任务，编辑区、证据、共享说明合并为默认折叠的只读修改摘要，主区切成阶段/结果/恢复动作；完成后不再显示 textarea 或字数计数。桌面三阶段、失败重试与下一项应首屏可见，不能继续被编辑表单挤到底部。生成阶段失败保留旧数据；提交成功不等于全链完成。
5. 描述已保存但匹配失败：明确部分完成、成功/失败数；「重试匹配更新」只补未完成阶段，不再次改描述/重嵌。
6. 全部匹配更新结束：显示「更新完成，效果待下一轮体检验证」；主按钮变为「处理下一项」。不可说评分已提升，不能即时重写旧体检快照。
7. 刷新/重新进入从后端持久任务恢复进度；不得仅依赖组件内标记。版本冲突先加载最新描述重新核对，保留用户草稿；disabled/非 auxiliary 不执行。

**摘除（次链）**：仍走既有手动 DELETE，仅移除本版块构成、不删共享标签，行内确认/失败重试/防重复提交；说明历史匹配不会因此自动回填。成功后明确结果并提供「处理下一项」，不暗示当场完成全局重算。

## State Matrix

| 状态 | 展示与恢复 |
| --- | --- |
| 正常待处理 | 问题索引 + 当前项依据、表单与唯一主动作 |
| 输入错误 | 表单旁说明原因，禁提交，不丢输入 |
| 确认 | 原/新描述、共享范围与明确提交/取消，非新弹窗 |
| embedding 失败 | 旧描述/向量未变，说明失败且可重试整个修复 |
| 保存成功、匹配运行中 | 描述/向量已更新；进度来自任务，不显示已修复 |
| 匹配部分失败 | 部分完成、失败计数与仅重试匹配动作；不误标已完成 |
| 范围项不再适用 | 同一进度行内补一句「N 项已失效/删除被跳过」；跳过不计入成功，不改布局、不加卡片 |
| 冲突/不可用 | 未覆盖最新数据，加载最新版本重新核对；禁用标签不给提交 |
| 完成 | 匹配更新完成，效果待下一轮体检；可处理下一项 |
| 再进入 | 以服务端任务为准恢复，不因关闭页面撤销任务或重复创建 |
| keep/insufficient | 默认折叠、只读，不把不足伪装为健康 |
| 无快照/加载/读错误/stale | 沿用整体快照状态与重试，不新增独立分诊请求 |
| 旧快照/空 triage/LLM 降级 | 不展示问题清单，仍有原统计/评语或降级说明 |

## Layout Contract

复用现有 `<AppDialog size="xl">`，1040px、92vw 上限，单级工作面。内部主从：索引约 240px、右区 min-width:0，均在工作面可用高内滚动；不在正文嵌套独立卡片网格。1440×900 与 1920×1080 验收居中、宽度稳定，无页面横溢出。窄屏统一 767.98px 断点：索引/当前项切换，有「返回问题清单」及处理下一项；390×844 和 375×667 检查可达性；详情采用底部粘性动作条，避免主动作落在两屏之后。不新建页面 shell 或第五布局模式。

## Component Reuse

保留 BoardWideWorkface、RailHealthBrief brief 与既有治理入口。动作通过宿主/composable 注入，组件不直接发 API。复用 AppButton/AppInput，描述多行编辑沿用语义 token；按需拆统一问题处理子组件供 full/Detail 消费。editorial 暖纸色与 dark 双主题，强调色只标异常/进度，不用四个彩色大容器。新增持久任务读写由 API 层归一，不把 snake_case、临床公式或任务完成判据复制进组件。

## Prototype

`ui-prototype/index.html` 是 v2 待批准静态原型；v1 保留作被否定基线，不再作为实施依据。原型全部模拟，生成向量/保存/匹配都不请求 API、不碰真库；用浏览器本地状态演示重新进入，**正式实现必须后端持久任务**。演示数据/耗时不是实际体检/性能结论。顶部演示控制不进正式页面。

原型提供紧凑索引、编辑/校验/共享确认、三阶段进度、embedding 失败、匹配失败续跑、冲突重核对、完成后下一项，以及保留/不足与体检依据折叠。不得先实现正式接口再让用户补批原型。
