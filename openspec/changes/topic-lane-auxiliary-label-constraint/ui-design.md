## 入口与入口变更

- **入口**：话题编辑面 —— 由前置 change `lane-manual-correction-loop` 的「泳道修正工作面」提供（该 change 尚未开工，0/60 任务）。本 change **不新建编辑入口**，只在既有编辑面内追加一个配置区。
- **变更点**（唯一一处）：编辑面内新增「辅助标签」配置区，位于话题属性（标题/首义）之后、其它操作区之前。
- **配置区内容**（每条约束一行）：
  1. **短词输入**（如「以色列」「黎巴嫩」）—— 单行文本，placeholder「输入主体词，如：以色列」。用户**不填 description**，描述由短词本身承载。
  2. **模式二选一**：`required`（必须同时在场）/ `preferred`（仅加权）。默认 `required`。
  3. **阈值**（可选，折叠展示）：该约束的余弦距离阈值，默认走全局值。
  4. **删除**：移除该条约束（`preferred` 可直接删；`required` 删除后该话题回到「无约束」行为）。
- **新增动作**：添加一条约束 → 输入短词 → 后端计算锚向量并落库 → 行出现在列表中。
- **无入口变更**：话题总览（`BoardThreadBrowser.vue`）不新增任何入口或徽标；约束是话题属性，只在编辑面可见。

## 受影响状态

- **loading**：添加约束时该行处于「计算中」态（短词已输入、向量未返回），期间禁用该行的模式切换与删除；**失败时该行保留短词并给出可重试的错误提示**（短词不丢）。
- **empty**：话题无约束时，配置区显示单行空态说明「未绑定辅助标签 · 话题将按语义自由吸附」，**并显式说明约束只影响吸附、不影响话题生命周期**（避免用户误以为会改变 hit_count 或状态）。
- **error**：锚向量计算失败（embedding 服务不可用 / 短词无法编码）→ 行内错误态 + 重试入口；**不静默丢弃用户输入**。
- **success**：约束生效后行内展示短词 + 模式徽标 + 当前模型标识（`embedding_model`，如「远程 qwen3-embedding」），让用户知道该约束的锚向量算在哪个向量空间里。
- **长文本**：短词输入上限 100 字符，超出在输入框内截断提示，不换行挤压行高。
- **重复提交**：同一短词在同一话题内重复添加 → 后端返回冲突，配置区提示「该辅助标签已存在」，不产生第二条。

## 复用组件与布局模式

- **布局模式**：复用话题编辑面既有 layout mode（由 `lane-manual-correction-loop` 确定），本 change **不新增 layout mode、不引入自由宽度**。配置区为单栏列表，宽度随编辑面容器。
- **基础组件复用**：`AppInput`（短词输入 / 阈值输入）、`AppButton`（添加 / 删除 / 重试）、既有列表行样式（约束行）、既有徽标样式（`required` / `preferred` 模式徽标，复用话题状态徽标的视觉 token）。
- **不新造组件**：模式二选一复用既有 segmented / radio 组样式（若既有编辑面无，则用 `AppButton` 组的 toggle 形态，不引入新组件库）。
- **主题与可访问性**：沿用既有主题 token；模式徽标带 `aria-label`；删除按钮带 `aria-label`（含短词，如「移除约束 以色列」）；错误态用 `role="alert"`。

## 验收映射

- **组件测试**：配置区所在组件的 Vitest 测试（实现时确定实际落点文件，落在 `front/app/features/tags/components/` 下）——覆盖：空态渲染、添加约束后的行渲染、`required`/`preferred` 模式切换、删除行、重复短词冲突提示、计算失败时的错误态与重试。
- **后端**：约束读写 handler 测试（`backend-go/internal/topicgraph/handler/`，实现时定具体文件）——覆盖读取、批量替换幂等、短词编码失败返回 4xx。
- **真库效果核对**：绑定「以色列」+「黎巴嫩」两条 `required` 约束到 id=2 后，跑一次日报生成，核对「2026-11-12 之前 32 条纯以色列内政 section 在新约束下是否会被拦下」——记录触发原因、方法、量化结果、结论（效果依赖真实内容分布，属 test-design 效果核对节）。
- **视觉/交互**：agent-browser 主链路（打开编辑面 → 添加约束 → 看到行与模式徽标 → 删除）在 `ui-verification/report.md` 建账（格式契约见 `ui-verification-trace-gate`）；两档视口（1440×900 / 1920×1080）各截图一次。
- **依赖前置**：前端实现待 `lane-manual-correction-loop` 的编辑面就绪后接线；在此之前仅交付后端 + API + 组件层（组件测试以独立组件形态落地，不等编辑面）。
