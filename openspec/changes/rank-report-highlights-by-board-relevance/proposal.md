## Why

日报「今日重点」（刊头 N°01–03，第一条同时是头条和日报标题）现在固定按「簇里文章多」排：当天文章最多的簇必然排第一，而且模型是从「文章最多的 8 个簇」里挑，挑的时候并不知道这是哪个版块。于是「中东地缘政治与美伊关系」版块 11-27 的头条是「美国对华进口产品税率提升20%」（靠权重最低的一档标签绑定进版块、归在只出现过 3 次的候选话题下）；往前翻，11-26 头条是「美国对多国加征关税」、第三条也是关税，11-14 头条是「美国发布全国性航班停飞指令」，11-19 的 N°02 是「美国国安局 IT 系统故障」，11-23 的 N°03 是「美国11月标普全球PMI初值」。

用户的诉求：**跟版块贴的排前面，不贴的往后放，最好别进来。** 只在模型挑完之后排序不够——挑出来就那 3 条，跑题的挪到后面也不会消失（11-26 就是例子）。所以要把「贴题」这道门槛放到模型挑选**之前**，挑完再排一遍兜底。

系统在给正文板块分泳道时已经算过「这个板块离版块已成立话题的中心有多近」并分了档（正文板块的泳道档位：近 / 中 / 远 / 用户手动关注），连同话题当时是在跟的还是候选的一起存在每个正文板块上。直接拿这个现成的档位当「贴题档」即可——不需要新造评分，不需要新增向量计算。

## What Changes

- **给每个候选簇定一个「贴题档」（0–5，越小越贴）**，由服务端按该簇成员标签所落的本期正文板块计算，跨多个板块取最好的：近（贴已成立话题）→ 用户手动关注命中 → 中且话题在跟 → 中且话题为候选 → 远（新话题）→ 正文里找不到对应板块。
- **候选池先筛（版块关联度优先）**：
  - 贴题的簇（近档 + 手动关注命中）有 3 个及以上 → 模型只在贴题的里面挑（至多 8 个），不贴的簇不进候选、不送给模型；
  - 贴题的只有 1–2 个 → 保留全部贴题簇，再按贴题档从低到高补位到 3 个，不让刊头空着，补位的挤不掉贴题的；
  - 贴题的一个都没有 → 维持现状（文章数前 8 让模型挑）——典型是新板子还没有已成立的话题或关注，无从判断贴不贴题。
- **模型挑选、提示词、文案、合法性校验与重试、服务端快照字段全部不变**；顺序依旧由服务端决定，模型不决定顺序。
- **挑完再排（兜底）**：模型选出的至多 3 条按同一个贴题档稳定排序，同档保持现有候选序（簇内文章数降序 → 标签数降序 → 代表标签 id 升序）。补位进来的永远排在贴题的后面。
- **同一档位内部仍然只比文章数**：版块 section 数、泳道热度照旧不参与任何排序。
- **查不到正文板块的贴题信号时整体退回现状**（候选池与展示序都用现有口径）并记一条 Warn 日志，不阻断日报落库。
- 日报 `title` / `summary` 仍取第一条重点（不变），因此头条与副标题自动变成最贴版块的那条。
- 前端零改动（刊头与头条本就按接口返回顺序渲染）。
- **不做**：不按贴题度硬删模型选中的重点（只影响进不进候选池，以及先后）；不改模型提示词；零候选时的标签回退模式不变；不新增落库字段；历史日报不回填。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `daily-report-system`: Requirement「今日重点聚簇候选」——候选池改为「贴题簇优先、不足补位到 3、贴题簇为空维持前 8」，展示序改为「按贴题档稳定排序，同档保持候选序」，新增场景（贴题簇充足时不贴的不进候选 / 贴题簇不足补位 / 贴题簇为空维持前 8 / 跨板块取最好档 / 手动关注居次 / 候选话题同档靠后 / 信号缺失退回原口径）。Requirement「当天同事件聚簇先筛重点候选」——在既有候选序之上叠加同一套候选池规则，场景「候选按簇内文章数截断」改写为新口径。`daily-report-interface` 的「highlights 按 API 顺序展示、头条取 `highlights[0]`」契约不变，不动。

## Impact

- **后端**：`backend-go/internal/topicgraph/service/daily_report_story_highlights.go`（聚簇后先算贴题档、组候选池；落库前再排一次）；`backend-go/internal/topicgraph/repository/`（新增按日报取正文板块贴题信号的轻量只读查询；既有候选序比较器的三个排序键与截断语义不变，只是把比较器函数体抽成 `OrderEventClusterCandidates` 供组池复用完整序，`RankEventClusterCandidates` 只做截断委托）。`FinalizeReportHighlights` 不改。
- **测试**：新增候选池选择器与排序的表驱动测试；`service/daily_report_highlights_cluster_test.go` 按「板块信号为空 ⇒ 池子与顺序都同现状」补断言。断言既有候选序的三个测试（`repository/report_story_highlights_test.go`、`repository/report_event_clusters_test.go`、`service/daily_report_event_cluster_composite_test.go`）预期不动。
- **规格与文档**：`openspec/specs/daily-report-system/spec.md` 两条 Requirement；`docs/reference/flow/daily-report.md`「今日重点的选题与热度」节与红线 46 的候选口径与顺序表述。
- **并发提醒**：同包 `topicgraph` 下有进行中的 change（`lane-first-recall`）在改 `daily_report_lane.go` / `daily_report_orchestrator.go` / `daily_report_lane_recall.go`，本 change 不碰这三个文件，派发前跑一次 `concurrency-status.sh`。
- **用户可见效果与部署后影响**：刊头 N°01–03 的内容与顺序、头条、日报标题与摘要会变——贴题新闻够 3 条的日子，不贴题的新闻不再出现在重点里。只对改动部署后新生成或重跑的日报生效，历史日报原样不动；无需任何手动操作或数据迁移。接口形状不变，旧客户端不受影响。

## 回放验证（本 change 的依据）

对「中东地缘政治与美伊关系」版块 2026-11-13 ~ 11-27 共 15 期做只读回放（按正文板块的泳道档位与话题状态近似，贴题 = 近档 + 手动关注）。15 期里 14 期当天贴题的板块都 ≥ 3 个，所以：

| 日期 | 现状 | 先筛后挑 |
| --- | --- | --- |
| 11-27 | 中美关税 / 沙特炼油厂 / 伊朗霍尔木兹 | 只从 3 个贴题簇（伊朗与美韩波斯湾表态、沙特炼油厂、伊朗霍尔木兹）里挑，**中美关税不出现** |
| 11-26 | 美国对多国加征关税 / 胡塞袭沙特 / 商务部反对 301 关税 | 只从 3 个贴题簇（伊朗霍尔木兹、胡塞无人机袭沙特炼油厂、胡塞袭沙特推升油价）里挑，**两条关税都不出现** |
| 11-14 | 美国航班停飞指令 / 伊朗油轮触雷 / 中国代表中东主张 | 美国航班停飞指令不出现 |
| 11-19 | 特朗普考虑新袭击 / 美国安局 IT 故障 / 国际能源署评估 | 美国安局 IT 故障不出现 |
| 11-23 | 也门胡塞 / 特朗普称与伊朗间接对话 / 美国 PMI | 美国 PMI 不出现 |
| 11-13 | 胡塞打击沙特阿美 / 特朗普搁置美伊谈判 / 伊朗 LNG 船触雷 | 贴题的只有 2 个 → 中档那条伊朗新闻补位，结果与现状一致 |
| 其余 9 期 | 全是贴题新闻 | 模型仍在贴题簇里挑，预期基本不变 |
