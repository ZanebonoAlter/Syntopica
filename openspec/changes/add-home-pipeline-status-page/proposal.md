## Why

首页（`/`）现在是「1000 篇/天的等权列表」，它只呈现产品五层结构（文章→标签→版块→话题→日报）里的**第 1 层**，其余四层在首页一个字都没有（`features/shell/` grep 零命中）。于是：

- **新人看不懂这是什么**。新装的库是真·全空（0 信源 / 0 文章 / 0 标签 / 0 版块 / 0 日报，`migrator.go:63` 只建表，seed 无默认信源与默认版块），首页给的是「暂无文章 / 添加一些 RSS 订阅源开始阅读吧。」——一句提示，没有动作按钮，也不讲这产品怎么工作。
- **老人看不到系统在干什么**。1084 篇待打标在排队、今天还没出日报、某个环节卡住，首页全都看不见；判断"是不是坏了"只能去设置页翻状态。
- **引导机制已经失效**。driver.js 三个 tour 是按"界面区域指指点点"设计的，与现在的使用方式不符：home tour 只能手动从顶栏点（`AppHeaderView.vue:253`），tags tour 全仓无调用方（死代码），且"点遮罩外关闭 = 永久算完成、无重置入口"。本 change **不复用 driver.js**。

参考对象 AIHOT 的「关于页源流图」（`features/about/SignalRiver.tsx`，调研存档 `docs/research/aihot-reference/explore-findings.md`）视觉好看，但线数、束数、过闸、汇合**全是编的**（`SignalRiver.tsx:76-105,132-133,511-519`），只有信源名与统计是真的。我们的管线是真的，所以**不照搬它的随机示意**。

**前两版原型已被用户否决**：五站直线流水线只换了字段顺序，没换视觉语言，和普通流程图的差别不够；随后那版 2D 地图也走不到底——制图语言撑不起"读得出堵在哪"。最终形态是**双主题巨幅地图**：three.js 正交投影，平台只是被红圈标出的一块地。

## What Changes

**首页职责重划**：`/` 从「信息流」改为「脉络地图」，`/articles` 承接原来的三栏 RSS 阅读（能力零损失，只是换地址、`FeedLayoutShell` 内部不动）。

- **9 站 6 区 9 边**（编号 ≠ 拓扑顺序：06 在南排，07/08/09 在东侧脊柱）：
  - 北排自西向东：③ 打标车间 → ④ 向量炉 → ⑤ 标签库 → ⑦ 版块区；
  - 东侧脊柱：⑦ 版块区 → ⑧ 日报社 → ⑨ 探索订阅源；
  - 南排：⑥ 站内搜索（由 ⑤ 标签库分出）。
  - 采集侧：① 信源港 → ② 抓取码头 → ③ 打标车间；⑨ → ① 是**回流**，沿平台南缘 `z = 10.2` 把探索到的候选源送回信源港。
  - 平台 `GROUND = { w: 40, d: 23 }`；六个分区（采集 / 加工 / 仓储 / 产出 / 检索 / 探索）两两不相交，间隙 1.0~2.0。
- **渲染栈**：**three.js 正交投影**（vendored `vendor3/three.min.js`，MIT），**必须动态 import 且只在地图模式加载**，首屏先出 DOM 徽章与数字。原型为纯静态单文件、`file://` 可开，**零接口请求、零新增运行时依赖**。上一代的 2D 画布库方案已废弃（遗留文件不再引用）。
- **双主题**：浅色「俯瞰地图」（羊皮纸 `#f2ece0` / 墨线 `#4a453c` / 唯一彩色红 `#c0392b` 只用于当前选中与平台红圈）+ 暗色「实时视图」（`#070b11` / `#8fb8c8` / 橙 `#ff7a3d` 只用于状态）。两套固定色板，不与产品 token 拼色。
- **四档变焦**：全图 `viewH = 100`（整幅巨幅地图）/ 工坊岛 `34`（九站六区九路铺满）/ 节点 `10`（单站特写）/ 检视 `4`（零件级，1 单位 ≈ 260px）；滚轮逐格推拉，面包屑 `全图 › 工坊岛 › 打标车间 › 检视` 任意段可跳，ESC 逐级退。
- **巨幅地图**：平台之外是**巨幅地图**——40 块共边排线地块 + 8 条外围双线乡道 + 89 棵路旁树 + 溪流 + 图框坐标（横 0–7 / 纵 A–F）+ 比例尺 + 右下插图小地图。外围乡道是**制图符号**，与 9 条数据流道路在宽度与形态上必须严格区分。
- **站点即门 + 两处钻取**：① 信源港抽屉三层（文件夹 → 源 → 该源 RSS 文章）；⑦ 版块区抽屉（12 个版块 → 版块矩阵）；其余站点直接跳现有页面。**首页只读**，任何交互都不触发抓取 / 打标 / 成稿。
- **谁在干活写在脸上**：模型名来自 `/api/health` 的 `routes[]`（`topic_tagging`→Qwen3.5-4B、`embedding`→qwen3-embedding、`digest_polish`→deepseek-flash）；② 标注 `go-readability → firecrawl` 降级链；④ 在岗为 0 时必须熄火。
- **工人 / 货箱即数据**：小人数量 = 该站 `processing`（在岗篇数），图例明示「· 小人 = 该站正在处理的篇数」；货箱按 `min(20, ceil(pending / 100))` 堆在入厂道路端点外侧，图例明示「· 1 箱 ≈ 100 篇（超出 20 箱不再画）」；真实例：打标 1084 篇 → 11 箱，向量 255 篇 → 3 箱；`queue` / `jammed` 态箱子转橙。
- **状态由数据推导，不存 flag**：`deriveHomeMap()` / `diagnose()` 是纯函数，不写 localStorage、不落库。节点状态互不排斥（`ok` / `flow` / `idle` / `queue` / `jammed` / `off` / `degraded` / `empty` / `unbound`），诊断条只给"最该看的那一句话"（12 级优先级）。核心能力（`embedding` / `topic_tagging`）不可达 → ③④ 断电、队列只增不减，② 照常入库；非核心断 → 降级，照走不停。
- **节点造型走精修流程**：真实数据 → 造型决策 → parts 列表（≥40，形态多样）→ Anatomy 等距 SVG 定型 → 人工评审 → `parts.json` 内联 → three.js 转换 → 检视档验收。契约落 `ui-prototype/nodes/README.md`；已完成 05 标签库（97 零件）、09 探索订阅源（82 零件）、01 信源港（90 零件），每站 ≤ 6 draw call，全岛 52。
- **数据红线（诚实缺口）**：拿不到的字段显示「—」并注明口径，**不填 0、不估算**（例：标签表总数无只读端点 → 只显示"条挂载"）；**覆盖率 ≠ 健康率**（候选目录未探活 3097 条要显示为"全部未探活"，页面不出现「100% 健康」）；计数型数据做成**可数实体**（7 条待定推荐 = 7 个实体卡匣），大数字用机械计数窗而不是生成数千实体；地图动画只表达"这一段在运转 / 堵住 / 停了"，**不表达吞吐速率**——快照里没有速率数据，硬画就是编。
- **窄屏降级**：`<768px` **不渲染 3D 画布**，走单栏列表态 / 阅读态互斥 + 订阅源抽屉（真实 `FeedLayoutShell`），**不隐藏任何站**（站信息进列表行）。

**不做什么**：

- 不改任何抓取 / 打标 / 成稿逻辑与数据口径；首页只读，不触发任何任务。
- 不删现有三栏阅读的任何能力；不改 `FeedLayoutShell` 内部行为。
- 不为上一代形态保留任何设计空间（直线流水线、2D 地图均已作废）。

## Capabilities

### New Capabilities

- `home-pipeline-map`：首页脉络地图的表达契约——9 站 6 区 9 边拓扑与**站即门**去向、节点状态机（互不排斥）与诊断条优先级、两处钻取的信息层级、three.js 正交画布与 DOM 海报层的分工、四档变焦、双主题与巨幅地图制图语言、工人 / 货箱换算、**数据红线**（缺失显示「—」不填 0）、`/` 与 `/articles` 的模式切换。只管表达与状态推导，不接管任何任务执行。

### Modified Capabilities

- 无。既有 `reading`、`scheduler`、`semantic-board`、`daily-report`、`content-enrichment`、`ai-summary`、`data-enrichment` 全部不动；本 change 只读取它们的既有状态，不新增写路径。

## Impact

- **前端**：新增 `/` 地图页（three.js 正交场景 + DOM 海报层 + 右侧抽屉），原三栏阅读迁到 `/articles`（路由搬移，组件不动）；`useOnboarding` 与 driver.js 调用点退役；**新增 `three` 依赖（vendored / MIT，动态 import）**，上一代的 2D 画布库依赖不引入。
- **后端**：**不需要新增聚合接口**——`/api/poll` 已经给了 `tag_queue` / `embedding_queue` / `schedulers` / `ai_healthy` / `ai_health_routes` / `analysis_paused`，其余用只读端点首屏并行拉取。实现阶段只需补一个 `today_articles`（今日新增，现无端点）；`labels_total`、worker 池大小属可选。
- **轮询节奏**：复用现有 `usePollBundle`（硬预算 ≤4 次/分钟，实际 10–15s 一跳，失败退避不清零），**不新开 5s 轮询**；地图的连续运动由前端按时间插值，数据更新是跳变的。
- **数据**：无迁移、无写路径。原型与实现共用同一份真实快照口径（2026-11-04 20:25：信源 28 / 在库 2222 / 打标排队 1084 · 在岗 4 · 今日 156 / 向量排队 255 · 今日 146 / 挂载 3516 / 版块 12 / 可搜 2222 / 候选 3099）。
- **主题与动效**：editorial / dark 双主题固定色板；`prefers-reduced-motion` 下画布 `noLoop()`，工人冻结在岗帧，**数字全部保留**。
- **布局例外**：`/` 脉络地图按 `workspace` 落地、页面级不滚动，属「固定视口栅格」形态，实现阶段须在 `docs/reference/standard/frontend/layout.md`「已登记例外」表登记一行；`/articles` 同类登记。
- **用户可见变化（实现后）**：打开 `/` 看到的是脉络地图和今天的状态，不是文章列表；要看文章点「阅读模式」或直接访问 `/articles`。旧书签 `/` 会落到地图页——这是本次唯一的行为断裂点，实现时需给显式入口。
- **部署后需要用户做的操作**：无（不迁移、不清库）。若 WebGL 不可用或 three.js 加载失败，站点卡仍可读可点，只是没有 3D 场景。
