## 发现的问题

### P-1 画布纵向滚动导致拖拽主手势在密集窗口失效【已修（方案 1 吸顶）：组件测试 6 条 + 反向验证 + 吸顶实拍】
- 事实：board 3030 @30 天 → 12 行（lane + 10 链 + floor），画布内容高 **1076px**，可视区 **505px**（`overflow:auto`，`scrollHeight=1076`）。
- 后果：**本次泳道行（第 0 行）与散料地板不可能同屏**。拖拽的唯一终点是第 0 行，从地板往上方拖时必须先滚动，而滚动中看不到落点——主手势在「链数 ≥ 6」的窗口里不可用。
- 原型未暴露该问题：三态图与沙盒都是 4 条链，全部行恰好放得下。
- 备选：① 本次泳道行在画布内**吸顶**（用户 2026-11-21 选此）② 行数超限时压缩行距 ③ 候选链超限折叠。
- **修复实现**：单层 SVG + 第 0 行整组反向平移 `translate(0, scrollTop/zoom)`；吸顶行不透明底盖到本行下缘 + 6 级渐隐阴影；日期轴画在行之后（浮在底色上、位置不动）。落点判定改走 `rowAtPointer`：溢出时先用「吸顶行内容坐标区间 = `row0.top + scrollTop/zoom`」判定，再回退 `rowAtContent`（溢出时跳过第 0 行，避免指针在画布上方被误判）。节点卡定位加 `pinnedShift`，防滚动后卡片被甩到视口上方。
- **验证方式**：组件测试 6 条（含「不溢出时不出现吸顶层」「滚到地板后拖入吸顶行成员数 +1」「从吸顶行拖到滚动区 = 移出」「滚动后点吸顶行成员，卡片仍在可视区」），并做过**反向验证**（临时删掉 `rowAtPointer` 吸顶分支 → 相应用例立即变红，已还原），证明断言不空转。
- **已实拍（机器重启、`start-dev.sh` 重新拉起后端后补测）**：board 3030 @30 天（9 链 → 12 行，内容 1076px / 可视 238px）
  - `[data-role="sticky-row"]` 存在，且全画布 `[data-row-kind="lane"]` 只有 1 个；
  - 滚动前：lane 行 `top = 395`，首条链行 `top = 533`；
  - `surface.scrollTop = 400` 后：**lane 行 `top` 仍为 395（未移动）**，首条链行 `top` 变为 133（上移 400）——吸顶成立。
  - 合成 pointer 事件的「拖到吸顶行」未跑通（headless 窗口仅 1280×633、画布可视区 238px，节点 rect 与吸顶行 bbox 重叠域过小，脚本替身不可靠）→ 该路径仍以组件测试 #3（含反向验证）为准。

### P-2 右栏②空态文案是机制科普【已修并实拍】
- 实拍文案：「选入候选后，这里按成员平均质心给出可补充的事件。」
- 与 `standard/frontend/interaction.md:53-66`「派生值机制科普 / 界面内教学语 SHALL NOT 出现」冲突。

- **实拍验证**（rebuilt 生产构建 → 同源反代 → board 2128）：编排面全文 `选入候选后|质心|另行确认|节点卡里直接点` **零命中**，② 区出现 `无`。

## 第二轮实拍发现（2026-11-21 部署上线后用户看图提出）

### P-3 画布画了事件关系边（spec 早已禁止，实现超纲）【已修并实拍】

**现象**：30 天窗口上，同链节点之间有 dashed 折线（`similarity` 虚线 4 4）与 `identity` 实线，纵横交错，用户原话「既然相关度已经能体现泳道和散料的相近关系，节点之间的关联关系没必要画出来，只会增加理解复杂度」。

**判定**：不是体验偏好，是**实现违反 spec**——
- delta spec:152 / 主 spec:142 均写「…不生成事件关系边。」
- 实现里 `<g class="lcc-canvas__edges">` + `edgePath()` 照画不误。

**修复**：`tasks.md` 11.1 删除 edges 全部实现与样式，测试改断言「无 `.lcc-canvas__edge`」。

### P-4 节点与常显标题不可读（8px 字号）【已修并实拍】

**现象**：30 天窗口节点直径 4.8–8.4px、常显标题 8px，用户原话「节点可以大一些，文本也对应增大，这样起码能看清楚文本」。

**根因**：`titleBudget()` 在 `columnWidth < 40px` 时整档关闭（30 天 23px 列 → 无标题），14 天 47px 列虽有标题但只有 8px。

**决策**（用户在两选项间明示选择，非自由发挥）：
- 允许画布**横向滚动**（不选「保持一屏、放弃 30 天标题」）
- 尺寸走**明显档**：列宽下限 52px、散料直径 11px、推荐 12.4–14px、已选 15px、标题 11px、槽距 18px

**代价（已告知用户并获批）**：1920 视口下 30 天内容宽 1560px vs 可视 1114px → 必然横向滚动；1440 视口下 14 天 728px vs 664px → 也滚动。补偿手段 = 日期轴纵向吸顶 + 行标签列横向吸顶。

**验收锚点**：见 `ui-design.md`「几何变更（2026-11-21 用户当场批准 · 可读性提档）」表。

**实拍结论（2026-11-22，部署后 :5100 静态产物）**：

| 项 | 实测 |
| --- | --- |
| `.lcc-canvas__edge` 数量 | **0**（identity 与 similarity 都不再画） |
| 内容宽 vs 可视宽 | 1716px（= 132 + 30×52 + 24）vs 650px → `overflow-x` 成立 |
| 常显标题 | 11px、30 天**照常出现**（42 条），不再整档关闭 |
| 行标签横向吸顶 | `scrollLeft=400` → 组 `transform=translate(400,0)`，标签屏幕左缘 310→310 不动 |
| 日期轴纵向吸顶 | `scrollTop=400` → 刻度组 `translate(0,400)`，与本次泳道行同源 |
| 本次泳道行吸顶 | top 不动、首条链行 533→133（上移 400） |
| 折叠计数可达 | `floor-fold`「另有 90 条未展开 · 展开」随标签列吸附（left 302 vs 画布左 300） |

**遗留观感问题（需用户定档，未擅自改）**：52px 列宽下常显标题实际只能放 **3 字 + 省略号**（11px 字宽 11px/字，4 字 + 省略号需约 55px）。30 天窗口标题形如「大模型…」「用户反…」。要 4 字需把列宽下限提到 **60px**（30 天内容宽 1956px，1920 视口滚 1.75×）；要 5 字需 71px。当前档位是用户批准的 52px。

### P-5 吸顶带文本重叠 + 关联度映射失效（2026-11-23 第二轮实拍）【已修】

用户原话：「吸顶需要注意背景区分，现在都文本重叠了」／「通过关联度配置颜色大小怎么被你删了？」

**成因一（重叠）**：吸顶底色 rect 用 `y=0`（= 内容坐标 0），而吸顶行整组被反向平移了 `scrollTop` → 底色落在视口上方不可见区，滚上来的行标签直接叠在吸顶文字上。诊断本身也被拖住：行内容包在一个裸 `<template>` 里，其子节点 `getBoundingClientRect()` 恒为 0。
- 修：底色几何起点改 `-scrollTopLogical`、高度加 `scrollTopLogical`；裸 `<template>` 改 `<g class="lcc-canvas__row-body">`。
- 修：吸顶行标签移入置顶覆盖层，不再依赖绘制顺序。
- 实测：`scrollTop=300` → 底色 rect 高 438、`elementFromPoint(30,10)`/`(30,120)` 命中 `sticky-tint` 自身、`(30,60)` 命中吸顶行 `row-count`。

**成因二（映射失效）**：尺寸提档后推荐半径区间被挤成 `6.57–7.0`（0.43px），肉眼等于常量。
- 修：`recommendRange {5.9,7.4}` 线性插值 + `strengthRange {18,80}`，两者都是显式 flag（修正画布缺省不变）。
- 实测（13 已选）：推荐半径 6.12–7.02（直径 12.2–14.0px），填充 26.9% → 51.5% → 64.1%，已选恒 7.5（15px）。

**成因三（刻度压标签）**：日期刻度组最后绘制且只做纵向吸顶，横向滚动后文字滑到吸顶标签列上方。
- 修：给刻度/列 guide 加 `clipPath`，左界 = 可视区 `LABEL_W`（内容坐标 `132 + scrollLeftLogical`）；不溢出时不下发。

**视觉分界**：吸顶带 = 不透明 bg-base 打底 + elevated 一档 tint + 下缘 1px 硬分隔 + 标签列竖分隔。两层 rect 的原因：深色主题 `--color-bg-elevated` 是 `rgba(17,27,38,0.98)`，单用会 2% 透出。

### P-6 标题 3 字不可读 / 底部说明多余 / 折叠措辞易误解（2026-11-23 第三轮）【已修并实拍】

用户三条：
1. 「3 个字太少了，起码得 10 个字」
2. 「最下面的说明没必要有了」
3. 「展开这个说明太容易误解，应该改成显式低相关散料」

**修法**
- 标题档：`MAX_TITLE_CHARS` 5→10、`TITLE_MIN_COLUMN` 52→**124**、`TITLE_CHAR_WIDTH` 12.6→11.5。列宽下限跟着标题档走，30 天内容宽 = 132+30×124+24 = **3876px**。
- 截断改宽度口径：新增 `truncateByWidth()`，`nodeTitleText` 上限 = 列宽 − 2px。修掉「`Gemini 4.5` 被截成 `Gemini 4 …` 但还有半列空白」。
- 画布底部「相关节点（只读 N 个…）…；另有 M 个可补充的相关节点未标名…」整行删除，连带三个死计算属性与样式。
- 折叠计数：`另有 N 条未展开 · 展开` → **`低相关散料 N 条 · 展开`**。

**部署后实测（:5100）**
```
viewBox 宽 3876（=132+30×124+24）  vs 可视 650 → 横向滚动
node-title 42 条，CJK 最长 10 字：大模型服务限流、封… / ChatGPT中文区出现…
                     Latin 吃满宽度：codex 异常汇报与 C…（18 字符，约 122px）
lane-related-hint              不存在
floor-fold 文本                低相关散料 90 条 · 展开
```

**代价（用户已知情）**：30 天窗口在 1920 屏要横向滚约 3×（内容 3876 vs 可视 ~1270）。日常用 14 天更顺手（1892px，滚 1.5×）。

### P-7 关联度看不出差别 / 标题随机出现（2026-11-23 第四轮）【已修并实拍】

**P-7a 关联度**：原口径 `proximity = 1 − d/threshold`；实测这批距离 0.59–0.67、阈值同量级 → proximity 只在 **0.04–0.14**，半径 5.9→6.0px、填充 18%→21%，等于常量。
- 修：批次内 min-max 归一（最近 1 / 最远 0 / 单点或全等取 0.5），阈值不再参与视觉映射。
- 实测：半径出现 **46 个不同取值**，min 5.90 / max 7.50。

**P-7b 标题**：原来只有「候选链成员 / 已选 / 检索命中」常显标题，散料不标；同一行里标题与「是否相关」绑定 → 看起来随机。
- 修：所有会画出的节点统一常显（含散料），落位统一避让（障碍 = 节点圆 + 已落位标题），放不下整条不画。
- 实测：散料行 **43 节点 / 43 标题**（原来 0），候选链行 2/2、7/7，泳道行 5/5，全画布 57 条标题。
