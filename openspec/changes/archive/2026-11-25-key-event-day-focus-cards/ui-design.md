# UI 设计契约：关键事件视角「引线树标签 + 日聚焦卡片」

## User Journey

- **入口**：`/tags/:boardId` 版块态势页 → 顶部视图切换组「关键事件」（`?view=events`），与「矩阵 / 追踪」「文章归档」「研究工作台」同级。
- **主任务**：**看清那一天发生了什么**。选中某天 → 该日在每条有事件的泳道内就地展开卡片列（日期打头、标题、摘要、关联文章），一屏读完。
- **扫读任务**：不选日时，每条事件标签都能**顺着引线回到自己的圆点**，从而知道它是哪一天的——不靠在标签里写日期，也不靠猜位置。
- **不承担**：注记的确认 / 取消 / 编辑（唯一归属日报阅读台 `KeyEventMarkerActions`）；跨版块检索。

## Information Architecture

```
版块态势页（workspace）
├── 面包屑 / 版块栏（不变）
├── 主舞台
│   ├── 视图切换组（不变）
│   ├── 时间视窗（与矩阵共用，不变）
│   ├── 关键事件视图头（新增）：「关键事件 · 所属日期 [下拉] · MM/DD · n 条」
│   └── 关键事件视图（行 = 持久化话题，列 = 同一 visibleAxis）
│       ├── 行头：话题名 · N 事件 · 最近 MM/DD · 当日 k 条
│       └── 行内：上带标签 / 生命线 + 圆点 / 下带标签（选中日 → 下带放卡片列）
└── 治理右轨（不变）
```

- **横向骨架不变**：行 = 持久化话题（active，候选不占行），列 = 同一 `visibleAxis`，列宽 `max(64px, 可用宽 / 可见日数)`，舞台内横滚、选中日滚入视口。**行头单独成列**（192px，不参与横向滚动）：舞台 = 行头列 + 滚动区（轴头、标签、引线、卡片都在滚动区内），两列逐行等高；行头 MUST NOT 以 sticky 覆盖滚动内容（实测 1440 下 sticky 行头会盖住 192px 内容）。
- **标签分上下两带挂在生命线两侧**，每条标签一根引线连回自己的圆点；同一天多条从并排的主干分叉到上下堆叠的标签。行高随标签动态撑开。
- **下方「当日关键事件」阅读区移除**（用户 2026-11-23 决定）：它的全部能力（标题 / 所属话题 / 摘要 / 关联文章 / 文章预览）由泳道内的日聚焦卡片承接，不再有两份重复内容。
- **休眠泳道**：组标题显示「休眠泳道 N · 当日 M 条」；选中日在休眠泳道里有事件（M > 0）时自动展开当天有事件的那几行，卡片列照常出现。

## Interaction Contract

| 操作 | 触发 | 结果 | 反馈 |
|---|---|---|---|
| 认出标签是哪一天 | 静态可见，无需操作 | 每条标签有一根引线连回自己的圆点；同日多条呈树形分叉 | — |
| 选日 | 点轴头日期 / 圆点 / 标签 / 视图头「所属日期」下拉 | 写入与矩阵同一个 `selectedDate`；该日在**所有**有事件的泳道内展开卡片列；该日原有的药丸标签撤下（由卡片承接） | 选中列淡底 + 轴头日期加粗 + 该日圆点实心；卡片淡入 |
| 换日 | 点另一个日期 / 下拉选另一日 | 前一日卡片列收起、新一日展开；行高随卡片堆叠重算 | 淡出 / 淡入 |
| 悬停强调 | 悬停标签或圆点 | 该事件的引线与圆点加重、轴头对应日期加重；**不改变选中态** | 移开即恢复 |
| 读卡片全文 | 点卡片摘要区 | 就地展开 `summary_snapshot` 全文 | 卡片高度增长 |
| 看关联文章 | 点卡片「关联文章 N 篇」 | 卡内展开文章列表（标题 · 来源 · 日期） | 按钮变「收起文章」 |
| 打开文章预览 | 点文章行 | 走既有 `ArticlePreviewModal` | 遮罩；Esc 回到原卡片，滚动位置不变 |
| 平移 | 空白处左键拖 >5px | 舞台横滚 | 位移未超 5px 不回退为平移 |
| 切换时间窗 | 共用控件 | 行内重排；选中日落到窗外则取消聚焦 | — |

- **无「取消选中日」路径**（共同 `selectedDate` 恒有值）：`laneConsoleView.ts:reconcileSelectedDate` 对 `current === null` 会回落到最近报日，视图 emit 签名也只收 `string`。下拉选项 = 当前观察窗内全部日期，**不含「不聚焦」项**；要收起卡片只能换选另一日或切时间窗。
- **无危险操作**。本视图只读。
- 切换视图 MUST NOT 重置 `selectedLane` / `selectedDate` / 观察窗。

## State Matrix

| 状态 | 触发 | 呈现 | 恢复路径 |
|---|---|---|---|
| loading | 首次进入 / 切版块 / 换观察窗 | 主舞台骨架（行头与轴占位）；视图切换仍可点 | 数据到位自动替换 |
| empty（无注记） | 窗口内 0 条 confirmed | 日期轴与行集合照常渲染，行内只有空轴；轴上方一行「这段时间没有确认的关键事件 · 在日报阅读台标记」 | 去日报阅读台确认后刷新 |
| empty（无泳道） | 版块无持久化话题 | 「该版块暂无持久化话题」（诚实空态，不补候选行） | 无 |
| empty（选中日无事件） | 选中日在本版块 0 条 | 视图头「11/13 · 0 条」+ 轴上方一行「11/13 没有确认的关键事件」；不出现卡片区，行头「当日 0 条」 | 换一天 / 去日报阅读台 |
| 休眠泳道选中日有事件 | 选中日的 confirmed 事件只落在休眠行 | 休眠组自动展开当天有事件的行并显示卡片列 | 换选无事件的日子后按原规则折叠 |
| error | 版块级事件读取失败 | 视图内错误条 + 「重试」；MUST NOT 冒称 0 条 | 点重试；失败保留上次内容并标陈旧 |
| stale | 刷新失败但已有内容 | 保留内容 + 「刷新失败，展示上次数据」条 | 重试 |
| success | 有 ≥1 条事件 | 上下两带标签 + 引线；选中日整列淡底 + 各泳道卡片列 | — |

## Layout Contract

- **layout mode**：`workspace`（继承版块态势页；`AppPageShell mode="workspace" :gutter="0"`）。
- **目标视口**：1440×900 与 1920×1080；两档均要求无页面级横向滚动。
- **行高实测口径**：行高 = `max(标签行高, 卡片列占位高)`；卡片列占位高取**实测**（每行一个 `ResizeObserver` 观察 `.kev-cards`），任何原因导致的卡片变高都要让行高跟上，MUST NOT 只依赖点击 / `transitionend` 入口（2026-11-24 用户反馈 R-35）。
- **栏宽与溢出**：版块栏与治理右轨不变。列宽 = `max(64px, 主舞台可用宽 / 可见日数)`（**不变**）；总宽超出舞台由舞台容器内部横向滚动承接（行头 sticky、选中日滚入视口）。
- **行内三段**：上带（层数 La）· 轴带（18px：生命线居中、圆点骑线）· 下带（层数 Lb）。标签高 24px、层距 32px、带间留白 8px。
  - 行高 = `max(70px, 50 + 32 × (La + Lb))`；4 层时 178px，仍低于既有 246px 封顶。
  - 生命线在行内的纵向位置随 La 变化；行头文字与生命线对齐。生命线取 `--color-text-muted`（原 `--color-border-medium` 对比度仅 1.67:1，承载不了引线树）。
- **圆点**：在日期列中心；同日多条以 **24px** 步长横向散开，互不压盖。
- **引线**：自圆点外缘垂直走到标签垂直中线，再水平 12px 接入标签近端边缘；线宽 1.5px，画在标签之下（标签遮线不遮字）。**同日多条 = 树形分叉**：并排的竖主干各自接到上下堆叠的标签，默认近端对齐到「该日最右圆点 + 12px」（圆点在标签右侧时近端 = 标签右缘）。**右侧放不下时的绕线规则（实现期定案，R-15）**：整组改摆到圆点**左侧**（组右缘 = 该日最左圆点 − 12px），使组内所有竖引线落在标签横向范围之外；**「组内引线不穿组内标签」优先于「近端对齐最右圆点」**。**仅「同日多条组」**右侧放不下时才改摆圆点左侧（多条组才有「组内其它标签」需要避让）。**同日单条组**右侧放不下时直接贴右缘：单条组不存在组内其它标签，圆点落在标签横向范围内时引线按 design 的 `inside` 分支退化为一段竖线段（原型同款行为）——实测 30 天 11 条若把单条组也镜像，层数会从 4 涨到 5 触发整行收起。仅几何无解（组宽 > 最左圆点 − 12px）时才由调用方收起该行。
- **归带与分层**：按日期升序逐组决定；每组占连续 k 层（k = 该日条数）。上 / 下带各算代价：`100 ×（该带内已有标签横向覆盖本组任一引线的条数）+ 10 ×（起始层 + k）+ 3 ×（该带已用层数）`，取代价小的带（并列取下带）。同层间隙 ≥ 4px；贴右缘放不下时整组左移贴边。
- **收起判据不变**：层数口径 = La + Lb；总层数 > 4 的**该行**收起为「圆点 + ★N」。真实数据实测：`LLM生态相关新闻` 近 30 天 11 条标签在 64px 列宽下排成 4 层（上 2 / 下 2），不触发收起。
- **日聚焦卡片列**（选中日 S 所在的行）：
  - S 日的药丸标签撤下；卡片列放下带，左缘 = S 列左缘，宽 **280px**，顶 = 轴带下缘 + 8px；
  - 右边放不下（S 列左缘 + 280px > 行内宽）时改为**右缘对齐 S 列右缘向左展开**，MUST NOT 伸出舞台；
  - 下带其它标签的横向范围 MUST NOT 与卡片矩形相交，相交的组改去上带；
  - 卡片纵向堆叠；≤ 4 张全部展开、**不设行高封顶**；> 4 张固定高度内部滚动并标「还有 N 条」；
  - 该行行高 = `max(常规行高, 轴带下缘 + 8px + 卡片堆叠高 + 8px)`。
- **卡片（紧凑形态，用户 2026-11-23 批准时选定）**：首行「MM/DD 周X · 所属话题」（日期加粗、事件色；话题弱化，同一行）→ 标题（完整显示、可折行，MUST NOT 省略号截断）→ 摘要 1 行节选（点开就地展开全文）→ 「关联文章 N 篇 ›」文字链（展开文章列表）。单卡高约 116px；同一泳道当日 2 张时卡片列约 240px。原型截图里是舒展卡片（约 167px），以本条为准。
- **长窗**：MUST NOT 因观察窗天数长就整视图收成光点。
- **窄屏**：`<768px` 不渲染本视图。
- **双主题**：亮 / 暗两套主题复用产品语义变量（`--color-bg-*` / `--color-text-*` / `--color-border-*` / `--color-accent`），MUST NOT 写死色值。
- **事件色（新增语义 token，用户 2026-11-23 选定）**：新增 `--color-event`，用于圆点描边、引线、卡片首行日期。**取值以产品 `main.css` 的真实底色为口径**（`--color-bg-elevated` = `--raw-stone-100` = `#f5f0e6`，`--color-bg-base` = `#faf7f2`）：亮色 `#8f5a17`（对 elevated **5.08:1**、对 base 5.39:1）、暗色 `#e0a75a`（对暗底 ≈ 8.15:1）。原型内部把 `bg-elevated` 写成 `#fffdf9` 并取 `#9a6219`，该组合对 **原型自己的底色** 是 5.0:1，但对产品真实底色只有 4.47:1——已按产品底色重标定，视觉上与原型几乎无差。token 落 `front/app/assets/css/main.css` 并登记 `docs/reference/standard/frontend/theming.md`。分工：**琥珀 = 事件，强调色 = 我选中的那天**（亮色为红 `#d94a4a`，暗色为橙红 `rgba(240,138,75,.85)`——故只靠色相区分不够，选中日另靠「整列底色 + 轴头加粗 + 实心节点」三重冗余）；现有 `--color-tag-event`（文章事件标签）亮色对比度仅 2.46:1，不足以画细线——不复用、也不改它的值。
- **dialog**：本视图自身不新增弹窗；文章预览复用既有 `ArticlePreviewModal`。

## Acceptance

- agent-browser 断言：
  - 扫读形态：每条标签存在一根连到其圆点的引线；同日两条呈分叉且标签互不重叠；标签 MUST NOT 越出行容器。
  - 30 天窗口：列宽 64px 下限、舞台内横滚；`LLM生态相关新闻` 行标签全部显示名称（层数 ≤ 4）。
  - 选日（点轴头）→ 该日在**所有**有事件的泳道内同时展开卡片列；卡片标题完整、无省略号；摘要可展开；关联文章可展开并打开既有文章预览。
  - 选 11/22 → 卡片不伸出舞台右缘。
  - 换选另一日期 → 前一天卡片列收起、新一天展开，行高随卡片堆叠重算；无「取消选中」路径。
  - 下方不再出现「当日关键事件」阅读区。
  - 悬停标签 → 对应引线 / 圆点 / 轴头日期加重；移开恢复；`selectedDate` 不变。
- 1440×900 与 1920×1080 两档截图（含暗色），确认无页面级横向滚动、卡片不越出舞台、行头与生命线对齐。
- **红线回归断言**：候选话题行不出现；`suggested` / `dismissed` 不出现；右轨选话题仍先切回矩阵 / 追踪；本视图无注记写入口。
- 与批准原型的差异说明写入 `ui-verification/report.md`；信息架构 / 主流程 / 布局模式有变时重置 `ui-approval: pending`。

- **D3 依据**：用户 2026-11-23 实看原型后指出「最大的问题是看不懂这是哪一天的事件」，并定方案「上下两部分、折线引出、多个用树、高度动态适配」。标签宽 150–330px 而日期列仅 64–165px，位置无法编码日期，必须连线。判据 P5：需并列比较的是同一天在不同泳道的事件，保持同页并列。
- **D4 依据**：用户 2026-11-23 从四个形态中选定「日聚焦卡片列」+「整日展开所有泳道」。P5：`dialog` 逐条串行违反并列比较；`drawer` 会盖住时间轴上下文。
- **D5 依据**：P2，展开摘要 / 关联文章是就地可见上下文的单点动作。
- **D6 依据**：用户 2026-11-23 选 B。P2：日期选择是单个字段，行内控件就地选。不放进与矩阵共用的 `ObservationRangeControls`，避免矩阵视图跟着出现新控件。
- **D7 依据**：引线已静态解决「哪一天」，悬停强调消掉密集处引线从旁标签背后穿过（实测 14 天 1 次、30 天 2 次）的残余歧义；判据 P5（并列比较时每条标签须可追溯）。用户 2026-11-23 批准的原型默认开启，随之置 pinned。
- **D8 依据**：用户 2026-11-23「直接去掉」。泳道内卡片已完整承接阅读区能力；保留会造成同一内容两份。
- **变更来源**：D3 / D6 / D8 均为用户 2026-11-23 对话明确改口，由主线程写回台账。
