# 原型里人眼数不准的那几件事，交给机器

## Why

你的原话（ISS-03 立项时）：

> 越改越散、状态不闭环、操作反人类。

这半年的复盘点在同一个地方：**原型是返工最大的一块**，但复盘出来的结论大多是「下次注意」。而「下次注意」这种话，和刚修掉的 `ui-stage` marker 是同一种东西——**它依赖执行者主动遵守**。

ISS-03 已经按「人眼可靠吗」把候选检查分过两堆：

| 检查件 | 人眼可靠吗 | 结论 |
| --- | --- | --- |
| 热区太小、可点元素没有 hover/focus、危险按钮没二次确认 | **不可靠**（100 个元素数不过来） | 留，纯机械 |
| 状态有没有路径能到达（闭环） | 可靠（看图就看出来） | 砍，交给人 |
| 状态该不该存在、流程顺不顺 | 只有人能判 | 本就不该机器管 |
| 单屏可点数 >12 | 可靠（一眼就知道挤不挤） | 砍 |

**但评审推翻了「留下那一行」中的三项**（详见 What Changes 第 2 点）：热区/焦点/悬停的静态判定只能看「字样在不在」，做不出可信判定。最终只机器化**危险操作确认**一项。

### 一个必须先说清的事实

「44px 热区」这条规范**在权威文档里根本不存在**。`grep -rn '44px' docs/reference/standard/` 零命中，唯一匹配是 flow 文档里一个无关的「层距 44px」。它是 ISS-03 台账里的一句话。

所以本 change 有一半工作是**把规范本身写下来**，另一半才是检查。

## What Changes

### 1. 规范先分两类原型（用户澄清的关键点）

现存那个「原型」不是功能原型，是 **three.js 首页改版的视觉探索**：顶层 20 个平级 HTML（`city-workflow.html`、`module-01..09-*.html`）、`blender-pilot/`、`city-grid-shots/`、整目录 504 文件 / 98M。**这些不是「原型目录成了垃圾桶」，是视觉探索的正常形态。**

所以规范先分两类：

| 类别 | 特征 | 机械检查 |
|---|---|---|
| **功能原型** | 状态/交互/组件，驱动功能开发 | 适用 |
| **视觉探索原型** | three.js / 品牌 / 动效实验，多版本并存 | **不适用** |

声明在 proposal 头部：`<!-- ui-prototype-kind: exploratory(理由) -->`，默认 `functional`。

### 2. 只机器化一项：危险操作必须有二次确认

原计划的四项里，**只有这一项做得出可信判定**——它不依赖 CSS 解析，是「有没有这个机制」的事实判断。

评审实测另三件是形式主义：
- EC-1 热区：任何容器有一处 `padding: 24px` 全过；`padding: 12px 24px` 反而判红
- EC-2/EC-3：判的是「出现过 `:focus` 字样」——`outline: none` 过关，用浏览器默认焦点环的反被判红

这三项**撤回机器检查**，但在规范里保留为**人核的设计下限**（热区 24×24 等），并明写「不做机器检查」及原因。

### 3. 挂到真会拦的地方

`spec-gate.ts` 检查⑨（阻断）+ `archive-readiness.sh` 第⑨项（自查），判定逻辑只在脚本一份。

## Impact

- **新增**：`scripts/harness/ui-prototype-check.sh`（约 200 行）、`scripts/harness/ui-prototype-check.smoke.sh`
- **改动**：`spec-gate.ts`（加检查⑨）、`archive-readiness.sh`（加第⑨项 + smoke 16→17）、`prototype-content.md`（+1 节）、`开发执行规范.md` §11 门禁清单（八项→九项）
- **零前端零后端改动**
- **风险**：静态判定的固有误报（动态类名、JS 生成 DOM）。用 `data-ui-mechanics-skip="<理由>"` 显式豁免，与 `ui-skip` 同纪律
- **可回检**：脚本输出 reasonCode，可统计哪一条最常触发 → 判断是规范太严还是原型太随意

## 已知残留

- **静态扫不到 JS 生成的 DOM**：原型若用 JS 拼界面，检查会漏。现存原型是手写 HTML，暂时没问题；将来若普遍用框架，需改渲染实测
- **「有声明」不等于「够大」**：写了 `min-height: 12px` 也能过。这是静态方案的固有上限，写进规范注释
- **`data-destructive` 是新约定**：存量原型 0 处使用，只能靠文字关键词。两通道里 data 通道要等新原型才用得上
