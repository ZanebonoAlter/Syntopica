# 讨论记录：叙事工坊 → 雷达 + 阅读台（2026-10-23 ~ 10-24）

> 本文件是设计探索的过程档，不是规范。权威结论在 `proposal.md` / `ui-design.md` / `design.md` / `specs/`；本文件记录**为什么走到这里、哪些方案被否、哪些数字是实测的**，避免以后重复讨论。
> 原型：`ui-prototype/`（可丢弃，`node ui-prototype/build.js` 重建）；本地工作副本在 `docs/research/narrative-workshop-screen/`（gitignore）。

## 0. 起点

用户诉求（原话要点）：「叙事工坊大部分是卡片堆积，想在产品设定上做成类似大屏的设计，讨论下架构选项和产品 ui/ux 设计方向。」
同时在 4K 本地屏使用，明确**不做挂墙数据大屏**，定位是**观看便利度**。

## 1. 诊断（第一轮）

对照 `/tags` 现状（截图 + 代码）：

```
叙事工坊 = 固定左栏（选版块） + 可滚动内容区
内容区   = 5 份互斥文档（切 tab = 换整份文档）
          板块内容 / 话题总览 / 日报 / 文章 / 研究
```

三个结构性问题：

| 症状 | 事实 |
| --- | --- |
| **tab 失忆** | 体检 85 / 挂载 128 / 幽灵 0 / 追踪 3 都在「板块内容」里；切到话题总览或日报就全丢 |
| **矩阵被画成列表** | `LaneDynamicsCard` 内部已是「泳道 × 日期 × 事件」矩阵；渲染成 `minmax(360px,1fr)` 卡片墙后，14 天横向节奏被压进每张卡各自的竖轴 |
| **同一数据画三遍** | 泳道动态（卡片）/ 话题总览（DAG + 话题泳道）/ 侦探墙（3D） |

另有两个缺口：`全部` 状态给的是标签池（不是总览）；内容区没有 max-width（1920 下表格被拉长、组合标签行右侧大片空白）。

## 2. 「大屏」的三种含义（第一轮辨析）

| | 是什么 | 结论 |
| --- | --- | --- |
| A 数据大屏（wall） | 16:9 定屏、发光线条、挂墙可读 | **否决**：与 editorial/暖纸基调冲突，中文字号在 1080p 下不可读，容易变装饰 |
| B 指挥台（console） | 固定视口 + 分区栅格 + 关键状态常驻 + 点击钻取 | **采纳为骨架** |
| C 剧场（stage） | 一屏一个主载体，其余浮层 | 留给单个载体（侦探墙） |

当时的四个架构选项（A 单屏指挥台 / B 舞台+抽屉 / C 精修现有滚动 / D 双模式）在用户给出真实使用方式后被收敛为「一个脊 + 一种编辑态」。

## 3. 用户给出的四条硬约束（第二轮）

1. 每天主要是看日报，空闲才钻取文章详情；
2. 态势文字太多看不清；
3. 关键事件的演进怎么串起来是核心；
4. 缺「最近哪几个版块火热」「今天哪几个版块可能有较多关键事件」的提醒。

由此产生 4 个原型（`ui-prototype/index.html`）：

| 原型 | 赌注 |
| --- | --- |
| P1 今日雷达 | 每天第一动作是「今天该看谁」；版块按热度横排，常温压成一行 |
| P2 演进脊柱 | 缺的是「怎么走到今天」；矩阵 + 演进带 + 结构化态势 token |
| P3 日报阅读台 | 主任务是读，给足行宽字号；左右只做导航 |
| P4 晨间一屏 | P1 压成热度带叠在 P3 上，一条屏走完早间 |

**演进串起来的答案**：用「泳道（topic）」当贯穿 id——`雷达 → 矩阵 → 演进带 → 日报分区 → 文章` 四跳都指同一个 topic，右栏永远是上一层级的上下文。

## 4. IA 定稿（第三轮）

用户确认：P3 替换现有日报阅读体验；P1 做首屏；矩阵/关系图/文章是同一层三个视图；标签池挪设置页（「这玩意目前没有作用」）。

对象模型与四级脊：

```
L0 /tags            雷达（跨版块）
L1 /tags/:boardId   版块态势（矩阵=默认视图 / 归档视图 / 编排态）
L3 /tags/:boardId/:date  日报阅读台
L4 文章抽屉（60% 宽，背后不卸载）
```

旧功能归位表（全量，见 ui-design.md §IA）：

| 旧入口 | 新家 |
| --- | --- |
| 泳道卡片墙 | 矩阵 + 演进带（卡片退役） |
| 话题总览 DAG / 话题泳道 / focus | 矩阵视图（断档已表达连续性）；关系图降级到编排态 |
| 体检面板（评分/质量表/组合/候选/趋势） | 右轨（信号）+ 治理抽屉（明细） |
| 来源构成面板 | 右轨 top3 + 抽屉全量 |
| 文章 tab | 归档视图 |
| 研究（beta，数据增强） | 版块 ⋯ → 独立全屏工作台（不进主脊） |
| 匹配参数 / 标签合并 / 回填 / 升级建议 | 设置页或版块 ⋯ 菜单（全局动作不该挂在版块栏） |
| 辅助/组合标签池 | 设置页 |
| 侦探墙 | 矩阵右上「全景」 |

四类跳转的语义：点格子 → section 抽屉（不开新 tab）；点泳道名 → 换演进带；点候选 chip → 进编排；点线索 → 文章抽屉。

## 5. 第二轮推翻与修正（第四轮）

用户三点反馈直接改了三处：

1. **「矩阵把关系图的故事讲了」** → 认同。矩阵行内断档已表达「连续/断档」；关系图作为同级视图冗余，而且跨泳道边要另拉 `section-timeline.relations`（`lane-dynamics` 不带边）。→ 关系图**降级为编排态的选料辅助**。
2. **归档要留档 + 看匹配理由**：不是「文章列表」。→ 归档视图 = 遗漏档案：按命中标签分组（一组≈一次事件）、标「未入日报」、展开看规则/分数/降级/方向校验。
3. **休眠泳道**：14 天 ≤2 个 section 的活跃泳道折叠；**前端派生**，不加 `dormant` 状态（现成状态只有 candidate/active/archived，加状态要动状态机与迁移）。

**窄屏方案（用户让我定）**：<768 只保留「雷达 → 版块摘要（泳道列表 + 迷你 14 天条）→ 日报」；矩阵不横滚；编排态禁用并提示用宽屏。理由：4K 单用户产品，窄屏是「手机上瞄一眼」，横滚会毁掉「一眼」。

## 6. 编排态 v2（第五轮）

第一版「话题托盘」被否（「新增泳道有点粗糙」），对着现有功能（截图里的 compose 态）补齐：

- 画布：日期列 × 6 条 active 泳道（圆点）+ 底部「待确认 / 未分类」（chip），颜色按话题色相归一到暗底可读；
- 相似关系：`section-timeline` 的 125 条 relation 默认隐藏，点节点画 top-6 虚线并列出距离；
- 候选侧栏：连续 N 天 / 采纳（预填名 + 预勾）/ 确认启用（连续 ≥2 天才可点）/ 已中断折叠 / 搜索；
- 质量：成员 / 平均距离（真实 distance 均值）/ 离群（最小距离 > 0.35）。

## 7. 实测数字（本地真库，board 1974 中东地缘政治，2026-10-23）

| 指标 | 值 |
| --- | --- |
| 泳道（active topic） | 6 条；14 天 84 个分区 |
| 待确认 section / 候选话题 | 17 / 17（卡片：马克龙、沙特海水淡化、美国 PMI、加拿大免税贸易…） |
| 满足「连续多天」的候选 | **1 个**（鲁比奥/印度贸易，2 天） |
| section 时间线 | 69 个 section，125 条 similarity 关系 |
| 关系距离 | min 0.051 / p25 0.116 / 中位 0.142 / p75 0.168 / max 0.259；单节点最大度 6（后端已截断 top-6） |
| 体检 | 85 分（好），挂载 128，幽灵 5，14 轮趋势 68→85 |
| 构成 / 来源 | 39 个构成标签；窗口 7 天 118 篇、5 个来源（最大源 50%） |
| 文章归档 | 20 篇中 12 篇进了日报、8 篇未进、6 篇弱证据 |
| 关键案例 | 「霍尔木兹海峡」组 3 篇全是 `max_sim 1.00 ↓` 且全部未入日报——弱证据整组遗漏 |

**两个由数据得出的结论**
1. 「确认启用」大面积置灰不是 UI 问题，是候选机制基本只在产出单日话题（16/17 连续 1 天）。
2. 关联推荐已是每节点 top-6 最近邻，所以「推荐没优化好」更可能出在上游相似度/候选粒度，而不是界面。

## 8. 被否方案清单（避免重开）

| 方案 | 否因 |
| --- | --- |
| 数据大屏 / 发光 / 仪表盘 | 撞 editorial 基调；中文小字不可读；装饰大于信息 |
| 单路由 + 内部层级状态 | 层级不可收藏/回退，首屏要等 JS |
| 新建 matrix 专用端点 | 口径分裂；lane-dynamics 已有同样数据 |
| 给文章表加 `in_report` 列 | 日报重生成会使列失效，需回填任务；派生查询够用 |
| 新增 `dormant` 话题状态 | 要动状态机 + 迁移；折叠是纯展示规则 |
| 矩阵横向滚动（窄屏） | 滚到第 3 天看不见第 10 天，「一眼」价值归零 |
| 重写日报 reader | 页边注 / watch 定位 / 深链是长期演进能力，抽壳即可 |
| 前端并行 9 路请求渲染雷达 | 首屏抖动；改用 `GET /semantic-boards/overview` |

## 9. 仍待观察

- **热度排序口径**：绝对数会让 AI 类版块长期霸榜（18 条/日 vs 中东 7 条/日）；是否改相对基线（环比 / z-score）尚未定。
- **归档补日报**：本期只做「留档 + 证据」，是否提供「补进日报」写动作（会动日报数据）未定。
- **关系图连线版**：编排态现在是「点节点看关联」+ 全量关系开关；是否要常驻显示局部子图待观察。
