# 归档视图重做阶段合同（待审）

## 背景与问题（2026-11 用户复盘）

2026-10-25 重做的归档视图（BoardArchiveView）交付后存在四类问题，用户确认主要痛点是「一个视图三代风格混杂」：

1. **风格混杂**：新手写 `ar-*` 骨架 + 旧 MatchDetailPanel（渲染在抽屉外、列表流末尾，1440×900 下 y=937 掉出视口，即 FB-3 已核实 bug）+ 原生 `<select>/<input type=date>/裸 checkbox`（违反主合同 Component Reuse「不自建第二套控件」）。
2. **行内评分明细弱化**：旧版文章 tab 的标签四色编码（`matchReasonColor`：direct_hit/hit_rate/max_sim/weighted 各一色、降级半透明）、每行最强匹配提示全部丢失；规则+分数缩成灰 chip 小字，扫描性归零。
3. **组内质量排序被 spec 砍死**：delta「归档排序」一刀切禁了跨日期排序（合理）但连同日组内质量排序也禁了；前端写死 `sort:'time'`，而后端 `sort=quality`（BestTier+BestScore）一直是默认能力。一天几十篇强弱混排。
4. **主点击行为与冻结方向不符**：FB-4 冻结「文章主点击直接站内读原文，匹配解释才是独立操作」，现实现是行点击开证据抽屉、读原文藏 footer。

## v3 修订（2026-10-31 用户第三轮反馈）

- **层级语义修正**：match-detail 实为「事件×版块」维度（事件辅助标签逐个找版块辅助池最相似对，sim≥阈值计 1 hit）；文章进版块 = 文章标签 ∩ 构成标签（判定跨文章共享）。据此前「本文命中事件辅助标签」的设想修正为三层：本文标签层 / 事件辅助×版块收编层（✓/✗逐对+M/N）/ 文章级判定。
- **计算明细改维度**：文章维度公式（进版块判定 + strong(t) 定义）放「文章判定面板」（行尾判定钮，右侧小面板，不含阅读内容）；事件级规则代入式保留、藏在 popover 展开里（用户拍板）。
- **原型数据**：新增 tag-hierarchy.json 冻结层（事件辅助全集 149 / 文章全标签 163 / 标签→semantic 展开 353 / 版块辅助池 47），238319 逐对真实（4/5，含「加沙战争→中东战争 0.84 ✓」「抵抗之弧→中东战争 0.78 ✗」这类 id 交集算不出的相似命中）；其他事件 ✓=直接重合、其余标 · 不伪造。

## v4 修订（2026-10-31 用户第四轮反馈）

- **修 UI 问题**：「判定」按钮越界 → 行列改五列（时间/主体/最强匹配/状态/判定独立列，文字链样式）；popover/判定面板去卡片堆砌（背景卡全部改栏线+缩进+点线分隔，回归报刊风）。
- **内容组织改瀑布叙事**（用户指定「第一步匹配做了什么，有没有满足，没满足走第二步」）：沿用旧版 MatchDetailPanel 的 flowSteps——⓪组合命中→①精确匹配→②余弦相似度→③命中率→④最高相似度→⑤综合加权，命中即停；每步「做了什么/结果/满足与否」三行，命中步高亮。阈值参数来自全局匹配配置（真实跨事件一致），逐事件命中数值未冻结时按需实时并如实标注。判定面板同步叙事化（「第 N 步即命中（规则 分数）→ 强证据/仅弱证据」）。

## v5 修订（2026-10-31 用户第五轮反馈）

- **匹配流程独立成通用入口**（用户：「这是对所有标签命中结果的说明，不该是单个标签的」）：工具行新增「匹配流程」，打开通用说明——⓪组合命中→①精确匹配→②余弦相似度→③命中率→④最高相似度→⑤综合加权，每步做什么/阈值（全局配置真实值）/命中即停/方向校验，对所有构成标签一致。
- **事件卡 popover 只留私有判定行**：「第 N 步即命中 · 规则 分数（命中数值）」+ 指向通用流程入口；不再在每张事件卡里重复完整瀑布。

## v6 修订（2026-10-31 用户第六轮反馈·澄清）

- **入板 chip（行内）**：每个有命中标签的文章行，标签带末尾加「入板④相似度」样式的 chip（虚线边区分于普通标签、步号取最强判定、颜色随规则色）——扫一眼即知本文靠第几步入板块（①=强快速通道、④⑤=弱通道）；点击打开通用匹配流程说明。无标签文章不显示。

## v7 修订（2026-10-31 用户第七轮澄清）

- **入板 chip = 判定入口**：点击打开判定面板，面板重组为「本文在各个阶段的得分」（参考旧版瀑布、按文章维度汇总）：匹配流程对本文全部标签顺序判定，各阶段（⓪组合/①直接/③命中率/④相似度/⑤综合）分组列出命中标签与得分，入板依据打标，空阶段如实显示；行尾「判定」钮退役（chip 即入口，行回四列）。通用流程说明保留在工具行。

## v8 修订（2026-10-31 用户第八轮反馈）

- **判定抽屉退役**：入板 chip 点击打开**锚定 popover**（与事件卡同款形态，不再右侧面板）；内容纯数据（五阶段得分 + 入板依据 + 本文标签 chips），说明文字全部删除。

## v9 修订（2026-10-31 用户第九轮反馈）

- **空阶段必须给原因**：入板过程 popover 里命中步之前的空阶段展示「为什么没命中」——最强标签为冻结样本时给真实差距数值（交集 N<M / R=x≤y / Smax 未达），否则给该阶段真实阈值 + 未达结论（静态真话）；命中步之后的阶段标「未走到（第 N 步命中即停）」弱化显示，区分「没命中」与「没走到」。

## v10 修订（2026-10-31 用户第十轮反馈·高保真）

- **类别高保真**：构成标签不限事件——keyword/person 类如实标注（「关键词」/「人物」chip、描述区标题自适应）；关键词与事件结构同构（同样有辅助标签集合与描述，如「沙特」direct_hit 0.7、辅助 ×2），同样展示辅助×收编层。
- **组合链真实冻结**：composite_hit 标签展示真实推导组合链（「伊美关系 = 伊朗 × 美国」「伊朗特朗普时期关系 = 伊朗 × 特朗普」——挂齐组合标签全部组件即推导挂载，10/10 全部真实拉取）。

## v11 修订（2026-11-01 用户第十一轮反馈·统计带去大屏化）

- **统计带 → 一行 deck（FB-14）**：四格 grid 卡片（1.5rem serif 大数字、横拉满宽）与页面其余部分（0.78rem 密排列表 + 发丝线）语言分行，且 109/52 在两行内重复、四个等宽格暗示不存在的四分法。改为一行「刊头副题」：`范围 · N 篇 ｜ 已进 X（P%）+ 比例条 ｜ 未进 Y ｜ 弱证据 Z（可与入报交叉）`。
- **弱证据不并列**：`weak` 与 `in_report` 各自独立统计（一篇无标签文章也可被日报线索引用），所以文案写「可与入报交叉」而不是「其中」；口径两句（已入定义 + 无命中标签不入日报）改为直接可见的小字，不再靠 hover 才看得到。
- **数字只出现一次**：筛选 chip 去计数（全部 / 未纳入日报 / 弱证据 只做动作），计数进 `title`；deck 里的 109/52 是唯一权威计数。
- **工具行收敛**：去掉三根竖分隔条，改为「日期快捷 + 起止 ｜ 排序 ｜ 筛选 chip ｜（右端）⚙筛选 ⓘ匹配流程」三段 + 右侧动作组；中等宽度由 flex-wrap 自然折行。
- **不变项**：四指标口径（窗口内 / 已进 / 未进 / 弱证据）、起止日期、进日报口径文案、筛选与排序行为、API 字段、质量序均不变；`specs/workshop-article-archive/spec.md` 「顶部展示四个数 + 起止 + 口径」仅约束信息量，不约束形态，故不产生 spec delta。

## User Journey

1. **带着疑问进归档**：从矩阵日格/分区工作面「看归档」带入日期，或从控制台顶栏切「归档」。默认数据锚点当天；顶部一行 deck 先回答窗口内多少篇、多少进日报（带比例）、多少弱证据，并直接写明「弱证据可与入报交叉」。
2. **扫描证据强弱**：文章按日期分组平铺；行内标签 chip 按匹配规则四色编码（边框+分数同色、降级半透明、方向不符带 ⊘），行尾「最强匹配」规则色文字一眼定强弱；chip hover 即可读规则+分数+描述摘要。
3. **组内按质量看**：组间永远日期倒序（不打乱日期阅读，delta 红线保留）；组内默认质量排序（最强证据在前），可一键切回发布时间。
4. **看文章**：行主点击 = **文章预览弹窗**（复用既有 ArticlePreviewModal，控制台 Shell 已挂载；2026-10-31 用户修订，对齐旧版习惯）。
5. **核对一个事件（层级）**：点标签 chip → 锚定事件卡 popover（定位贴切，非弹窗/非右侧工作面）：事件描述（这个事件是什么）+ 本文标签层（文章直接打了哪些 topic_tags）+ **事件辅助标签×版块收编层**（事件全部辅助标签逐个 ✓/✗，✓=与版块辅助池直接重合或最相似对 sim≥阈值，头部收编 M/N）+ 判定规则/分数/降级/方向 + 规则代入式藏展开里（KaTeX）。层级数据全部来自现有接口（/api/tags/:id/auxiliary-labels + match-detail + topic_tags.description），无新端点。
6. **看这篇文章为什么进版块**：行尾「判定」→ 右侧文章判定面板：文章级公式（文章∈版块 ⇔ 文章标签∩构成标签≠∅ 且存在强证据）+ 本文满足情况（最强判定→进版块 ✓/仅弱证据）+ 全部构成标签判定汇总（事件级共享）+ 本文全部 topic_tags（构成标签高亮）。
7. **筛遗漏**：全部/未入日报/弱证据三 chip（带计数）；来源、构成标签、显示方向不符收进「筛选」覆盖面（工具行降噪，不再常年占一行原生控件）。

## Information Architecture

```text

 ├ 工具行（v11：三段 + 右侧动作组，去竖分隔条）：日期快捷（数据日/7/14/30）+ 起止 ｜ 组内排序（质量/时间两档）｜ 全部/未入日报/弱证据（不带计数）｜ ⚙筛选 + ⓘ匹配流程（右端）
 └ 主体：日期分组文章表（组头=日期+篇数+组内弱证据计数）
    └ 行：时间(mono) · 标题 · 来源 · 标签带(四色chip×全部命中) · 最强匹配(规则色) · 入日报状态 + [判定]
 文章预览弹窗：既有 ArticlePreviewModal（纯阅读，Shell 已挂载，行主点击）
 事件卡 popover：锚定 chip（窄屏底部档）——事件描述 + 本文标签 + 事件辅助×版块收编 ✓/✗ + 规则代入式藏展开
 文章判定面板：右侧小面板（窄屏底部档）——文章级公式 + 构成标签判定汇总 + 本文全部标签
```

### 权威数据与口径（不变项）

- `in_report` / `weak_evidence` 仍由后端派生，前端只读不复制公式；「进日报 = 出现在窗口内任一日报分区线索」口径文案保留。
- 质量排序沿用后端 `sort=quality`（最佳匹配层级 → 分数），前端多页合并时**组内保持后端序**，不自行重排（BestTier/BestScore 前端不复制）。
- 四色 token 复用产品 `--color-match-*`（明暗两套已存在于 main.css），原型以 paper/ink 语义变量 + 规则色双主题重述；composite_hit 无既有 token，定为直接命中同族色（证据强族），待用户确认。
- 冻结样本：`reference/articles-1974-7d.json`（163 篇，direct_hit 8 / hit_rate 8 / max_sim 59 / weighted 91 / composite_hit 10，入报 81 / 弱 55 / 降级标签 16，方向不符 0——该状态原型仅以既有数据机制表达，不伪造样本）；`reference/match-detail-238319.json`（计算明细，pairs 截前 12 对）。

## Visual Design

- 报刊风延续矩阵阶段语言：暖纸/墨线/赭红 ↔ 深墨/铜色双主题；serif 大数字（统计带）、mono 时间/分数、无衬线正文；栏线分组，不用卡片墙/发光数据墙。
- 标签 chip：规则色边框 + 规则色分数文字；降级 = 色彩 50% 透明（color-mix）；方向不符 = ⊘ 后缀 + 虚线边。chip 溢出折叠为「+N」计数，点开在同一工作面列全（不弹新层）。
- 最强匹配：行尾独立一列，规则色文字 + 分数，等宽数字；质量排序时即扫描锚点。
- 组头：日期（mono）+ 篇数 + 弱证据计数（琥珀点缀）；组间细栏线分隔。
- 统计带（v11）：不做卡片 + 大数字，改一行 mono 数字 + 5px 已入比例条（fill 同列表 `.is-in` 的 success 色），与工具行共用发丝线分隔；弱证据前用「互」字前缀或括注表达交叉，不与前三项并列同权。
- 工具行（v11）：三段分组 + 右端动作组，竖分隔条全部退役；中等宽度靠 flex-wrap 折行，不横向滚动。
- 控件全部走产品档：AppToggle（排序/方向不符）、AppInput（日期）、AppSelect 或覆盖面内列表（来源/标签）——原型静态表达形态与档位，产品实施换真实组件，不自建第二套。
