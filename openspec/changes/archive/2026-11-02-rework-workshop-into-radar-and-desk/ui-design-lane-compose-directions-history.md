2026-10-30。用户认为此前不直观、默认候选多且未必准，要求据实际候选再调整。本轮只改原型起点和名单分工：**少量当前方向＋真实成员事件先展示；人勾选后才进入编排；历史管理候选另放。** 不声称后台推荐准确率已提高。上版 [人工纠错合同](ui-design-lane-compose-correction-history.md) 及原型保留，总览/矩阵已批范围不变。

## User Journey

1. 起点不再自动铺开32条历史候选；默认展开3个以内当前材料中的方向，其余合格方向保留按需展开入口；每个直接列出真实事件、日期，不只看一个抽象候选名。
2. 用户先判断是不是同一条线，再勾选。默认0勾选，不自动采纳整组，也不自动补相似项。
3. 点唯一主动作“用选中的N条事件开始”，只把明确勾选项加入草稿；可跨方向挑选，不要求服从原分组。
4. 如果这些方向不合适，显式“不合适？自己从全部事件里选”直接进入完整工作面，允许0成员起步，不被推荐封路。
5. 编排主面沿上一版：全部13条可选事件及真实关系，没连线也能加入；已有正式泳道节点可显示只读参照。
6. 最后起名，合法草稿只做离线模拟创建。历史话题直接启用是另一条路径，不与本次人工新建混淆。

## Information Architecture

### 起点：contained

生产布局选 `AppPageShell(mode=contained)`，上限1120px居中；不是大标题占一侧的展示页。

- 小标题“新建泳道”＋一句操作提示。
- 默认3个以内的朴素分组列表：降级标识的“原话题名” → 实际事件标题与日期 → 复选框；其余方向可展开，不静默丢弃。没有评分、热度墙、图表或质量徽标。
- 每组默认最多3条事件，更多真实成员可展开；本样本每组2条，共6条，一眼可核对。
- 底部一个主动作“用选中的事件开始”；0勾选时禁用。
- 同处轻入口：手动选全部事件、继续已有草稿（有才显示）、历史待启用话题（32）。

### 编排：workspace

生产布局切换 `AppPageShell(mode=workspace)`，沿上版人工纠错面，不退回只看算法推荐：

- 全部本窗可选节点与原边常驻；标题只聚焦，checkbox/独立移除改成员。
- 常驻“显示已有泳道节点（只读）”“高亮当前关联”两个视图开关。
- 右轨仅核对本次成员/当前事件/关联快捷入口；技术指标在次级说明里。
- 底部唯一创建主动作，命名md；完整参照图xl仍可达。
- <768px只提示宽屏/横屏；不新增产品窄屏编排路由。

## Reuse & Data

### 必须分开的两种名单

| 名单 | 来源与用途 | 不能混淆的边界 |
| --- | --- | --- |
| 当前材料方向 | 原 `compose-candidates` 14天pool里非active、当前归属candidate的节点；按原topic ID归组 | 用于人工编排指导，可包含尚未达管理可见门槛的observing；不是直接启用资格 |
| 历史待启用话题 | 原 `/topics` 管理接口，沿 `FilterVisibleTopics` 累计HitCount门槛 | 保留管理可见/启用规则，不为减少推荐噪声自动归档、删除或改状态 |

现状核查：中东32个管理候选在当前pool都无owned，但当前pool有10个candidate归属未在管理名单，命中数为1/2。这是管理门槛合法隐藏，不是TOP50截断；人工编排不应只复用可启用名单。

### 本轮原型的展示提案（不是后台新算法）

`buildDirections` 仅按原ID分组：非active的candidate节点，同ID至少2条、分布在至少2个报告日期；按最新成员日期倒序、成员数倒序、ID升序，保留全部合格组，默认先展开3组，其余用“还有N个方向”按需展开。每组先列最近3条，可展开剩余。

这是一条**待审批的视图筛选规则**，不作质量保证、不改变候选生命周期、不新增距离阈值、不调用AI，也不把“跨两日”误当成直接启用门槛。单条/没被列出的节点仍全量可手动选。相同标签但不同ID不合并，不对标题做前端语义改写。

当前真实样本显示ID1984/1914/1845三组，各2条、跨2日。原方向标题可能仍不准确，故直接露出成员让人核对；不因被展示就宣称它是一条好叙事线。

历史“直接启用”在本原型中按服务端 `can_activate` 显示资格，撤掉之前原型照搬的 `consecutive_hits>=2` 条件；**只是对齐已有后端权威字段，不改产品后端门槛或PATCH行为**。产品宿主旧冲突仍需正式实现时处理，不能把原型当修复上线。

### 输入与复用

- 中东板块1974；2026-10-30实际只读采样。topics/candidates来自最近核查的原始响应，timeline再次GET只读留样；无写接口。
- 65条带向量分区：13条可选、52条active只读；67时间线分区/123原边，默认13节点4边，全参照65节点112边。
- 管理topics含50话题、32 candidate；方向使用其中没有的观察中topic ID，不要求升级资格。
- 产品复用 `usePersistentTopicsApi` / `useDailyReportsApi` 正常转换后的camelCase数据，ID字符串；原型raw JSON边界映射不授权产品组件散落snake_case转换。
- 代码锚点：`front/app/features/tags/composables/useInlineCompose.ts`、`components/ComposeSidebar.vue`、`components/console/BoardComposeOverlay.vue`；管理筛选 `backend-go/internal/topicgraph/repository/daily_report_topic_repository.go:FilterVisibleTopics`。

## Visual Design

沿报刊纸/墨/细分隔线与既有双主题，去掉起点大幅口号和左右英雄区。起点为一个居中列表，不堆候选卡片。原话题名用14px无衬线次要字并显式标识，不冒充系统精选概括；日期11px，成员14px主字色，完整换行。计数只写“共N条”，不把跨日天数摆成质量分。勾选态只用复选框＋浅底，主动作只有一个。

编排视觉沿已取样的纠错版：成员浅朱红、焦点墨框、原关系身份实线/相似虚线；密集参照其他边保留为淡背景，点节点看其全量邻接。不把人工成员标记画成虚构算法边。

## Interaction & States

| 动作/状态 | 行为 |
| --- | --- |
| 默认 | 3组/6事件、0勾选；历史32行不出现；不填名称、不自动选全组 |
| 勾选起点事件 | 只更新预览选择；未点开始前不进入本次成员集合；取消勾选恢复禁用态 |
| 用选中事件开始 | 只带明确勾选项，可跨组；不调用旧adopt自动相似补选；若同组且无已有名称，仅预填原名称供最后修改 |
| 自己选 | 可0成员进入13条全量工作面；若先有预览勾选则保留这些明确选择，不静默丢失 |
| 返回起点 | 已确认成员保留并可继续；预览选择不自动全勾，无新选项时开始按钮禁用 |
| 预览/编排Esc | 有未提交选择时请求退出确认；取消保留；弹层Esc只关当前层 |
| 无可展示方向 | 如实空态＋手动入口；不补造方向，不为凑3个降低门槛或合并不同ID |
| 历史名单 | 只有显式打开才出现；声明不是当前推荐；资格用服务端字段；直接启用仅说明、不写入 |
| 历史带入草稿 | 保留旧adopt行为并披露新增预选数量；不与主面“仅带明确勾选”混淆 |
| 编排无边节点 | 全量可见、可选、可创建；推荐只提示，不作人工准入 |
| active节点 | 可显示/定位参照、不可悄悄移出；跨正式泳道纠错仍需另议人工确认 |
| 0成员 | 留在编排供浏览，创建禁用；不强制退出工作面 |
| 命名与创建 | 最后输入，空白拦截，关闭保草稿；合法值仅本地模拟，成功重置，不跳生产页面 |

## Constraints & Open Questions

1. **没有宣称推荐更准**：只减少过期管理库存的默认曝光，把事件证据摆在前面。当前分组本身仍可能不准，选择权在人；后端聚类/命名质量若要改需另议。
2. 候选质心事实不变：平时按所属最近CentroidWindow条分区平均（默认30条），有效<2回Embedding；直接启用不补算；旧缺质心风险未知且未修。人工新建以全部有效已选均值写初始Embedding，之后随日报滚动刷新。
3. 不写永久人工边、不伪造关系；主面只画原relations。跨active归属移入未批准，不借本轮解除。
4. **部署后影响＋操作**：只更新原型/设计记录，产品默认候选和后端算法尚未改变；不部署、不配置、不迁移、不重生成、不回填。旧候选不自动归档删除，旧缺质心不自动修复，用户无需清理。
5. 当前制品待审；只授权做原型，不等于产品实现批准。已批准总览/矩阵不重绘，历史三栏/引导/纠错版目录均保留。
