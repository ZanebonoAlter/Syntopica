## 三之三、画布滚轮缩放（2026-11-01 用户补充）

- 滚轮以**光标为锚点**缩放，0.5×–3×、步进 1.1；右下角有读数 + 「重置」。
- **1:1 契约不破**：100% 时 `viewBox` 宽 == 容器 `clientWidth`；缩放**不改 viewBox**、只改 SVG 元素尺寸 → 日期列不重排（缩放是「看细节」，不是「换布局」）。
- 缩小时按像素下限补偿（普通点 ≥3px、只读 ≥2.5px）；节点卡按缩放换算仍贴节点跟随（E16.5 量测 <200px）。
- 画布上滚轮 `defaultPrevented`（不把页面滚走）；**已知取舍**：画布的纵向滚动改用容器滚动条，`scrollbar-gutter: stable` 常驻预留约 10–15px 滚动条槽（换缩放全程容器宽度恒定、日期列不漂移）。

## 三之四、画布拖拽平移（2026-11-01 用户补充）

- 按住左键拖画布即平移：内容跟着指针走（滚动位置与指针位移**反向**）。
- **拖 ≠ 点**：位移 <4px 算「点」，节点的点击（选中 / 节点卡 / 快捷选入）照常生效；拖完那一下 click 不会误选节点。
- **实现期踩到的坑（如实留档）**：最初在 `pointerdown` 就 `setPointerCapture` → 浏览器把随后的 `pointerup`/`click` **改派到画布**，节点点不中 → E7.3「卡片跟随选中节点」直接红。改法：指针捕获**只在判定为拖拽的那一刻**启用。已写进契约 §2.3 与 delta spec。

## 三之五、节点卡塌成竖条（2026-11-01 用户报障，已修）

用户实机截图（3840×1907）报「有超长的显示 bug」：节点卡被压成一条 ~25px 宽的竖条，标题一个字一行。

- **复现与量测**：1920 视口 + 126% 缩放 + 聚焦右缘节点 → 卡片 **92×296**；容器宽 1290、卡片 `left=1197.77` → 可用宽 = 1290 − 1197.77 = **92.23**（= 实测宽度）。
- **成因**：绝对定位卡片默认 shrink-to-fit，宽度被「容器宽 − left」夹住；而 `left` 又用**渲染后量出来的宽度**算 → **反馈环**（量到 92 → 更靠右 → 可用宽更小 → …）→ 塌成竖条。缩放上线后节点屏幕坐标变大，翻到左侧的分支变多，触发概率显著上升。
- **修法**：宽度改用常量 `CARD_WIDTH = 300` 参与定位、量出来的只取高度；样式固定宽度 + `max-height` 封顶 + 卡内滚动。
- **回归**：源码锚（`LaneComposeCanvas.test.ts` Z8）+ 真机 E16.8（真实浏览器量宽 ≥240px、高度 ≤320px）。
