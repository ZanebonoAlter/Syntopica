## Why

当前版块按语义相似度组织新闻，版块调查又只能读取父简报派生的本版块泳道，因此系统无法泛化地发现、核验和沉淀跨版块关系；已经配置的博查搜索也主要停留在单次手动研究上下文中。需要增加一套与具体领域无关、由外部证据搭桥的关系发现能力，让系统从任意内部观察出发寻找潜在关联，同时确保未经验证和人工确认的关系不会污染简报。

## What Changes

- 增加“证据支撑的跨版块关系发现”能力：从任意 observation 或 research question 出发，通过博查原始搜索结果提取外部概念，再将概念解析到内部版块或泳道；无法可靠映射时保留为 unresolved，不强制选择最相似目标。
- 将候选发现与关系验证拆成两个独立阶段：发现阶段追求召回，验证阶段根据原始证据、反证和替代解释给出 `supported`、`contested`、`insufficient` 或 `rejected`，不得将模型自评分直接作为置信度。
- 增加泛用关系类型与持久化生命周期，覆盖因果影响、共同驱动、分化、仅相关、上下文补充和不明确；关系从 `proposed` / `unresolved` 进入 `confirmed`、`dismissed` 或 `expired`，只有人工确认的关系才能注入后续简报。
- 扩展版块调查的内部探索能力：工具先返回候选版块/泳道概要，只有本次工具实际返回的 ID 才获得临时读取授权，随后方可调用泳道详情；继续拦截任意猜测或越权的 lane ID。
- 提供手动与自动两种触发入口，共用同一发现引擎：手动入口默认可用；自动入口按版块配置、默认关闭，并以异步、有预算的方式从新简报观察中产生建议，绝不自动确认。
- 保留博查 `summary:false` 原始结果模式，并持久化建议所引用的可核查来源、引用片段、检索时间、反证和映射依据；搜索失败或材料不足时诚实降级，不强造关系。
- 在前端提供关系建议的证据审阅、确认、搁置/驳回和过期状态展示；确认结果可从相关版块和调查结果中追溯。
- 不引入财经、地缘政治或特定版块关键词规则；时间先后、实体共现、数值相关等只作为可选证据类型，不是全局硬门槛。

## Capabilities

### New Capabilities

- `cross-board-relation-discovery`: 从内部观察经外部证据发现、解析、验证并裁决跨版块关系的通用能力，包括关系生命周期、证据契约、触发策略和失败降级。

### Modified Capabilities

- `data-enrichment`: 扩展研究工具的内部上下文发现、动态授权和外部证据留存要求，使调查可以安全地跨版块下钻。
- `board-level-analysis`: 允许版块调查引用经动态授权的其他版块泳道，并允许后续版块简报消费已确认且仍有效的跨版块关系，同时保持简报本身不主动联网。

## Impact

- 后端：`backend-go/internal/dataenrichment/` 的工具注册、调查研究循环、关系发现编排、结果/证据持久化、异步任务和 API；可能复用现有调查纪律与升级建议裁决模式。
- 数据库：新增跨版块关系建议及证据/状态持久化结构；旧结果和旧新闻记忆无需回填，未生成关系时保持现有行为。
- 前端：版块简报或调查结果中的“发现关联”入口、关系建议列表/详情、确认与 dismiss 操作、自动发现配置。
- 配置与运行：继续使用现有博查配置；自动发现默认关闭，并增加每次运行的候选数、搜索次数和超时预算。
- 文档：更新 `docs/reference/flow/data-enrichment.md`、`docs/reference/flow/semantic-board.md`，并同步相关 API、数据库和配置参考。
- 兼容性：无破坏性 API 变更；简报只有在存在已确认且未过期关系时才增加跨版块上下文，旧数据继续降级为无跨版块关系。
