# UI 设计契约 · clarify-archive-match-rules（minor）

## 入口与入口变更

- **入口不变**：归档「文章」tab 里点命中标签 chip → 锚定在该 chip 旁的标签卡 popover（`ArchiveMatchPopover.vue` tag 模式）；点「入板」chip → 入板过程 popover（article 模式）。锚定形态、Esc / 点外关闭、窄屏全宽底部档、`Teleport to body` 层级全部沿用现契约，**不新增页面 / 面板 / 弹窗 / 导航 / 多步流程**。
- **入口变更**：无。仅 popover 内部信息块的重排与文案粒度调整；工具行「匹配流程」按钮位置与打开方式不变。
- 工具行「匹配流程」`AppDialog` 保留，内容与 popover 共用同源规则文案常量；它是「规则与阈值全貌」入口，不再是理解 popover 判定结论的前提。

## 目标信息结构（标签卡模式，A2 定稿）

```
[头区]  标签名 · 类别 · 「第①步 精确匹配 命中」 · 得分(规则色) · 降级/方向标记
        指标行：相似达标 5/5 · R 1.00 · Smax 0.86   ← 口径=相似 ≥ 阈值的标签对数（hits），与 ①「完全相同」分家
[结论]  一句话因果：「本文 5 个辅助标签里 3 个与版块完全相同 → ①精确匹配(≥2)命中，得分 0.70」
        无 match-detail 时如实写「该步命中数值需实时拉取」
[判定过程] 标题「判定过程（命中即停）」
        ① 精确匹配            ✓ 命中
           「事件和版块有几个辅助标签完全相同？」  交集 3 个（完全相同）≥ 2
           这一步怎么算的 ▸  （就地 KaTeX）
        ② 算余弦相似度（参照）   相似达标 5/5 · R 1.00 · Smax 0.86
        （未命中的前置步：✗ 差多少，如「R=0.40 ≤ 0.50」）
        ③④⑤ 未走到（①已命中）        ← 合一排，灰化
        （composite_hit 标签：⓪ 组合命中行给组合链 + 命中，合并排为「①②③④⑤ 未走到（⓪已命中即停）」，无 ② 参照行）
[证据]  辅助标签 ×5 · 版块收编 5/5（相似 ≥0.72，非完全相同）
        逐行 ✓/✗ · 标签 → 最相似版块标签 · 相似度
[{类别}描述] 标签 description 原文（spec req ① 要求，排证据之后）
[本文标签] 本文其他 tag chips（构成标签高亮）
[参数]  ▸ 当前匹配参数（沿用旧版 12 项明细，折叠）
```

排序按「结论 → 判定过程 → 证据 → 其余」，旧版是「证据 → 流程」；理由是用户要的第一问是「凭什么判定」，不是「有哪些对」。

## 受影响状态

| 状态 | 表现 |
| --- | --- |
| loading | 骨架不变；判定过程与收编表等数据到达后一起出现（不在半途渲染「需实时拉取」占位再跳变） |
| empty | 该标签无辅助标签（`auxRows` 为空）：收编区给「该标签无辅助标签」，判定过程仍按规则给阈值；本文无其他标签 → 「本文未打其他标签。」 |
| error | `match-detail` 不可得：`missingParts` 如实标注；判定过程保留规则名 + 问法 + 阈值（来自全局匹配配置），命中步结果写「需实时拉取」；**公式入口不渲染**（不拿当前规则伪造历史明细） |
| success | 判定过程每步给真实结果；命中步高亮 + 「命中」徽标；「这一步怎么算的」展开就地 KaTeX；重算值与冻结 score 不一致时在判定过程脚注给一次 `⚠` 提示 |
| 降级 / 方向不符 | 头区标记不变（`已降级 ↓` / `方向校验未通过 ⊘`）；降级信息仍写在命中步结果里，不新开提示块 |

窄屏（<768px）底部全宽档：判定过程行改为两行折行（编号+规则名一行，问法与结果一行），不做横向滚动。

## 复用组件与布局模式

- 复用：`KaTeXRender`（公式）、`Icon`（@iconify/vue）、现有 `AppDialog`（匹配流程弹窗，`size="md"`）、现有 popover 锚定/层级工具（`Z_INDEX` + `nestedOverlayZ` + `useIsNarrowViewport`）。
- 布局模式：popover 是浮层，不套 `AppPageShell`；其宿主 `BoardArchiveView` 的 workspace 布局不变。无新增尺寸档 / 自由宽度。
- 样式：沿用 `archiveMatchPopover.css` 的 token 变量与规则色（`matchReasonColor`），不新增硬编码色值。

## 验收映射

- 组件测试（真实路径）：`front/app/features/tags/components/console/ArchiveMatchPopover.test.ts`
  - 判定过程：命中步高亮 + 「命中」徽标；未命中的前置步给差距数字；命中步之后合并一排「未走到（第 N 步命中）」。
  - 两个口径分家：收编标题含「相似 ≥0.72」，① 行含「完全相同」。
  - 指标行：`相似达标 x/N · R · Smax` 与头区得分同屏；结论行含规则名 + 得分。
  - 公式就地展开：默认收起，点开后 KaTeX 在命中步行内，不渲染到 popover 外。
  - 缺数据：`match-detail` 不可得时判定过程给规则 + 阈值、命中步写「需实时拉取」、不渲染公式。
- 组件测试（同源文案）：`front/app/features/tags/components/console/BoardArchiveView.test.ts` —— 匹配流程弹窗文案与 popover 共用常量（同一规则名 / 问法 / 编号）。
