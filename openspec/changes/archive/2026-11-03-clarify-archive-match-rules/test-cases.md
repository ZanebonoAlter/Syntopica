## 2. 变体走查

**输入**

- 空串 / 纯空白：不适用——本 change 无文本输入框（划除留痕）。
- 纯分隔符 / 单 token / 大小写 / 特殊字符：标签名由后端返回，前端不做分词或大小写处理；特殊字符（含 emoji、超长标签名）走「超长文本」变体，见 可用性。
- 超长：标签名 / 版块辅助标签名超长 → 头区靠 flex-wrap 换行兜底（不裁切），入板阶段行内 `.amp-stage-label` 有 `text-overflow: ellipsis`（既有实现，本次不动）；无独立组件断言，实页人工抽查长名版块（review R-3① 留痕）。

**前置**

- 空集：标签无辅助标签 → 收编区「该标签无辅助标签」，判定过程仍给规则 + 阈值（组件用例）。
- 单元素：只有 1 个辅助标签 → `max(N, s)` 取 `s=3`，R 显示 1/3=0.33 而非 1.00（纯函数用例）。
- 重复：辅助标签 id 重复（脏数据）→ 以 `direct_hit_auxiliaries` 去重，判定过程 ① 行数字不与收编行冲突（纯函数用例）。
- 越界引用：`direct_hit_auxiliaries` 含不在 `auxLabels` 里的 id → 收编表不新增行（auxRows 按 auxLabels 映射，越界 id 天然不进收编行），① 行交集数字照实（口径=后端字段去重计数）；无独立组件断言，行为由映射结构保证（review R-3③ 留痕）。
- 部分满足：① 交集不足、③ 命中率不足、④ 三条件只满足两个 → 判定过程逐步给 ✗ 与差距，命中步在 ⑤（组件用例）。

**命中类型**

- composite_hit：组合标签命中 → 判定过程 ⓪ 行给组合链 +「命中」，合并排为「①②③④⑤ 未走到（⓪已命中即停）」，无 ② 参照行（组合交集即命中，免相似度计算）（组件用例）。
- direct_hit / hit_rate：见 M1-M2 / M5；max_sim 降级：见 M9 与效果核对。

**时间窗口**

- 边界两端 / 空窗口 / 跨窗口 / 归一化：本 change 不涉及日期范围（归档日期筛选逻辑不改），划除留痕。

**幂等**

- 重复执行：同一 chip 连点两次 → 第二次以新 `pop` key 重建，`requestSeq` 保护旧响应不覆盖（既有「竞态保护」用例保留）。
- 部分失败重试：`match-detail` 失败后关闭再开 → 重新请求，成功则判定过程给真实数值（组件用例）。
- 并发：不声称线程安全，划除留痕。

**可用性（UI 必检前五）**

- 误输入反馈：无输入，划除。
- 空态：见 前置·空集。
- 错误态：见 M6。
- 加载态：加载中显示骨架，判定过程不出半成品占位再跳变（组件用例：loading 时无判定过程节点）。
- 超长文本：见 输入·超长。
- 重复提交：公式展开为纯本地状态，重复点击幂等（组件用例）。

## 3. 效果核对

- **效果**：判定过程让用户不跳弹窗即可读懂「第几步命中、差在哪」。
- **核对方法**：静态托管实页（`http://localhost:5100/tags` → 版块 → 归档）抽 3 个不同 `match_reason` 的标签（direct_hit / hit_rate / max_sim 降级），逐个打开 popover 目视核对，并记录到 `ui-verification/report.md`。
- **量化**：3/3 标签的判定过程首行即给出规则名 + 本次数值；popover 内无「完整流程见…」措辞残留（`grep -c "完整流程" ArchiveMatchPopover.vue` = 0）。
- **结论**：pass——组件/纯函数三文件 56+3=59 用例全绿；实页四类 match_reason（direct_hit / hit_rate / max_sim 降级 / composite_hit）判定过程首行均给出规则名 + 本次数值，证据见 `ui-verification/report.md`。
