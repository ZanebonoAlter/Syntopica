# UI 设计契约 · unify-lane-workbench

> 主要模式为 **canvas**（全屏泳道工作台 = 画布工作面）→ 原型 SHALL 用 `ui-prototype/states/` 三态图 + `ui-prototype/interaction-table.md`，SHALL NOT 用可点 HTML 模拟。
> 审批流：major 初始 `pending`；用户在对话中明确确认后才改 `approved`。改变信息架构、主流程或布局模式的修订 MUST 重置 `pending`（颜色微调 / 文案修正记录差异即可，不重审）。
> **审批记录**：原型于 2026-11-16 经用户在对话中明确批准（三栏形态 + 两场景三态 + 已记录的图例文案修正），`ui-approval` 置 `approved`。
>
> **本版修订（2026-11-16，用户答复）**：用户拍板**保留三栏**（左 380px / 中央画布 / 右 300px）——**三栏适用于编辑泳道工作面**；新建泳道工作面沿用既有三栏（左候选 / 中央画布 / 右检视）与既有保存出口（「起名并创建」），本 change 不重排其栏位、不改其保存协议（见 D-2 与「明确不做」）。三态图保持「两场景三态」（01=新增泳道空态，02/03=编辑泳道编辑中/已确认），用户确认够评审。图例文案由「大小=接近度」改为「候选大小=接近度」（消除「成员尺寸也编码接近度」的歧义，属文案修正，不重审）。

## User Journey

**入口**

| 场景 | 入口路径 | 触发元素 |
| --- | --- | --- |
| 编辑既有泳道 | `/tags/:boardId` 矩阵页 → 行头「⋯」→「编辑泳道」 | 行头菜单项（宽屏可用；窄屏禁用并说明原因） |
| 新建泳道 | 版块雷达 / 泳道管理 → 「新建泳道」 | 主按钮（宽屏可用；窄屏禁用） |
| 返回 | 工作面左上「← 返回」 | 按钮；写操作已即时生效，返回不丢改动 |

**主任务**：判断这条泳道「应该包含哪些事件」——把候选加进来、把错的移出去。
**次任务**：在时间维度上核对这条泳道的演化密度（顶部时间视窗曲线）；重设这条泳道的定义面（首义范围）；改泳道显示名。
**出口**：全屏工作台，无「保存」按钮——加入 / 移出 / 设首义 / 改名均即时生效；「← 返回」即离开。

**用户故事**
- U1：我在矩阵看到一条泳道，某天有 3 条线索但其中 2 条其实是另一条线 → 进编辑泳道 → 在时间轴上找到那 2 个节点 → 点它 → 卡片上「移出本泳道」→ 移出，计数当场变。
- U2：这条泳道少了一条本该属于它的线索 → 点画布上一个候选节点 → 相关节点自动高亮 → 卡片上「＋加入本泳道」→ 加入。
- U3：这条泳道的定义面偏了 → 左栏「首义范围」勾 3 个节点 → 「用选中的 3 个节点定首义」→ 徽标从「自动」变「人工 · 3」。
- U4：我想看这条泳道最近一个月哪几天最忙 → 顶部时间视窗把刷选区拖到 11 月上旬 → 画布时间轴随之收窄。

## Information Architecture

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 顶部工具条（通栏）：← 返回 │ 泳道名(inline-edit) │ 时间视窗（档位/起止日/曲线/平移缩放）│
├──────────────┬────────────────────────────────────┬───────────────────────────┤
│ 左栏 380px   │ 中央画布（自适应）                  │ 右栏 300px                │
│ （已选侧）    │                                    │ （待选侧）                │
│              │                                    │                           │
│ 本泳道成员    │ 时间轴 + 节点 + 首义虚线            │ 关联推荐 · N              │
│ 窗口 N · 全部 M│ + 「更早」折叠带                    │  · 标题                  │
│ 更早成员 · K  │ 节点卡（跟随选中节点）              │  · 接近度（估算）         │
│ 已移出（本次）│ 图例（成员/候选大小/只读/已移出/首义/相关）│  · 「＋ 加入」           │
│ 首义范围      │ 缩放读数 + 重置                     │                           │
└──────────────┴────────────────────────────────────┴───────────────────────────┘
```

**信息层级（三栏的语义分工）**：左栏 = **已选侧**（本泳道成员 / 更早成员 / 本次已移出 / 首义范围）；右栏 = **待选侧**（关联推荐）；中央 = **空间判断**（哪天、哪个、和谁相关）。两侧**内容不重复**：左栏不再承载关联推荐。

**为什么是三栏**：`lane-manual-correction-loop` 的 v3 曾以「左右重复」为由删掉右栏，但工具链演进后左栏已承担 4 块（成员 / 更早 / 已移出 / 首义范围），再把关联推荐也塞进去会让左栏 5 块纵向堆叠、每块都要独立内滚。右栏专放「待选」与左栏「已选」形成对照，也与新建泳道的「左已选、右待选」结构对齐。

**首义范围的位置**：保留在左栏底部（sticky 提交按钮），与画布「更早折叠带」「首义虚线」共享同一套空间语义；不弹窗。

## Interaction Contract

### 主操作

| # | 操作 | 交互形态 | 反馈 | 破坏性 |
| --- | --- | --- | --- | --- |
| M1 | 聚焦节点 | 点画布节点（或键盘 Enter） | 节点卡钉在该点旁并跟随；相关节点高亮、其余弱化；左栏勾选态与右栏列表同步 | 否 |
| M2 | 加入本泳道 | 节点卡「＋ 加入本泳道」/ 右栏推荐行「＋ 加入」 | 节点从候选态翻为成员态（实心 + 勾，尺寸固定）；左栏计数 +1；右栏列表 −1；toast | 否 |
| M3 | 移出本泳道 | 节点卡「⊘ 移出本泳道」（实心错误色 + ⊘） | 节点翻为已移出态（划除线）；计数 −1；左栏「已移出（本次）」出现该项可加回；toast | **是**（视觉与「× 取消聚焦」明确区分） |
| M4 | 设首义范围 | 左栏「首义范围」勾选 → 底部 sticky「用选中的 N 个节点定首义」 | 来源徽标由「自动」变「人工 · N」；画布首义虚线同步 | 是（覆盖既有首义 → 画布内就地确认条，不叠弹窗） |
| M5 | 改时间窗 | 顶部时间视窗（档位 / 起止日 / 曲线刷选 / 平移缩放） | 画布时间轴、左栏成员分层、右栏推荐按新范围重算 | 否 |

### 次操作

| # | 操作 | 交互形态 | 反馈 |
| --- | --- | --- | --- |
| S1 | 改泳道名 | 标题就地编辑（inline-edit） | Enter 保存 / Esc 取消 / 失焦取消；toast「泳道名已更新」 |
| S2 | 画布缩放 | 滚轮 / 右下角「＋ / － / 重置」 | 缩放读数；只影响呈现 |
| S3 | 画布平移 | 拖空白（位移超阈值才算拖） | 不误伤点选 |
| S4 | 取消聚焦 | 点空白 / Esc / 卡上「× 取消聚焦」 | 恢复默认呈现（相关高亮解除） |
| S5 | 加回已移出 | 左栏「已移出（本次）」→「加回来」 | 节点回到成员态；计数 +1 |

### 危险操作

- **M3 移出**：不可逆写操作，但**可逆**（左栏「已移出（本次）」可加回）→ **不弹二次确认**（判据 P3 只对「不可逆且需确认」成立），改用视觉区分（实心错误色 + ⊘ + 划除线）+ 可加回 + toast。
- **M4 覆盖首义**：已有人工首义时 → 画布内就地确认条（复用既有确认条），不叠弹窗。

### 反馈方式

界面文字只承担三类：动作标签 / 状态结论 / 必要确认与反馈。口径解释（如「接近度 = 快照 vs 估算」）**不进界面**，靠徽标与 tooltip 承担；派生值机制（质心加权公式）不出现。

### 曲线口径（顶部时间视窗）

| 场景 | 曲线口径 | 数据来源 |
| --- | --- | --- |
| 编辑泳道 | 本泳道逐日线索数 | `GET /api/semantic-boards/:id/lane-dynamics?days=365` → 该泳道逐日 `clue_count`（后端零改动） |
| 新增泳道 | 全部可选的线索数（**不含当前 active 泳道**） | `GET /api/semantic-boards/:id/persistent-topics/compose-candidates` → 各 section 的日期与归属（排除 active 后逐日聚合）；**若响应不含每条 section 的线索数，需后端补该字段** |

曲线单位 = 「线索数（非文章数）」。档位：编辑泳道 7/14/30/365；新增泳道 7/14/30/365/自选起止。**取数端点上限已按用户 2026-11-16 裁决放宽到 365 天**（原 90），新增泳道可见一年真实可选池；曲线路径走不带向量的轻量取数（实测 365 天 ≈200 KB，而非含向量的 ≈10 MB）。

## State Matrix

| 状态 | 画布 | 左栏（已选） | 右栏（待选） | 时间视窗 |
| --- | --- | --- | --- | --- |
| loading | 骨架（节点位留白，不画假节点） | 列表骨架 | 列表骨架 | 曲线区「池曲线加载中…」 |
| empty | 该时间窗内无可展示节点 → 空态说明（不含教学语） | 「这条泳道还没有成员。」 | 「选入节点后出现推荐」 | 档位 / 日期仍可改 |
| error | 行内错误 + 「重试」 | 保持旧数据不清空 | 保持旧数据 | 池未取到 → 提示 + 单独「重试历史池」入口；A 侧保持可读 |
| success | 节点 + 节点卡 + 图例 + 缩放读数 | 4 块（成员 / 更早 / 已移出 / 首义） | 推荐行 + 「＋ 加入」 | 曲线 + 日期轴 + 刻度 + 反馈行 |
| unknown | 该日线索数不可数 → 显示 `?`，不造 0 | 同上 | 接近度不可算 → 不显示该行数字 | 历史日 `?` 不补 0 |

错误恢复：画布加载失败给「重试」（不清空左栏）；写操作失败 → 节点形状回滚 + 行内错误、卡片保留、不整页刷新。

## Layout Contract

- **布局模式**：`workspace`（全屏工作台，非 dialog）。泳道工作面以全屏 overlay 承载，**不使用 dialog 尺寸档**（内容是画布工作面，不是独立小任务）。
- **栏宽**：左栏固定 380px；中央画布自适应（容器真实像素 1:1）；**右栏固定 300px**；顶部工具条通栏。
- **目标视口**：桌面 1440×900 与 1920×1080（两档都要出视觉检查证据）。窄屏 <768px **不画残缺工作台**，只提示「需要宽屏或横屏」并禁用入口。
- **溢出策略**：左栏与右栏各自纵向独立滚动，块内长清单再各自内滚；两块的操作按钮（「用选中的 N 个节点定首义」）sticky 在块内底部，SHALL NOT 被裁到视口外。
- **时间视窗**：顶部工具条内、「← 返回 / 泳道名」同一行右侧；曲线高度固定（与矩阵页同档），档位按钮组 + 日期表单 + 平移缩放按钮排布与矩阵页一致。

## Prototype

- 三态图（canvas 模式，SHALL NOT 用可点 HTML）：`ui-prototype/states/01-empty.svg`（空态 / 新增泳道）、`02-editing.svg`（编辑中：聚焦 + 节点卡写操作 + 相关高亮 + 时间视窗展开）、`03-confirmed.svg`（已确认：写操作生效后计数与态变化）。
- 操作表：`ui-prototype/interaction-table.md`（15 行，八列：操作 / 触发 / 前置 / 结果 / 反馈 / 落点 / 破坏性确认 / 失败）。
- **形态与分流依据**：泳道工作面 = 全屏画布工作台，主要交互模式 `canvas`（操作依赖多个对象的空间关系与相对位置）→ 按 `standard/frontend/interaction.md`「画布类交互的原型形态」用三张静态状态图 + 操作表，不做可点 HTML。
- **三张图同尺寸同结构**（1440×900 = 866px 应用视口 + 34px 状态图说明条），只有状态差异 → 可做逐态对账。
- **纯静态**：不连真实 API、不引外部资源（无外链字体 / 图片 / CDN）。颜色引用 `front/app/assets/css/main.css` 的 semantic token（同名同值），深浅色用 `@media (prefers-color-scheme: dark)` 切 dark 版同名值。
- **底部 34px 说明条是评审外壳**（与 `lane-manual-correction-loop` 原型同原则），不属于产品界面，承担「状态名 + 样例数据声明 + 曲线口径」标注。
- 基线：头部三条 marker 即契约（本文件第 1–3 行），此处不重复声明。
- **与三态图的已知差异（已记录，不重审）**：① 图例文案由「大小=接近度」改为「候选大小=接近度」（避免误读成员尺寸编码接近度，源文件已改）；② `ObservationRangeControls` 由「原样复用」改为「最小向后兼容配置扩展」（泳道侧需 7/14/30/90 与可编排上限；矩阵页默认行为与布局零变化）。

## Acceptance

1. **agent-browser 主交互链路断言**：进矩阵 → 行头「⋯」→ 编辑泳道 → 聚焦节点 → 节点卡「＋加入本泳道」→ 左栏计数 +1、右栏列表 −1 → 「⊘移出本泳道」→ 计数 −1 且落「已移出（本次）」→「加回来」→ 改时间窗档位 → 三栏按新范围重算。至少一条端到端落点（不可只做组件测试）。
2. **三栏存在性断言**：左栏 380px、中央画布、右栏 300px 三者均可见；左栏与右栏内容不重复（左栏 SHALL NOT 出现关联推荐分组）。
3. **视觉检查**：1440×900 与 1920×1080 两档截图（编辑中 + 空态），与三态图逐态对账。
4. **与批准原型的差异说明**：任何偏离（新增/删除栏位、改动交互顺序、改文案语义）逐条记录；重大差异需重新审批。
5. 建账位置：`ui-verification/report.md`（格式契约见 `openspec/specs/ui-verification-trace-gate`）。
