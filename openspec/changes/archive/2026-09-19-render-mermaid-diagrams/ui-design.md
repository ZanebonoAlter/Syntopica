# UI 设计契约：mermaid 图渲染

> proposal 声明 ui-impact: major（正文内容元素新增「图」形态，呈现样式需用户看原型拍板）。
> 本 change 不新增页面/面板/导航，变化全部发生在既有阅读列 markdown 流内。

## 1. User Journey

- **主任务（零操作）**：用户在阅读页选中文章 → 阅读 AI 整理稿 / 正文 → 遇到 LLM 产出的 mermaid 图，直接看到图（而非源代码）。无任何新交互步骤。
- **次入口同享**：QA 面板追问回答、因果分析报告、版块富化面板、候选编辑弹窗中 LLM 产出含 mermaid 块时，同规则渲染（共享渲染器，行为一致）。

## 2. Information Architecture

- 无新导航、无新区块、无信息层级变化。
- 图是 **markdown 流内的块级内容元素**（与段落/表格/代码块同级），出现在 AI 整理稿小节或正文内原位置，不漂移、不悬浮。
- 阅读信息架构（kicker → 元信息 → 标题 → 标签 → 导语 → AI 整理稿 → 正文）完全不动。

## 3. Interaction Contract

- **无新增主/次/危险操作**；图本体不可点击（本期不做点击放大，控制范围）。
- 唯一动态行为：**主题切换时已渲染图按新主题重绘**（容器样式若选定恒定深底方案则豁免重绘，见 §4/§7）。
- 渲染反馈方式：**原位替换**——源码块占位，SVG 就绪后同位置替换，不做骨架屏、不做布局跳动。

## 4. State Matrix

| 状态 | 呈现 | 恢复路径 |
| --- | --- | --- |
| 无 mermaid 块 | 零行为，零额外加载 | — |
| 加载中（mermaid chunk 按需下载） | 保留源码块原样展示（用户无感知） | 加载完成自动替换 |
| 成功 | 源码块原位替换为 SVG 图 | — |
| 图语法无效（LLM 常见） | 保留源码块 + 下方细字错误提示（warning 色，一行） | 重新打开文章自动重试；源码始终可读 |
| chunk 加载失败（如异常离线） | 同上降级：源码块 + 提示 | 同上 |
| 主题切换（editorial↔dark） | 已渲染图重绘为新主题配色（若选恒定深底容器则图不重绘、天然适配） | — |

## 5. Layout Contract

- **Layout mode：reader（既有阅读列，max-width 840px 居中，面板窄则取可用宽）**——本 change 不引入新模式。
- 图容器宽度 = 列宽 100%；SVG `max-width: 100%` 等比缩放；超宽图容器 `overflow-x: auto` 兜底（横向可滚，不破版式）。
- 图容器高度随图自适应，不设固定高。
- **去卡片化红线**：容器 MUST NOT 使用「边框 + 投影」卡片形态（reading-article-pane 既有需求）；分区手段限留白 / 细分隔线 / 内容自身底色。
- 目标视口：桌面 1440×900、1920×1080；窄屏（<768px）跟随阅读列既有自适应，无独立断点。
- 无 dialog。
- **容器样式为本次待决项**，三个候选（原型对比、用户拍板）：
  - **方案 A 裸图融合**：SVG 直接入文流（同图片待遇，居中），无边框无底色；
  - **方案 B 细分隔线轻容器**：上下 hairline 细线 + 小字图题/来源标注，去卡片化合规；
  - **方案 C 恒定深底容器**：沿用现有代码块深底（#1f2430），图固定 dark 主题渲染——视觉与代码块连续，主题切换无需重绘。

## 6. Component Reuse

- 复用 `.markdown-body` 排版基准（`.markdown-body` 为 tags 三面板共享宿主，**基础排版不动**，仅纯增量新增 `.mermaid-block` 系列规则）。
- 复用 `data-theme`（editorial/dark）全部颜色令牌与现有 pre 深底样式。
- 无新增基础组件；新逻辑单元为 `useMermaidRender` composable（纯逻辑，非 UI 组件，详见 design.md）。
- 阅读页挂接点复用 `ArticleContentPreviewPanel` 既有 `v-html` 宿主，不另立组件树。

## 7. Prototype

- `ui-prototype/index.html`：静态单页（可丢弃，不连 API、不改产品代码）。
- 内容：阅读列语境还原（暖米渐变底 + 衬线标题 + AI 整理稿小节）+ **editorial/dark 主题切换按钮**；同一张 mermaid 流程图分别以方案 A/B/C 三种容器呈现并附取舍注记；另含**渲染失败降级示例**与**超宽图横向滚动示例**。
- 颜色全部使用真实主题令牌，观感与实现一致。
- 审批流：approval 初始 `pending`；用户在对话中看原型并明确选定容器方案后改 `approved`；若后续改信息架构/布局模式（本期预期不会）须重置 `pending`；颜色微调/文案修正记录差异即可。
- **审批记录（2026-09-19）**：用户浏览器查看原型（editorial/dark 双主题截图）后明确批准；容器方案选定 **方案 B 细分隔线轻容器**（上下 hairline + 小字图题「图 N ·」），A/C 两方案否决。实现以方案 B 为准。

## 8. Acceptance

- opencli 主链路断言：打开含合法 mermaid 块的文章 → `.mermaid-block` 内出现 SVG 且源码 `<pre>` 消失；构造非法 mermaid 块 → 源码保留且出现错误提示行；切换主题 → 图重绘（或深底方案无需重绘）。
- 双视口视觉检查证据：1440×900 与 1920×1080 各一份（阅读列内图不破版、超宽图横向滚动可用）。
- 与批准原型差异说明：**实现与批准原型方案 B 一致**，仅两处实现级差异——① 图题由静态文案改为自动编号「图 N」+ 源码首个 `%%` 注释行作可选标题（原型无真实渲染器，文案系示意）；② 裸围栏（firecrawl 丢语言标记）识别为 apply 阶段新增检测面（原型未涵盖该输入形态，容器样式不变）。无信息架构/布局模式/主流程差异，不触发重审。
- 与批准原型差异说明：容器样式、错误提示样式逐项对照；重大偏离需重新审批。
- 回归边界：无 mermaid 块的文章与四面板既有渲染零变化（bundle 无 mermaid chunk 下载）。
