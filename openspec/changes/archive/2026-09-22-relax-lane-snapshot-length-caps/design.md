# Design: relax-lane-snapshot-length-caps

## 决策

纯参数放宽，无结构改动：

| 常量 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| `laneSnapshotMaxRunes` | 100 | 200 | LLM 实际短版输出常态 80–150 字，100 上限高频硬切 |
| `laneSnapshotDetailMaxRunes` | 500 | 1000 | 长版常超 500，硬切烂尾是用户可见的主要截断面 |
| `laneSnapshotMaxTokens` | 768 | 1536 | 768 预算下模型啰嗦即掐断 JSON → 误走降级（长版丢失+短版砍半）；1536 留足两版上限 + JSON 开销余量 |

## 不变量（保持不动）

- 机械截断保护本身保留（防模型失控的兜底，rune-safe）；只放宽数值。
- 长短两版单次调用、同一素材窗口、结算松耦合不阻塞日报主流程——全部原样。
- DB `text` 字段、前端全文展示——无感知，无需迁移。

## 风险

- 卡片变长：前端区块内自然滚动，1000 字上限极端情况仍在可读范围；实际 LLM 输出预计 600–800 字。
- token 成本：单泳道单日一次调用，max_tokens 只是预算上限，实际消耗随输出长度自然增长，增幅有限。
