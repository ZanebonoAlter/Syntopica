# Proposal: 新建泳道编排态画布——泳道行 + 拖拽选入 + 由浅入深的渐进披露

## Why

30 天窗口下，编排态画布（`LaneComposeCanvas.vue`）呈现为 180+ 个同尺寸空心圆点：其中约 3/4 是**未归属散料**，与候选链成员视觉无差别；唯一的身份标记（点旁编号）编码的是**全局序号**这个对用户无意义的值；"大小 / 深浅 = 接近程度"的编码在首屏（尚无质心）整体休眠。三者叠加 → 用户原话「画布中间全是原点，没有什么可以区分的信息」。

这不是第一次。2026-08 同一抱怨已出现在侧栏（`openspec/changes/archive/2026-08-01-inline-compose-lane/tasks.md:84`「信息密度高、与当前编排关联弱」），当时解法是"新增相似推荐区"；三个月后因「花里胡哨的东西加太多，没有重点」被整批删减（`lane-compose-topic-event-tags/ui-design.md:42`）。**钟摆的根因不是信息量，而是两件事：归属只能靠顺着 0.8px 虚线爬 27 列去读、首屏没有任何可读结构。**

## What Changes

五件事，按承重顺序排列：

1. **泳道行（画布纵向语法改造）** —— 候选话题从'飘在顶部的横条 + 长 tick 拖线'改为'**行**'：每条候选链占固定 y 区段，成员直接排在行区段内；**横条胶囊整个删除**（横向位置已由成员自身表达，条的长度是冗余信息），行分组靠 y 区段 + 行标签 + 1px 分隔线；整组拖动的把手改为**行标签**（hover 时整行成员同时提亮）；未归属散料沉到底部「地板带」。同日内 y 排序键由 `id`（无意义）改为**所属候选链**。这是承重件：y 轴第一次有了含义，归属不再需要爬线。
1b. **节点下常显截断标题** —— 候选链成员与本次泳道成员在点下常显 ≤5 字截断标题（列宽 <40px 时整档关闭、回到 hover 读全文；30 天窗口列宽 ≈23px 即属关闭档）。未归属散料**仍不常显标题**（母 spec 既有边界）。
1c. **同日多节点竖直堆叠** —— 同一天选入多条时按槽位竖直排列（每槽 24px：点 9px + 标题 10px），行高随当日条数增长，每个点各自带标题；不做折叠计数点。
2. **本次泳道行 + 拖拽选入/移出** —— 画布新增第 0 行「本次泳道」（accent）。拖单个点入行 = 逐条选入；拖候选链**行标签**入行 = **采纳整组**（手势粒度 = 数据粒度）；拖出行 = 移出。**本次泳道不绑定任何候选链 / 事件线**：成员可来自任意链与散料，链被取空则整行消失（左栏仍记 `n/n`），不出现"已采纳"摘要、不统计来源构成。**点击回归"只看"**（聚焦出节点卡，无副作用），节点卡上的 ＋/⊘ 按钮保留为键盘/无障碍通道。
3. **散料折叠（阈值承担显示门控）** —— `matchThreshold` 从"只改大小深浅"升级为**散料的显隐门控**，三档（仅高相关 / 标准 / 全部，默认标准=0.3）；**候选链成员、已选成员、只读参照永不隐藏**。折叠必须是"折叠"而非"不存在"：常驻「另有 N 条未展开」+ 一键展开（数值 + 动作，不写解释句）。
4. **检索态** —— 右栏「按标题找」输入非空时画布切检索态：候选链层降为背景纹理（不可点），**命中只可能来自「未归类」层**（不属于画布上任何候选链的节点；含未归属话题与挂着 candidate 话题但未成链的节点），命中点在地板层浮出为可点选入集；**不做批量选入**（逐条人工确认）。入口仍在右栏 tab，画布只做结果投影。
5. **由浅入深的三阶** —— 阶 0（无质心）只画结构；阶 1（首次选入）散料按距离浮现、大小深浅激活；阶 2（调范围 / 检索）命中集覆盖结构。视觉复杂度 = 用户进度的函数。

## Non-Goals

- **不做按话题/事件着色**（会与「深浅 = 接近程度」这条唯一语义竞争；`unify-lane-workbench/design.md:72` D7 已定）。
- **不加图例、不写教学文案、不做机制科普**（`standard/frontend/interaction.md:53-66` 明文禁止；上一轮用户也已砍过）。
- **不给候选链成员或已选成员做阈值门控**（否则等于把距离当准入门槛 → 违反"推荐不得当置信度"）。
- **不做同日折叠堆叠点**（如 `●3` 计数点）——同一天多条要能各自看到标题，宁可行变高。
- **不做 30 天窗口的常显标题**（列宽不足时整档关闭，不降级成 2 字碎片）。
- **不做批量选入**（检索态也逐条）。
- **不把本次泳道绑到任何一条候选链 / 事件线**（不出现"已采纳"摘要、不做来源构成统计）。
- **修正工作面（`lane-correction-surface`）本期不动**——`LaneCorrectionCanvas.vue` 为独立组件，两工作面语义对齐留作后续 change，避免一次改两处。
- **不做触屏拖拽**（母 spec 既有：375 窄屏回落为"新建泳道需要宽屏或横屏"）。
- **关键词检索下沉后端（含正文/摘要）单独立项**——本期检索态沿用现有纯前端标题过滤，后端能力到位后可无损接上。

## UI 方案（形态已定，视觉待原型批准）

- 画布纵向结构：`本次泳道`（accent，第 0 行）→ `候选链 N`（中性，各占区段）→ `地板`（散料，更小更淡、可折叠）。
- 拖拽：拖起时 ghost 放大、目标行高亮、松手吸附；拖拽期间禁滚轮缩放与 hover 出卡。
- 阈值：三档 + 常驻「另有 N 条未展开」。画布与右栏「可补充的事件」必须同批（母 spec 硬契约）。
- 检索态：命中集浮出 + 检索环（视觉需避开"已选=实心+✓"，不得被误读为已选）。

`ui-impact: major` → 需 `ui-design.md` 八节 + `ui-prototype/` 原型，**用户明确批准原型后才进实现**（详见后续 ui-design 制品）。

## Impact

- **前端**：`components/compose/LaneComposeCanvas.vue`（布局与交互重写）、`composables/laneComposeLogic.ts`（排序键 / 门控 / 命中集）、`composables/useLaneCompose.ts`（阈值档位、检索态状态、拖拽动作）、`components/compose/LaneComposeInspector.vue`（检索态联动，入口位置不变）、`components/console/BoardComposeOverlay.vue`（行容器、工具条文案）。
- **后端**：**无**。质心距离本就前端计算（`laneComposeLogic.centroidRecommendations`），候选链数据已具备。
- **spec**：`openspec/specs/workshop-lane-compose/spec.md` 的「编排态入口与全屏画布」「成员质心与关联推荐」「右栏职责与画布标题」三节需 delta。
- **既有决策**：`standard/frontend/interaction.md` Interaction Decisions D1（增删改入口 = `canvas`）**更贴合**（增删改现在真的发生在画布本体）；「查看与选入分离」**不需要推翻**——点击=查看，拖拽=显式选入，分离得比现状更彻底，只需在"显式选入动作"枚举里加入拖拽。
- **部署后影响**：(a) 编排态画布的形态与选入手势全部改变，老用户"点击选入"习惯失效，工具条需改写现有那句「推荐不自动选入；候选大小=接近度…」；(b) 无数据迁移、无旧数据降级问题；(c) 用户需手动操作：无。
