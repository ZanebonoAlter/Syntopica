# UI 设计契约 · console-rails-live-signals

> 主模式为 **page / inline-edit**（常驻两栏的就地选择与跳转，不弹层），因此原型用 `ui-prototype/index.html` 可点 HTML，不用 canvas 三态图。
> 审批流：major 初始 `pending`；用户在对话中明确确认后才改 `approved`。信息架构、主流程、布局模式变更后 MUST 重置 `pending`。
> **审批记录**：原型于 2026-11-19 经用户在对话中明确批准（左轨一行式条码、右轨「当日日报」两层、矩阵选中列淡底、两栏满高自适应），`ui-approval` 置 `approved`。
> **用户追加决策（2026-11-19）**：各泳道按**当日线索数降序**，且泳道行**显示**该线索数——取 `lane-dynamics` 当日 `clue_count`（与矩阵日格同源同值），MUST NOT 用含综合稿的日报分区线索数。
> **本版范围**：只改版块态势页（`/tags/:boardId`）左轨与右轨，以及矩阵选中列的淡底；顶栏、弹层、雷达页、窄屏形态一律不动。

## User Journey

**入口**：`/tags` 雷达 → 点任一版块行 → `/tags/:boardId`（矩阵/追踪）。面包屑可回雷达。

| 任务 | 频率 | 现在怎么完成 | 改版后 |
| --- | --- | --- | --- |
| 换版块 | 高 | 左轨找名字 → 点；数字 `409` 不知含义 | 左轨看「哪个版块这两天在动」→ 点；条码即逐日线索 |
| 知道这天发生了什么 | 高 | 读矩阵格（要找泳道 + 找日期列） | 右轨「当日日报」：3 条点评 + 各泳道一句 + 线索数（跟随矩阵选中日） |
| 回到某一天 | 中 | 拖观察范围 / 点列头 | 点矩阵列头或日格 → 右栏自动跟到那天 |
| 管追踪 | 中 | 右轨第三块，常被体检测评语挤出首屏 | 右轨第三块 |
| 查体检质量 | 低 | 右轨首块直接给评语 | 一行状态条 + 按需进详情 |

**用户故事**
- U1：我早上打开「中东地缘政治与美伊关系」，想确认昨天发生了什么 → 矩阵列头选中 11-18（整列淡底）→ 右栏「当日日报 · 11-18」给出 3 条点评 + 4 条泳道各一句 → 我不用读矩阵就知道这天讲了什么。
- U2：我想看「沙特与也门胡塞武装冲突」那天具体说了什么 → 右栏泳道行点它 → 定位到该泳道与该日。
- U3：我想切到另一个版块 → 左栏扫一列条码，找最近几天更亮的 → 点。
- U4：我要收编构成标签 → 右栏「构成候选」按需点进，位置比现在更靠下但入口不变。

**层级逻辑**：左轨 = 横向比较（哪个版块在动）；右轨自上而下 = 结论（体检一行）→ 这一天讲了什么（当日日报）→ 我的关注（追踪）→ 属性（候选 / 来源）。

**为什么左轨固定 14 天**：跨版块比较需要一个共同刻度。若跟随主舞台 7/30/365 档，切档后所有行同时变形，比较基准消失。

**为什么右轨不出现日期选择器**：日期只有一个来源——矩阵选中日。右栏写「当日日报 · 11-18」说明自己在跟哪天；用户想换日，去矩阵换（那里有列头、日格、编年三处入口）。两个日期入口必然打架。

**为什么右栏能显示条数**：右栏泳道行的「N 条」取的是 `lane-dynamics` 当日 `clue_count`——**与矩阵日格同源同值**，用户能在矩阵里对上号。真正会出事的是用「日报分区线索数」（含综合稿），那是另一套量纲；本 change 明确不用它。

## Interaction Contract

### 主操作

| # | 操作 | 形态 | 反馈 | 破坏性 |
| --- | --- | --- | --- | --- |

| M2 | 换选中日 | 点矩阵列头 / 日格（`inline-edit`，既有入口） | 选中列整列淡底；右栏「当日日报」跟随换日 | 否 |

| # | 操作 | 形态 | 反馈 |
| --- | --- | --- | --- |

### 危险操作

无。本 change 不引入写操作；追踪管理与构成收编仍在既有抽屉/详情内。

### 反馈方式

- 界面文字只承担三类：动作标签（刷新 / 管理 / 查看）/ 状态结论（11-18、3 篇来源）/ 必要确认。
- 口径解释不进界面：不写「线索数 = 非综合稿 thread 合计」，左轨也不写「每格 = 一天」。
- 禁止出现：教学语（「点击左侧版块切换」）、算法术语（`lane_heat` / `clue_days` / `highlights` / `story_count`）、已退役量纲（事件线 / 分区数）。

## Data Provenance

| 数据项 | source | 说明 |
| --- | --- | --- |
| 左轨条码格值 | `api GET /semantic-boards/overview` → `boards[].clue_days` | 非综合稿线索；未取到位置 = null（斜纹） |
| 左轨共同轴 | 同上 → 响应 `date`（全局锚点）+ `boards[].anchor_date` | 前端重对齐：`位置 = i - offset` |
| 左轨行整体强度 | `derived 0.42 + 0.58 × (行14天总量 / 最大行总量)` | 只压暗安静行，形状不变 |
| 左轨标签挂载数 | `api GET /semantic-boards` → `tag_count` | 仅进 `title` |
| 当日日报点评 | `api GET /daily-reports/:id` → `report.highlights[]` | `{title, reason, tag_ids, cluster_id?, article_count?, cluster_mode?}`；2–3 条 |
| 点评来源篇数 | 同上 → `highlights[].article_count` | 缺省则不显示「N 篇来源」，不补 0 |
| 泳道层名称 | 同上 → `report.sections[].persistent_topic.label` | 仅 `topic_status_at_report = active` |
| 泳道层代表线索 | 同上 → `sections[].threads[0].title`，无则 `sections[].cluster_label` | 日报自己的文字，不前端拼装 |
| 泳道层色点 | `derived 话题 id 稳定哈希` | 与雷达 `top_lanes` 同一色源 |
| 泳道层线索数 | `api GET /semantic-boards/:id/lane-dynamics` → `lanes[].timeline[].clue_count`（选中日） | 与矩阵日格同源同值；取不到显示 `—`，不补 0；休眠泳道（矩阵首屏折叠）会出现在右栏，其矩阵格需展开「休眠泳道 N」后可见 |
| 泳道层排序 | 同上（线索数降序） | 并列保持 `report.sections[]` 原序；线索数未知的排末位 |
| 所跟日期 | 壳层 `useConsoleSelection.selectedDate` | 唯一日期源；右轨无选择器 |
| 体检评分 | `api GET /semantic-boards/:id/health-checkup` → `latest.llm_score` | 徽章；`null` → 「待评分」 |
| 体检时间 | 同上 → `latest.checked_at` | `上次体检 MM-DD HH:mm` |
| 话题追踪 | `api GET /semantic-boards/:id/topic-watches` | `label` + `status` |
| 构成候选 | 同体检响应 → `uncaptured_candidates` | top 3 名称 + 清单数 |
| 来源构成 | `api GET /semantic-boards/:id/source-breakdown?window=7` | 总量 + 来源数 + top 3 占比 |

## 明确不做

- 不在右轨内联展示完整体检评语（保留一行状态条，评语进详情）。
- 不在左轨显示任何数字（当日线索数、标签数都不占位）。
- 不在左轨显示口径说明文字（「每格 = 一天」等）。
- 不做左轨排序切换控件（保持 `display_order`），不做折叠分组。
- 不让左轨 14 格跟随主舞台档位变化。
- 不在右轨提供任何日期选择器（不引入第二个日期来源）。
- 不在右轨显示**两套**条数口径（矩阵线索数与含综合稿的日报分区线索数不得并排；只显示与矩阵同源的那一套）。
- 不在右轨排除休眠泳道（它是有当日线索的真实追踪对象；矩阵侧本就折叠在「休眠泳道 N」里，不因此从右栏隐藏）。
- 不按日报分区线索数排序（排序键与显示值必须同一个，且与矩阵同口径）。
- 不在右轨列 candidate 分区（其他动态）。
- 不做「已读/未读」标记（全库无该状态，不造）。
- 不新增共享 skeleton 组件、不引入动画库。
- 不改矩阵数据、顶栏、弹层、雷达页、窄屏（<1200）形态。
- 不改任何接口、统计口径、写操作。

## Layout Contract

- **布局模式**：`workspace`（三区固定视口栅格，`layout.md` 已登记例外），沿用 `BoardConsoleBody.vue` 的 `17rem | 1fr | 21rem`。
- **栏宽**：左轨固定 17rem（272px）；右轨 21rem（336px），1440–1535 视口收 18rem；**本 change 不改栅格**。
- **两栏满高自适应**：左轨与右轨 SHALL 为**满高容器**（高度 = 视口高减顶栏），内容超出时各自纵向滚动（沿用 `.scroll-thin`）；SHALL NOT 让两栏内容悬在顶部、栏体自身高度随内容收缩。两条栏 SHALL 带极淡的底色（与主舞台拉开一层），使栏体读起来是「面」而不是「浮条」。
- **右轨纵向分布**：右轨 SHALL 为纵向 flex；「当日日报」块 SHALL 撑开剩余高度（`flex: 1 1 auto`，内部内容顶部对齐、块内不滚动），「版块体检 / 话题追踪 / 构成候选 / 来源构成」SHALL 固定尺寸并贴底。视口变高时空白落在「当日日报」块内（而不是栏底悬空），视口变矮时整栏滚动。
- **左轨行高**：一行式行高 SHALL 为弹性区间 **24px–40px**（栏高富余时按 `flex-grow` 均匀撑开，上限 40px）；行内名称与条码垂直居中；行间 SHALL 带一条极淡分隔线，使左轨读作目录；栏高不足时整栏滚动。
- **左轨内部宽度**：条码 14 × **5px** + 13 × 1px gap ≈ 83px；名称 `min-width: 0` + ellipsis 占剩余 **≈144px**（实测 13 行全部不截断：「中东地缘政治与美伊关系」11 字完整）。首版曾用 6px 致名称被截断，验收后收窄（见 `ui-verification/report.md`「验收后微调与复测」）。
- **目标视口**：桌面 1440×900、1920×1080（两档均出视觉检查证据）。
- **窄屏**：<1200 右轨收进顶栏「治理」入口（沿用现状）；<768 双轨全隐（沿用）。
- **dialog 尺寸档**：本 change 不新增弹层，不涉及。
