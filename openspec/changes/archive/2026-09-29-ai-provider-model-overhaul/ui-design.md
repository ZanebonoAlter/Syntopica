## User Journey

**入口**：设置页（SettingsWorkspace，sidebar 分组导航不动）→「AI 配置」组两个 section；观测在「运行状态」组的 ai-health tab。

**主任务**：
1. **管理供应商与模型**（「AI 模型」section 重构）：供应商卡片（logo/名称/base_url/健康点/模型数/**承载 N 能力常显徽章**）点击展开模型清单（启用勾选/类型/默认思考档/新·stale 标），卡片操作行刷新列表/测试连接/编辑/删除；新增走两段式弹窗（选预设 → 只输 API Key → 保存自动拉模型清单）。预设目录覆盖 **pi 内置 41 家**（中国区/国际直连/聚合与云平台分组，见 design D9）+ Ollama/llama.cpp + 自定义；logo 用 pi `provider-icons.svg` symbol（无图标 5 家首字母回退）。
2. **配能力路由与思考档**（「能力路由」section，2026-09-29 FB-3+FB-5 改**行式泳道**）：顶部**模型池横条**（按 vendor 分组的可拖模型卡），下方**每能力一行泳道**（行头 = 能力 badge+名称+N 计数+健康点）；模型卡片从池拖入行内，**行内自左向右 = 降级优先级**（序号常显，卡片间箭头即降级方向）；卡片带 logo+模型名+vendor 小字（告别 `model@vendor` 文字串）、思考档下拉（继承（模型默认）/七档）、×移除；hover 卡片提示「另承载 N 能力」。**降级状态内嵌行内（FB-5）**：失联/近期失败卡片红边+错误角标+「24h 失败 N」徽章，降级接管方标「接管 N」，发生迁移的箭头高亮标次数，行头健康点三态（绿正常/黄降级已兑底/红近期失败无兑底）；数据源 /api/ai/health + /api/ai/observability/degradations（既有端点）。
3. **查降级**（「运行状态」→ ai-health tab 新增观测块）：24h/7d 统计行 + 降级事件流（类型分「结构化降级 / 供应商失败降级」），事件「定位」→ 跳能力路由对应行并脉冲高亮（行内已有降级内嵌标注，观测块供全局统计与逐事件追溯）。

**次任务**：编辑供应商（弹窗预填）、删除供应商（级联确认列明影响）、刷新模型列表看 diff（新增标「新」、上游消失灰显 stale）。

```
SettingsWorkspace（不动：header + sidebar + content）
├─ AI 配置组
│  ├─ 「AI 模型」ai-providers ──→ 供应商与模型管理（AIProviderManagement 重构）
│  │    ├─ 供应商卡片列表（展开式：卡片头 + 模型清单面板）
│  │    │    卡片头：logo / 名称 / base_url / 健康点 / N 模型 / 承载 N 能力徽章
│  │    │    清单：启用 / 模型名(+新/stale) / 类型(llm|embedding) / 默认思考档
│  │    │    操作：刷新模型列表 / 测试连接 / 编辑 / 删除
│  │    └─ 「+ 新增供应商」→ 两段式弹窗
│  └─ 「能力路由」capability-routes ──→ 行式泳道（CapabilityBoard，FB-3+FB-5）
│       布局：顶部模型池横条（vendor 分组可拖卡 + 数据源小注）+ 下方能力泳道行（每 capability 一行：
│       行头 badge+名称+N 计数+健康点三态；行内卡片自左向右 = 优先级序，序号常显，卡片间降级箭头）；
│       embedding 行的拖入候选过滤为仅 embedding 模型；行内横向滚动内化，保存按钮置 section 头部；
│       行尾「＋拖到此处」虚线 slot 是行内追加落点
└─ 运行状态组 runtime-status（tab 不动）
     └─ ai-health tab：
         ├─ 现有健康快照 + 自动拉起开关（保留不动）
         └─ 新增「降级观测」块：时间窗切换(24h/7d) + 统计行(调用/降级/失败)
             + 事件流（时间/能力/顺位迁移/模型/类型/错误码/定位）
```

- **导航零变化**：sidebar「AI 配置」组仍是两项，深链（section=ai-providers / capability-routes / runtime-status&tab=ai-health）全部沿用，无重定向成本。
- **词汇回归直白**：供应商/模型/能力路由/思考档/覆盖/降级事件——概念 A 的报刊词（供稿/勘误/栏序/墨量/红笔）全部废弃。
- **扇出信息转正**：供应商卡片常显「承载 N 能力」徽章（单点依赖警示），能力路由 hover 提示补反向视角。

## Interaction Contract

**主操作（能力路由行式泳道，FB-3+FB-5）**：
| 操作 | 流程 | 反馈 |
|---|---|---|
| 添加绑定（拖拽） | 模型池卡片拖入能力行（落点卡左/右插入，或行尾虚线 slot 追加） | 卡片落位序号重排，入场过渡 |
| 添加绑定（点击，FB-7） | 点模型池卡片（带＋徽标）→ 弹能力选择菜单（类型不匹配项置灰、已在行中标出）→ 点能力项 | 卡片追加行尾序号重排；toast 确认；点外/ESC 关菜单 |
| 调优先级 | 行内卡片左右拖动换位（同行） | 序号即时重排；换位失败回弹 |
| 调思考档 | 卡片下拉：继承（模型默认 N）/关/微/低/中/高/超高/极 | 下拉值即时存；覆盖时卡片标「覆盖」小徽章 |
| 移除绑定 | 卡片 × | 卡片出列，序号重排；空行显示虚线引导（拖入模型） |
| 看扇出 | hover 卡片 | tooltip「qwythos 另承载 6 个能力」（同模型多行出现时可见）+ 近期错误信息 |
| 看降级态 | 直接看行内标注（无需跳转） | 失败卡红边+角标+「24h 失败 N」；接管卡「接管 N」徽章；降级箭头高亮标次数；行头健康点三态 |
| 保存 | section 头部「保存路由」（沿用现有） | saving 锁 + 成功/失败 toast；行序→priority 派生 |

**拖拽约束**：拖拽与点击双通道添加（点击是键盘/无障碍友好路径，拖拽用于精确落位）；换位仅限行内左右拖动或 ←/→；不支持跨行拖动（跨行=先移除再拖入）；embedding 行只接受 embedding 模型（拖入红框拒绝、菜单项置灰）；降级标注数据窗口与观测块一致（24h），行头健康点 = 行内最差状态归约（绿=无失败；黄=有失败且有接管；红=有失败无兑底）；池卡与泳道卡内控件（select/徽章）不溢出卡片边界（FB-7 卡宽 208px + flex 收缩）。

**次操作（供应商卡片）**：点击展开/收起模型清单；清单内勾选启用、类型下拉（仅本地服务可标 embedding）、默认思考档下拉（embedding 为 —）；刷新模型列表（loading 锁，diff 标「新」/stale）；测试连接三态；编辑（两段式弹窗预填）；删除（sm 确认弹窗，级联列明 N 模型 M 绑定）。「+ 新增供应商」唯一入口在 section 头部 actions 位（FB-6：底部不放重复按钮，空态文案引导到右上角）。

**次操作（供应商卡片）**：点击展开/收起模型清单；清单内勾选启用、类型下拉（仅本地服务可标 embedding）、默认思考档下拉（embedding 为 —）；刷新模型列表（loading 锁，diff 标「新」/stale）；测试连接三态；编辑（两段式弹窗预填）；删除（sm 确认弹窗，级联列明 N 模型 M 绑定）。

**新增供应商（AppDialog lg，两段式）**：①预设目录（**pi 内置 41 家分组**：中国区/国际直连/聚合与云平台 + 本地 Ollama/llama.cpp + 自定义；组内卡片=pi logo+厂商名，无图标 5 家首字母）→ ②预设只需输 API Key（base_url 可改；llama.cpp 另有启动命令字段，文案说明后端执行、跨主机留空）；自定义走全量表单；高级折叠（超时/思考方言/结构化输出覆盖）；测试连接三态；保存后自动拉模型清单并展开卡片。目录分组可折叠、组内可搜（41 家一眼扫不完）。

**观测块（ai-health tab）**：时间窗切换改统计行；事件流行含模型名与类型标（结构化降级 / 供应商失败）；「定位」→ 切到能力路由 section、滚动到对应能力行、行内对应卡片脉冲高亮一次（行内常驻降级标注见主操作表）。

**危险操作**：删除供应商（AppConfirmDialog sm=420，级联影响列明，确认按钮 danger 色）；移除绑定（轻操作不确认，可重加）。

## State Matrix

| 状态 | 供应商与模型 | 能力路由 | 降级观测块 |
|---|---|---|---|
| loading | 卡片骨架行 | 池与行骨架 | 统计行+流水骨架 |
| empty | 「还没有供应商」+ 新增引导（指向右上角入口） | 空行虚线引导（拖入模型卡片） | 「窗口内无记录」 |
| error | 列表加载失败内联条 + 重试 | 同左 | 同左 |
| success | 卡片+清单 | 池横条+能力行+卡片（含健康/降级标注） | 统计+事件流 |
| 健康数据 pending | — | 行头健康点置灰（数据未就绪），卡片不带降级标 | — |
| 刷新 loading/失败 | 按钮锁 / toast 保留旧清单 | — | — |
| 测试连接 | 弹窗内联三态 | — | — |
| 误输入 | 弹窗字段级校验 | 类型不匹配拖入拒绝（红框+回弹） | — |
| 超长文本 | 模型名/base_url ellipsis+title | 卡片模型名 ellipsis | 能力/错误码 ellipsis |
| 重复提交 | 保存按钮 loading 锁（沿用现有 saving） | 同左 | — |
| 错误恢复 | 失败可重试，无死胡同 | 换位失败回弹 | 保留上次结果 + 提示 |

## Layout Contract

- **layout mode：`workspace`**（SettingsWorkspace 既有：sidebar + content 滚动容器，本 change 不动框架）；content 区沿用现有 padding（24px 28px）。
- **目标视口**：桌面 1440×900 与 1920×1080（major 双视口验收）；窄屏走设置页既有降级（sidebar 抽屉 + 单栏），无新增断点。
- **弹窗**：新增/编辑供应商 `AppDialog size="lg"`（760px，92vw 上限）；删除确认 `AppConfirmDialog`（sm=420 档）。
- **溢出策略**：供应商卡片/模型卡/base_url ellipsis+title；能力行内卡片横向滚动内化（行内超出不换行不撑页）；页面级无横向溢出；观测事件流窄屏下隐藏次要列（模型名保留）；预设目录弹窗组内滚动（41 家 + 搜索框）；行头固定宽（~168px）窄屏优先保行头。
