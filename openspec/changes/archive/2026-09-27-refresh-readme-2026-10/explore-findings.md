
## README 设计哲学叙事红线（ssp-article 讨论定稿）

README「运转方式/设计取舍」叙事必须遵守的红线（源自 2026-09-20 会话 docs/research/ssp-article/article.md 定稿讨论，用户逐条拍板）：
1. 不许对立「纯向量匹配只给 0.83 分数、标签才可解释」——检索产品也能给上下文，用户原话「纯向量匹配就是检索那套，没有人直接看 0.83」；正确口径：标签+向量是「能维护的组织材料」，检索是「需要时找回」，两者不是替代关系。
2. 本地成本=电费/机器时间视角，不许拿云价格×调用次数算账（「拿某家云服务的价格乘以调用次数，算出来的不会是我的实际成本」）；核心因果叙事是「同一份内容不被反复加工——已有标签/向量/缓存能复用就复用」。
3. 不断言比别人效果好（「不能因为用了不同的处理流程，就断言自己的效果更好」）、不堆数据、不做未实测的「省几倍」结论。
4. Syntopica 也要 LLM 提取标签，没绕开理解文章；「多一层不是优点本身」，值不值取决于整理结果是否被后续阅读反复使用。
5. 用户偏好：图用「故事驱动」形态（2026-09-18 harness-lifecycle 顺序图同款要求）；浏览器操作/截图派 commandcode/z-ai/glm-5.3-flash thinking max。
