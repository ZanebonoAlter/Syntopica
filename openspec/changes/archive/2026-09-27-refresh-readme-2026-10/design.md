# Design — README 重组（方案 B：分层去重）

## Context

见 `proposal.md` §Why。现状 521 行，三层重复叙述（理念/旅程/功能全景各讲一遍），且与仓库实际功能漂移（端口、死链、数据增强域形态）。探索结论与差距清单已在会话中确认（方案 B + 四项用户决策：FinGenius 剔除、截图全量可换、研究数据源一句话 alpha、端口按 5100 修正）。

## Goals

- 521 → 约 320 行（±10%）；每个内容类型唯一归属，不再重复。
- 功能清单与 `docs/reference/architecture/map.md` 的业务域对齐，一次说全。
- 所有链接、端口、路径与仓库现状零漂移。

## Non-Goals

- 不改任何代码 / 接口 / 数据。
- 不动 `docs/reference/` 下活文档内容（只改 README 对它们的引用）。
- 不重写产品理念叙事本身（只压缩，不换调性——保留「产品门面」气质）。
