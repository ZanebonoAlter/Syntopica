## User Journey

继续使用现有 `/discovery` 入口与返回首页、主题切换，不新建独立目录服务。主任务是挑选并确认订阅合适来源；次任务是在候选源库维护、复用配置，以及查看问答留下的兴趣记录。

主故事：进入发现页 → 浏览推荐及来源理由 → 确认订阅（RSSHub 必要时填参验证）→ 显示已订阅。维护故事：候选源库 → 手动新增公开/自建 RSS → 保存到目录 → 明示未订阅 → 可在后续推荐或目录中主动订阅。导入同样不触发订阅。

本制品只设计原型，不修改产品代码、数据库或订阅；布局和主流程等待用户审批。

## Information Architecture

- 顶部保留发现页标题、返回与主题切换。
- contained 页面标题区说明“先收藏来源到候选库，再按需订阅”。三个同级标签页：
  1. **为你推荐**：列表之前常驻“你想看什么内容？”查询框与“找订阅源”按钮，不隐藏在兴趣记录或弹窗中；与“刷新推荐”明确分开。本次查询显示“关于 ×× 的结果”，可返回为你推荐；失败保留输入和原有结果，成功留下独立兴趣记录。版块筛选、刷新；推荐理由、候选来源、可用性与最后检查时间；当前推荐/历史切换。
  2. **候选源库**：搜索和来源/参与推荐状态筛选；新增、导入、导出；来源类型、介绍、验证状态、推荐启停与维护入口。是否已订阅和是否参与推荐是不同字段。
  3. **兴趣记录**：逐条问答兴趣、归属版块或未匹配、记录时间、当前参与状态；解释“近期记录用于补充推荐，影响会逐渐降低”，不把向量相似度伪装成兴趣百分比。
- 版块/近期阅读/问答徽标说明候选召回来源，不冒称每条都由某一路独占产生；同候选可有多个徽标。Ask 结果仍作为全局问答推荐展示，种子归属另列，两者不混淆。
- 历史区区分自动过期、暂时不看、长期排除与已订阅；自动过期不冒称“不感兴趣”。

## Interaction Contract

| 操作 | 流程与反馈 |
| --- | --- |
| 刷新/问答 | 执行中禁用重复提交；问答空白输入给就地提示。成功可返回零条；服务失败保留旧卡并标记未更新，提供重试，不把旧卡清空或发布粗筛兜底结果。 |
| 订阅 | 明确按钮“订阅”，原生 RSS 确认地址后提交；RSSHub 有必需参数时填参验证再创建。失败保留输入并可重试，成功反馈已订阅并禁用重复创建。 |
| RSSHub 参数 | 复用字典优先、目录 options 次之、无选项输入框的既有规则；始终显示官方文档入口。原生 RSS 不显示伪造的 RSSHub 文档链接。 |
| 暂时不看 | 卡片退出当前列表，反馈冷却中与实际到期时间；允许撤销。具体冷却默认值在 specs/design 确定，不把原型示例当最终配置。 |
| 不再推荐 | sm 确认说明“保留目录、不取消订阅”，确认后长期排除；历史列表可恢复推荐资格。 |
| 新增/编辑 | md 表单：名称、RSS URL、内容介绍、语言/地区、参与推荐。空值/URL 格式错误就地反馈；保存按钮明确“保存到候选库”，成功提示“尚未订阅”。重复地址显示已存在记录入口，不静默再建一条。 |
| 人工补充 | RSSHub 记录区分上游原始信息和人工补充；人工字段不被同步覆盖，技术路由参数不在普通说明表单中伪装可自由编辑。 |
| 参与推荐开关 | 仅控制推荐候选资格，不改变订阅；提交期间防连点，失败恢复原值。长期排除状态单列，不因目录开关误恢复。 |
| 导入 | lg 预览新增、重复、冲突、无效项；显式确认才写库，显示逐项结果与失败重试入口。私有地址需要明确确认访问范围，导入本身不发起探测或订阅。 |
| 导出 | md 预览范围；默认排除私有地址和凭据，明确敏感项排除数。仅导出目录配置，不含画像、阅读记录和订阅状态；真实文件格式与敏感识别边界在 specs/design 定义。 |
| 可用性 | 未检查不标坏，需参数不标失效；展示检查时间/重试入口，检查按实际配置端点。请求执行中禁用重复检查，暂时网络失败给可恢复反馈。 |

原型仅演示内存交互，刷新页面恢复 fixture；导入导出使用标明的模拟预览，不假称已上传、下载或订阅真实来源。

## State Matrix

| 区域 | loading | empty | error / 恢复 | success |
| --- | --- | --- | --- | --- |
| 推荐 | 首载骨架；刷新保留旧卡并忙碌提示 | 本轮没有合适来源，可换版块/问答/浏览目录 | 精排不可用显示旧结果未更新与重试 | 卡片含理由与召回来源，成功零条与失败明确区分 |
| 候选库 | 列表占位，工具栏防重复动作 | 未建库提示新增/导入；搜索无匹配可清筛选 | 列表读取失败重试，不展示虚构零计数 | 目录条目与订阅状态分列 |
| 编辑/订阅 | 保留输入、提交禁用 | 必填字段提示 | 字段或服务错误就地显示，重试不丢输入 | 保存到库与订阅成功用不同反馈 |
| 导入/导出 | 解析/生成中防重入 | 无有效条目不可确认 | 无效项逐条解释；解析失败可换文件 | 预览/确认/结果，明确未订阅和敏感项排除 |
| 兴趣记录 | 占位 | 还没有问答兴趣，给找源入口 | 获取失败可重试 | 独立记录及参与/衰减状态 |
| 历史/可用性 | 加载或检查中 | 没有历史记录 | 短暂失败不升级成永久损坏；可重试 | 明确过期、冷却、排除和检查时间 |

所有区域覆盖超长标题/URL换行、重复提交、键盘焦点与主题切换；状态以文字辅助颜色，不依赖颜色独自传意。

## Layout Contract

- 页面使用 `AppPageShell mode="contained"`，最大1120px居中；保留顶部导航。1440×900、1920×1080为必须验收视口，另以390×844检查窄屏退化。
- 页面没有常驻主从栏，不使用 split；推荐卡桌面双列，各列允许收缩且内容 `min-width:0`，窄屏单列。目录条目窄屏堆叠，工具栏换行，URL和标题可断行，不允许页面横向溢出。
- 弹窗统一 `AppDialog size="sm"`（420，长期排除确认）、`md`（560，新增/编辑、订阅/填参、导出）、`lg`（760，导入预览）；均受92vw约束，内部高度受视口限制并纵向滚动。
- 原型用等值CSS token及原生 dialog模拟；实现不得复制原型弹窗容器替代AppDialog。
- 视觉遵循 editorial/magazine：纸色背景、墨色标题、克制暖色强调与细分隔线；深色主题使用项目语义token，不另起蓝紫SaaS方向。

## Component Reuse

- 现有 `front/app/pages/discovery.vue` 入口与 `DiscoveryPanel` feature边界保留，页面容器收敛到AppPageShell。
- 复用 `AppDialog`、`AppButton`、`AppInput`、`AppToggle`、`AppSectionHeader`、现有主题切换与Iconify，不引入组件库。
- RSSHub 填参逻辑继续复用 `buildRouteParamSpecs` 及现有参数组件，避免第二套字典优先级。
- 拟新增业务组件：候选库列表/编辑表单、导入导出预览、兴趣记录列表和历史状态展示；最终文件拆分在技术设计中明确。

## Prototype

- 路径：`ui-prototype/index.html`，自包含静态页面，可直接浏览器打开；不连接API、不加载远端资源、不修改产品数据。
- fixture包括日本新闻推荐、原生RSS、RSSHub填参条目和私有源占位信息；展示时间与数量都是示例，不代表真实数据库。
- 页面标注“交互原型·示例数据”，提供成功/加载/空/错误状态演示；导入导出为模拟预览。
- 原型修订：按用户反馈补齐顶部手动查询框、独立查询结果、返回推荐及兴趣记录联动；固定结果不代表真实搜索质量。
- **审批状态：approved**。用户在查看补齐查询入口的原型后明确确认：“可以，先按这个原型来”。批准基线为当前 `ui-prototype/index.html`，包括三页签、顶部手动查询、独立查询结果与返回推荐流程；此批准不代表产品实现或验收已完成。后续变更信息架构、主流程或布局模式须重置 pending 并重新审批。

## Acceptance

以下为后续验收计划，不是已通过证据：

1. opencli主链路：新增手动RSS→候选库出现→订阅数不变→明确订阅→订阅数增加且重复提交不重复创建。
2. opencli主链路：RSSHub填参（字典/目录options/输入兜底）→验证失败保留值→重试成功→已订阅；原生RSS无RSSHub文档按钮。
3. opencli：导入预览→确认→逐项结果，订阅数不变；导出默认排除敏感项且不含个人画像；人工说明不被同步覆盖。
4. opencli：精排失败保留旧卡并提示未更新；零选择显示正常空态；暂时不看和长期排除分流，恢复排除不自动订阅；过期历史不标拒绝。
5. 组件测试：输入错误、空/加载/失败、超长文本、重复提交、状态文案与来源字段；兴趣条目独立展示，不显示编造百分比。
6. 视觉证据：实现后记录1440×900与1920×1080截图及布局检查，390×844窄屏检查；确认contained不超过1120px、dialog不超过92vw、无横向溢出。
7. 实现后补与批准原型差异说明；重大布局/流程差异先重审。原型自身的检查不替代产品端到端验收。
