# UI 设计契约 · replace-lane-lifeline-with-topic-events

> **主模式**：阅读台是 `page`（`layout.md` 固定词表），本 change 只在线索行内加一行 chip + 预览浮层，不新增页面 / 弹窗 / 抽屉 / 导航，不引入新的交互模式（阅读预览弹窗是既有能力）。
> **审批记录**：用户在 2026-11-17 对话中明确确认形态（「就是这个意思，通过了」），并要求「点击的时候直接 preview 相关文章」——已并入交互契约。
> **被否决的 v1**：原设计是「话题卡片底部新增『话题事件』区块，按天然日分组列出最近 7/30 天的所有事件标签卡片」。用户原话：「不要堆列表吧，这可读性太差了，界面是给人用的，不是给 agent 看的」。
> **匹配口径说明**：chip 的候选来自 **thread 向量相似**（同话题、窗口内、余弦 ≥ 0.75），不是事件标签——实测标签口径 top-3 与 thread 口径零重叠，见 `design.md` D3。因此 chip 上写的是**候选线索的标题**，不是标签名。

## User Journey

| 场景 | 入口路径 | 触发元素 |
| --- | --- | --- |
| 读日报时想知道「这条线之前讲过什么」 | `/tags/:boardId/:date` → 「关心的话题」→ 话题卡片展开 → 某条线索 | 线索行内的相关 chip |
| 快速判断「这条相关值不值得点开」 | 悬停 / Tab 聚焦 chip | 预览浮层 |
| 读那条相关线索的原文 | 点击 chip | 站内阅读预览弹窗（既有） |
| 看得更远 | chip 行右端 `7 天 / 30 天` 档位 | segmented 控件 |

**主任务**：读当期日报的线索，顺带判断哪些线索有来头、值不值得跟进。
**次任务**：跳到那条历史线索的原文。
**出口**：阅读预览弹窗关闭后回到日报原位；不再有全屏出口（侦探墙入口退役，完整生命线从版块态势页泳道进入）。

**用户故事**
- U1：我读到「企业级 Agent 落地需补齐托管与度量基建」，想知道之前有没有铺垫 → 线索下方 chip「企业级 Agent 平台与组织机制探索」→ 悬停看到「11.02 · 强相关 · 0.89」→ 点开读原文。
- U2：另一条线索下面什么都没有 → 说明这条是新的，不用点。
- U3：这条线索的 chip 我两周前看过 → 切 30 天，多出更早的两条。
- U4：读完文章回到日报，线索位置没变、滚动没跳。

## Information Architecture

chip 行嵌在线索行内，位于标题+摘要之后、文章列表与关键事件动作之前：

```
┌─ 话题卡片 ─────────────────────────────────────────────────┐
│ 具身智能与世界模型                      active · 命中 12 天 │
│ ── 当日线索 ──                                             │
│ ┌───────────────────────────┬───────────────────────────┐ │
│ │ 朱松纯发起通芯智能研发      │ 通芯智能由朱松纯发起、北通 │ │
│ │ AGI 专用推理芯片            │ 院孵化，成立半年内连续完   │ │
│ │ 通芯智能由朱松纯发起，北京…  │ 成融资。                  │ │
│ │                            │ 依据 1 篇文章              │ │
│ │ ┌ 相关 ─────────────────┐ │                           │ │
│ │ │[★具身智能专用芯片路线][  │ │    [AI 建议][确认为关键]  │ │
│ │ │ 北通院孵化项目][还有 2 条] [7天|30天]                 │ │
│ │ └───────────────────────┘ │                           │ │
│ └───────────────────────────┴───────────────────────────┘ │
│                                                            │
│   9 所高校联合发布持续在线智能体路线图      1 篇 ⌄          │
│   （这条没有相关线索 → 不渲染 chip 行，行高与现在一致）     │
└────────────────────────────────────────────────────────────┘
```

**层级语义**：线索 = 主体（已存在）；chip 行 = 附注层（最多 3 个，弱化样式，不抢标题）；★ = 人工主权信号（这条历史线索里的标签我确认过）；「还有 N 条」 = 折叠入口。

**为什么不做独立区块**：v1 已否决。独立区块必然按天分组 → 必然长成列表墙。chip 挂在线索行内，数量天然收敛到 2–3 个。

## Interaction Contract

### 主操作

| # | 操作 | 交互形态 | 反馈 | 破坏性 |
| --- | --- | --- | --- | --- |
| 1 | 展开话题卡片 | inline 展开（既有） | 卡片展开，chip 行随线索一起出现 | 否 |
| 2 | 悬停 / Tab 聚焦 chip | 预览浮层（`position: fixed` + 边界翻转） | 候选线索标题（可换行 2 行）、摘要（2 行截断）、来源文章标题、相关度档位与条+分数、日期 | 否 |
| 3 | **点击 chip** | 直接打开站内阅读预览弹窗 | 弹窗加载态 → 正文；弹窗内显示该推荐的相关度档位 + 分数 + 候选日期（一行 meta） | 否 |
| 4 | 关闭弹窗 | `Esc` / 点遮罩 / 点关闭 | 焦点回到该 chip，滚动位置不变 | 否 |
| 5 | 切 `7 天 / 30 天` | segmented 单选，位于**分区级工具条**（不放进线索行） | 已缓存档位即时切换；未缓存档位对 chip 行显示骨架；失败后再切档会强制重试 | 否 |
| 6 | 展开「还有 N 条」 | 就地补出剩余 chip | 全部 chip 可见，按钮消失 | 否 |

### 禁止项

- **不显示相似度小数在 chip 上**：chip 只写标题，分数在浮层里。裸数字摆在标题旁会被读成"重要度"。
- **无相关时不渲染任何东西**：不占位、不留最小高度、不写「暂无相关」——那是常态，不该每条线索都念一遍。
- **不做颜色编码**：chip 不用颜色区分高中低相似度；唯一强调色用于 ★。
- **不整行可点**：点击目标是 chip 本身，不是线索行。
- **chip 不用标签名**：候选是线索不是标签，写标签名会误导成「同一事件」。

### 键盘与焦点

Tab 顺序：分区标题行的 `7 天 / 30 天` 档位控件 → 线索标题按钮 → **chip 1..N** →「还有 N 条」→ 关键事件动作按钮（档位控件在分区级工具条，因此天然排在线索之前）。chip 是 `<button>`，`aria-describedby` 指向浮层内容。`Esc` 先关弹窗、再关浮层。浮层在 `focus` 时同样显示（不依赖 hover）。

## State Matrix

| 状态 | 触发 | chip 行表现 | 文案 | 下一步 |
| --- | --- | --- | --- | --- |
| loading | 首次请求 / 切到未缓存档位 | 2 个骨架 chip（高度固定，不引起跳动） | 无（骨架即说明） | 等待 |
| empty | 该线索无合格候选 | **整行不渲染**（任何档位都如此；档位在分区工具条，不随线索行消失） | 无 | 无 |
| error | 请求失败 | **整行不渲染**（推荐失败不阻断阅读） | 无 | 切一次档位即强制重试 |
| success | 有候选 | 最多 3 个 chip + 「还有 N 条」 | — | hover / 点击 |
| partial | 当期有线索缺向量被跳过 | 有候选的线索正常显示 | 不占视觉位 | 无 |
| 浮层显示 | 悬停 / focus | 固定定位浮层，边界翻转 | — | 点 chip / Esc |
| 弹窗加载 | 点击 chip | 弹窗打开、正文骨架 | 加载态可见 | 等待 |

**都不出现的**：全屏 loading、Toast 报错、「暂无相关事件」文案、把 error 画成 empty 的静默。

## Layout Contract

- **页面级**：阅读台三栏结构、宽度、断点在本 change **零改动**。
- **chip 行**：位于 `.drm-thread-row` 之后独立整宽一行（不塞进其两列 grid——那里由 `KeyEventMarkerActions` 的多根 fragment 自动摆放，塞第三块会错位）。`display:flex; flex-wrap:wrap; align-items:center; gap:.35rem`。
- **chip 尺寸**：`padding: 1px 6px`、`font: 11px/1.5` 等宽字体、`max-width: 18rem` + 单行 ellipsis，`title` 属性保留全文。
- **宽度档行为**（原型可切）：

| 正文列宽 | 期望 |
| --- | --- |
| 1100px | chip 单行最多 3 个，不换行 |
| 900px（原崩坏区间） | 3 个 chip 仍单行；超长标题 ellipsis；**无竖排断词** |
| 760px | chip 允许换到第二行，行高自然增长 |
| 390px | 每行 1–2 个 chip；档位控件换到独立一行；无横向滚动 |

- **浮层**：`position: fixed`、`width: min(24rem, 100vw − 2rem)`，左右不出视口、下方不够翻到上方；`z-index` 高于阅读台内容但低于阅读预览弹窗。
- **断点**：只用 `767.98px` 做间距/字号微调；≥768px 的现有布局与交互不因本 change 改变。
- **视觉下限**（V1–V6，原型自检）：chip 文字用 `--color-text-secondary`（editorial 6.3:1 / dark 6.5:1），不使用 `--color-text-muted` 承载产品文字；焦点环 ≥3:1；`prefers-reduced-motion` 关闭浮层过渡；radius 仅 2px；浮层才用阴影；无装饰性 emoji、无无含义彩色左条（★ chip 的 accent 描边承载「人工确认」真实状态）。

## Prototype

**路径**：`ui-prototype/index.html`（单文件，内联 CSS/JS）。**用法**：浏览器直接打开。

控制台（不属于产品 UI）：主题 editorial/dark、列宽 1100/900/760/390、chip 形态（标签 ↔ 图标，仅对比用）、「全部展开（评审用）」把浮层平铺便于截图评审。

**评审重点**
1. 悬停第一个 chip → 浮层里「标题 + 摘要 + 来源文章 + 相关度」是否够判断值不值得点。
2. **点击 chip → 直接进阅读预览弹窗**，弹窗里保留相关度与日期。
3. 第三条线索没有任何 chip——确认这种「什么都没加」的观感可接受。
4. 900 / 760 两档：chip 是否换行自然、有无竖排断词。
5. ★ chip 与普通 chip 的区分是否足够、又不刺眼。

> 原型内的 chip 文案取自已批准版本的示例（具身智能 / 通芯智能等），实现阶段的数据来源是 `thread-relations` 响应的候选线索标题。

**一次性制品**：实现完成后丢弃，不入库（`.gitignore` 已挡 `changes/**/ui-prototype/`）。

## Interaction Decisions

| # | 决策 | 依据 |
| --- | --- | --- |
| ID-1 | **全尺寸替换折线**，不做双轨 | 崩坏在 ≥768px 窄容器，断点修不了 |
| ID-2 | **不做「最近 N 天事件列表/时间轴」** | 用户否决 v1：「界面是给人用的，不是给 agent 看的」 |
| ID-3 | 形态 = **线索行内 chip + 悬停浮层 + 点击开文章** | 不占版面，信息按需出现 |
| ID-4 | chip **最多 3 个** + 「还有 N 条」，后端返回全量 | 不在后端静默截断 |
| ID-5 | **无相关时整行不渲染** | 常态不该被提示 |
| ID-6 | **候选来自 thread 向量**（同话题、余弦 ≥0.75），不用事件标签 | 标签口径 top-3 与 thread 口径零重叠（design D3 实测）；候选池 19% vs 94.7% |
| ID-7 | **chip 只写候选线索标题**，分数只在浮层 | 裸分数会被读成重要度；标签名会误导成「同一事件」 |
| ID-8 | 移除「在侦探墙打开完整生命线」入口 | 完整生命线从版块态势页泳道进入 |
| ID-9 | 缺向量的线索**不进推荐**但 `status=partial` 如实标注 | 可取舍，但不得伪装成 ready |

## Data Provenance

> 原型与实现的数据来源对照，字段 ⊆ `thread-related-events` 响应。

| 界面元素 | 字段 | 来源 | spec 锚 |
| --- | --- | --- | --- |
| chip 文字 | `threads[threadId][].title` | `daily_report_threads.title` | 候选集与相似度打分 |
| chip ★ | `confirmed` | `topic_key_event_markers`（`state='confirmed'`，按候选 thread 的 event 标签命中） | 来源文章与已确认标记 |
| 「还有 N 条」 | `threads[threadId].length` − 3 | 响应条目数 | 排序与截断 |
| 浮层·标题 | `title` | `daily_report_threads.title` | 候选集与相似度打分 |
| 浮层·摘要 | `summary` | `daily_report_threads.summary` | 同上 |
| 浮层·来源文章标题 | `source_article.title` | `articles.title`（经 `related_article_ids` 首篇） | 来源文章与已确认标记 |
| 浮层·相关度档位 | `level` | `score >= 0.85 ? strong : related` | 候选集与相似度打分 |
| 浮层·相关度分数 | `score` | 余弦相似度 `1 - (a <=> b)` | 同上 |
| 浮层·相关度条宽 | `score` 归一百分比 | 同上 | 同上 |
| 浮层·日期 | `period_date` | `board_daily_reports.period_date` | 同上 |
| 弹窗·文章 | `source_article.id` → 既有 `ArticlePreviewDialog` 加载 | `articles` | `daily-report-system` 既有条款 |
| 弹窗·相关度与日期 | `score` / `level` / `period_date`（由 chip 点击时携带） | 同上 | 本 change |
| 档位标签 | `days`（响应回显实际值） | 端点参数 | 线索相关事件读模型 |

**原型 fixture 说明**：`ui-prototype/index.html` 内联 6 条候选（含 ★、含 30 天档额外项），文案取自用户截图中的真实话题（具身智能 / 通芯智能 / 持续在线智能体路线图），不是 `fake` 占位。原型不接后端，相似度为示例值，实现阶段以真实余弦分数替换。

## 明确不做

- 不做「最近 N 天事件时间轴/列表」（v1，已否决）。
- 不用事件标签做匹配（v2，实测零重叠）。
- 不做 chip 的颜色编码或热度着色。
- 不做事件点击 → related-events 二级钻取。
- 不做跨线索语义归并/聚类。
- 不做 chip 行分页/虚拟滚动。
- 不在 chip 行新增筛选器、搜索框、排序开关。
- 不恢复折线、连线、节点图与侦探墙入口（即使宽屏也不恢复）。
- 不改阅读台三栏、刊头、今日重点、页边注任何区域。
- 不把「无相关」渲染成占位或空态文案。
