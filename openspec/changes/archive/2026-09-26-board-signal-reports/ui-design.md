> 批准记录：用户在大白话样例修订后明确回复「好的，接下来进入opsx-apply模式」，并指定实现/审查模型。批准范围为当前两阶段人工触发、最多40轮、无评审链及简化样例的原型；沿用editorial视觉。本次据此更新approved，不以旧流程批准代替新确认。实现验收仍须另跑。

## User Journey

1. 月/年+period选择后点击「发现信号」，启动轻量discovery job；预检400/同板块任务409，恢复已有任务而非新增。
2. 达标候选持久化并显示异常、值得查原因、研究问题、依据、发现时间。**发现结束即停止，等待人工，不取数、不自动生成报告。** 无信号不清旧列表、不弹消息。
3. 用户在某条点「深入分析」，只为该候选启动研究，最多40轮/40次执行，可提前结束；展示真实轮次、取数次数和计算次数。其他候选不会自动跟跑。
4. 完成即可阅读；失败在该候选显示job错误和手动重试。已有成功报告默认「阅读报告」，详情提供明确「重新研究」（新调用可能消耗预算）。
5. 无评审/judge/采纳/通过/驳回；报告生成后没有额外操作要求。

## Information Architecture

- 工作台：周期工具栏→候选信号列表→已生成报告列表；原新闻背景折叠区保留，旧产出/绑定管理入口退役。
- 候选字段与来源：signal/why_it_matters/research_question来自校验后detect；依据来自快照；发现时间来自批次；待研究/研究中/已有报告从live job与成功result派生。评分是内部阈值，不显示为可信度或收益预测。
- 列表按周期、批次可追溯；重新发现不覆盖旧候选，批次0候选不清旧记录。候选、报告持久化，job仍内存。
- 详情：thesis/facts/causal/implication四模型段+代码appendix；数据引用精确到观测，计算引用精确到公式账本，图表只来自这些数据。
- 历史研究标「事后回顾 · 本次数据版本」，目标期/发现时间/生成时间分别展示。迟点研究仍用原候选快照，界面提醒重新发现才能更新材料。

## Interaction Contract

| 操作 | 行为 |
| --- | --- |
| 发现信号 | POST signal-discoveries；202后只轮询发现job，绝不串发research请求 |
| 候选展开 | 看原因/问题/新闻依据，不触发LLM |
| 深入分析 | POST signals/:id/research；仅当前候选；其他候选等待，board任务共享互斥 |
| 重复点击 | 运行中409恢复原job；完成后200已有报告，无额外费用 |
| 重新研究 | 显式regenerate=true才启动新研究、追加报告版本；不覆盖原报告 |
| 研究进度 | 显示决策n/40、取数x、计算y；最多40次执行，可提前结束，不要求跑满 |
| 预算用尽 | 以已有证据成文，正文显示影响结论的缺口，不标成“已验证所有问题” |
| 原值/计算引用 | hover或点击看来源，点击先展开附录再定位；计算可见公式/输入/精度 |
| 图表 | 有相关序列1～3图，否则0图；派生图标代码计算，null断点、不混单位 |
| 返回候选/报告列表 | 保留周期；无需任何评审操作 |

## State Matrix

| 状态 | 展示与恢复 |
| --- | --- |
| 首次无候选 | 安静空态与发现按钮 |
| discovery prepare/detect | job区loading；不提前显示“报告生成中” |
| discovered | 候选待研究，界面停止轮询已完成job，不自动取数 |
| no_signal | 不新增候选/报告，不清已有列表；内部批次保留 |
| discovery failed | 发现错误，与空态区分，允许手动重试 |
| research | 只有所选候选研究中，显示真实计数，无review phase |
| succeeded | 阅读报告，成功记录持久化 |
| research failed | 候选保留，显示阶段错误/重试；无failed result |
| job404（后端重启） | 停止轮询，提示状态不可恢复可重试，重新查询候选/成功报告；不永久卡研究中 |
| list/detail error | 复用错误态，不伪装无数据 |

## Layout Contract

- 保留editorial暖纸、印刷红、衬线标题、hairline，无卡片堆；候选以行展示原因/问题与明确按钮。
- 产品工作台使用现有workspace；报告使用AppPageShell reader≤760px，局部.signal-report样式，不改markdown基础。
- 不新增弹窗。窄屏操作换行，引用可触摸，附录局部横滚不得撑宽整页。
- 双主题；1440×900、1920×1080与375px验收。原型维持同视觉，不另起美术方向。

## Component Reuse

复用page shell、job loading/error和新闻背景组件。新增SignalCandidateList、SignalReportList、SignalReportView及轻量SVG/引用渲染；**不复用review组件**。新API归数据增强模块，旧API类型不改。

## Prototype

- `ui-prototype/index.html`：可点击的合成演示；发现后停在候选，点击深入分析再切换进度/完成，报告无review。演示不联网、不调用LLM、不代表40轮实测。
- `ui-prototype/flow.html`：两段流程图，人工点击是显式边界；取数/计算预算和失败旁路另列，不挤成几十个节点。
- `sample-report.md`：完整内容样例及全量合成观测/计算账本；与原型同一组数值。没有炼厂开工率/利润/历史命中率等当前工具不支持的指标。

## Acceptance

1. 点击发现后停在候选，任何工具/成文调用为0；不点击研究就不产生报告。刷新/重启候选仍在。
2. 三条候选只选一条，只有对应研究job；重复点击不会产生重复付费任务，重新研究须显式操作。
3. 合法第17轮不被截断；第41次禁止；计数真实且区分计算/取数。提前完成能正常读报告。
4. 无评审按钮、badge、phase或等待审批；报告合格即阅读。
5. 引用点击展开并定位唯一观测/计算；样例差值−1 MMbbl、变化−0.2381%、净进口2700→2800 Mb/d一致。
6. 真实样本能够讲清替代解释、未取得数据与条件判断；正文不把字段齐全当事实已证明。
7. 双视口与375px：候选长标题/问题、loading/error、无图、重启404均可操作，无整页横溢。视觉验收与机械交互断言分别留证据。
8. 旧产出/绑定入口不在DOM，新闻背景筛选/编辑保留；旧API记录仍可读。
