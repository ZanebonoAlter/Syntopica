# Design

## D1 族怎么切，才不是又一种「按感觉分」

判据三条，同时满足才算一个族：

| 判据 | 说明 |
| --- | --- |
| **一个族能对应到 1–2 个 spec** | 族是阅读单元，spec 是契约单元，允许 1:N，但不允许「找不到对应 spec」的族（那说明它是个杂项筐） |
| **族内共用一套数据结构或流程** | 标签族的共同点是 `Label` + `MergeEmbedding`；泳道族的共同点是 `topic` × `day` 矩阵 |
| **问「X 现在什么规矩」时只在族内找** | 标签匹配的问法只会命中「一、标签体系」与「二、版块匹配」，不会散到体检或治理 |

按这三条，17 块归 6 族，其中标签族合并了 5 块（原本散在 5 个 change 名下）。

**反例（为什么不按 change 分组）**：按 change 分组看起来"历史清晰"，但读者要的是「现在什么规矩」，而 change 只是「什么时候变的」——把变更时间当成组织维度，等于让读者先知道历史才知道现状。

## D2 当前规则与决策记录的分界线

不是「有没有日期」，而是**这句话换一种做法会不会错**：

| 内容 | 归哪层 | 判据 |
| --- | --- | --- |
| 「辅助标签按 L1/L2/L3 三级去重」 | 当前规则 | 现在必须这么做，违反就错 |
| 「L2 命中曾改成重算 MergeEmbedding，导致合并黑洞」 | 决策记录 | 这是**为什么不能那样做**的理由，不是操作指令 |
| 「泳道动态取代已退役的话题态势版图」 | 决策记录（放族首一行提示） | 「已退役」是历史，但「现在用泳道动态」是现状 |
| 「watch 观察池已退役，**不得再生成** decision=watch 建议」 | **当前规则** | 「不得再生成」是现行禁令；「为什么退役」才是历史 |
| 「慢 I/O MUST 在事务外完成」 | **当前规则** | 换一种做法就错 |
| 「历史实现在单事务内调 embedding API，是 idle in transaction 4–40s 的元凶」 | 决策记录 | 这是原因，不是操作指令 |
| 「max_sim ≥ 0.8 且 hits ≥ min(2,N) 且 hit_rate ≥ 0.3」 | 当前规则 | 阈值是当下契约 |
| 「旧规则词回填把分类名『新闻』与 HTML 属性子串误命成『Coding』」 | 决策记录 | 踩坑案例 |

**混合块的拆法**：先按句子扫一遍，把带「曾 / 旧 / 退役 / 原因 / 导致 / 坑 / 教训」的句子标出来，这些进决策记录；剩下的进当前规则。拆完回头读一遍当前规则，如果能独立读懂（不需要上文解释「为什么」），就拆对了。

## D3 为什么红线节一个字不动

`## 业务约束与不变量` 是 **48 行装 39 条红线**，占全文 7.5%——这是全文档密度最高、最干净的部分。

两个原因不能动：

1. **机制依赖**：`constraint-injection` 扩展按**节名硬编码**抓这个节里的顶层加粗句（`scripts/harness/constraint-digest.sh` 同源），改节名或改条目格式会让注入失效
2. **它本来就没病**：扁平的编号列表，没有 change 名，没有历史混入

所以重排的范围明确是「链路设计节」，红线节与变更溯源表原样保留。

## D4 搬迁怎么保证不丢内容

448 行手工重组，最容易出的事是「搬着搬着少了一段」。四道防线：

| 防线 | 做法 | 失败会怎样 |
| --- | --- | --- |
| 备份 | 搬前 `cp` 到 `/tmp` | 可回退 |
| 正文行对账 | 原文每个非空行（块标题除外）在新文存在 | 丢失/重复立刻显形。**不用总行数**：重排本身新增结构行（6 族标题 + 12 层标题 + 族说明），总行数必然涨 |
| 术语对账 | 抽 20 个高频术语（`MergeEmbedding`、`composite_hit`、`max_sim`、`suggestion_hash`…）grep 计数前后一致 | 关键内容被改写或删 |
| 人读 | 逐族读一遍，问「不查别的族能不能看懂」 | 层次错位、上下文断裂 |

**为什么不上自动化**：这是「把散落的段落重新归类」，判据是语义而非格式，脚本分不出来。自动化的价值在对账（第 2、3 道），不在搬迁。

## 核心逻辑（伪代码）

### 关键数据结构

```
Block = {
  title: string        // 原 ### 标题（带 change 名）
  startLine, endLine: int
  kind: "rule" | "decision" | "mixed"
  family: FAMILY       // 归入哪一族（D1 三判据）
}
FAMILY = 标签体系 | 版块匹配 | 升级建议 | 泳道与工作面 | 版块体检 | 版块治理
Section = { family: FAMILY, rules: [text], decisions: [text] }
```

### 主流程

```
restructure(doc):
    backup(doc)                                  # 防线 1
    blocks = parseSections(doc, "## 链路设计")    # 17 块 + 行号
    for b in blocks:
        b.kind  = classify(b)                    # D2：带「曾/旧/退役/导致/坑」的句子 → decision
        b.family = assignFamily(b)               # D1：三判据
    sections = groupBy(blocks, family)           # 6 族

    newBody = ""
    for fam in FAMILY_ORDER:
        newBody += "### {序}. {fam}\n\n"
        newBody += "#### 当前规则\n" + merge(sections[fam].rules) + "\n"
        newBody += "#### 决策记录\n" + list(sections[fam].decisions) + "\n"

    # 红线节与变更溯源节从原文原样截取，不经过任何加工
    newDoc = header + newBody + verbatim(doc, "## 业务约束与不变量") + verbatim(doc, "## 变更溯源")

    assert nonBlankLines(newDoc) == nonBlankLines(doc)          # 防线 2
    assert termsPreserved(doc, newDoc, TERMS)                    # 防线 3
    write(newDoc)
```

### 失败与边界分支

- **块跨族**（一个块讲了两族的事）：按「主要解决什么问题」拆成两段，各归各族。**不允许**为了省事整块塞进一个族——那正是现在的病
- **块内既有现状又有历史**（如 `升级建议生命周期` 90 行）：先拆句再归层，不整块归一层
- **族内没有决策记录**：写一行 `（暂无）`，不要留空节——空节让人误以为漏了
- **搬迁后正文行缺失**：不继续，先定位。**判据是「正文行零丢失」不是「总行数相等」**——后者在重排里必然不成立（结构行是新增的）；缺失行必须全部可归因为标题层级改写
- **术语计数不一致**：逐个人工核对，因为有的术语在改写时会从「重算 MergeEmbedding」变成「不重算 MergeEmbedding」——语义没丢但字符串变了
- **红线节被无意改动**：`git diff` 里出现 `## 业务约束与不变量` 之外的红线句变化 → 回滚重做
