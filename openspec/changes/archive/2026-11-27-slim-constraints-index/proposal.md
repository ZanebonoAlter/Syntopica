## 起因

用户说这个索引是「隐藏的污染源」。

它 6032 字节，**每个会话都塞进 system prompt**。但里面真正属于「索引」的只有一张域表（约 900 字节），剩下 2600 字节是**操作手册**：`stage.md` 怎么写、`<!-- stage: xxx -->` 六个取值、`constraint-domains` 两处并集、`constraint-digest.sh` 取数三步。

## 为什么是「污染」而不只是「浪费」

两个问题叠在一起：

1. **重复**——这些手册内容 `AGENTS.md:146` 已经有一份，而且更完整。同一份协议在两个地方各写一遍，改一处忘一处就会不一致。
2. **给了虚假的完整感**——我读完索引会形成「哦这个域归那个文档管」的印象，然后**就不去 read 详细文档了**。而真正的红线在 flow 文档的「业务约束与不变量」节里，索引一个字都没提。

第 2 点是本质问题：**索引看起来覆盖了所有域，实际一条约束都没提供**。这跟 `add-ui-prototype-mechanics-gate` 那轮撤掉三项 CSS 检查是同一个病——形式的满足感代替了内容。

## 改成什么

**索引只留「去哪儿找」，手册搬到「要用的时候能看到的地方」。**

| 内容 | 现在在哪 | 改后在哪 | 为什么 |
| --- | --- | --- | --- |
| 域清单（哪个业务归哪个文档） | 索引 | **索引保留** | 这是索引的本职，删了模型不知道有哪些域 |
| `stage.md` / `<!-- stage: xxx -->` 格式 | 索引 | `开发执行规范.md` §13 | `explore`/`propose` 阶段的路由清单本来就指向这份文档，需要时拿得到 |
| `constraint-domains` 两处并集规则 | 索引 | 同上 | 同上 |
| `constraint-digest.sh` 取数三步 | 索引 | 同上（保留一行命令） | 命令本身在索引留一行，详细用法在 §13 |
| 执行规范 8 行表 | 索引 | **压缩成 5 行**（后端/前端/UI 三件套/共享/harness） | 原来的粒度是「一个文档一行」，压缩成「一类一行」，找得到就行 |

**关键前提**（改之前查过）：`explore` 与 `propose` 的必读清单里**本来就包含** `开发执行规范.md`（`.pi/constraint-injection.json`），所以搬过去不会变成「没人指路」。另需同步 `stage.ts` 的 `ROUTING_DOC_CATALOG` 节名，否则路由清单指向的节名对不上。

## 顺手修的

- 索引漏了一个业务域：`research-data-sources` 有「业务约束与不变量」节（`doc-impact-applies` 也标了），但没进域清单
- **已知局限**：该域约束节抽出的红线只有约 218 B，低于 `constraint-digest` 的 512 B 阈值，所以即使声明了它，注入的也是「指引行」而非红线本身——需要自己跑 `constraint-digest --brief --domains research-data-sources`。列进域表仍然必要（否则连名字都不知道）
- 4 个 main spec 缺 `<!-- domain: -->` marker（`check-standards` 告警）

## Impact

- `docs/reference/constraints-index.md`：6032 → 2718 字节（省 55%）
- `docs/reference/开发执行规范.md` §13：扩写为「change 头部声明与图表达」，收入三种 marker 的格式与规则
- `.pi/extensions/lib/stage.ts`：`ROUTING_DOC_CATALOG` 的节名同步
- 4 个 spec 补 domain marker

## 风险

**最大风险是「机制失传」**——把握手协议搬走，模型不知道该写 `stage.md` 和域声明，于是既不声明域也不拿红线，而这一切**不会报错**。

缓解有两层：
1. `AGENTS.md:146` 保留完整说明（主线程必读）
2. 索引头部写明「机制说明见 AGENTS.md + 开发执行规范 §13」，留了路标

**哪些失败可见、哪些不可见**（review R-3 纠正了我原来的笼统说法）：

| 失败方式 | 会被发现吗 | 靠什么 |
| --- | --- | --- |
| 声明了域，但没 `read` 对应 flow 文档 | **会** | 归档门禁 ⑥ `constraint-read-trace` 对账，红 |
| 声明了域，但该域红线不足 512 B 回退成指引行 | 部分 | 拿到的是「去哪取」而非红线本身，需要自己再跑 `constraint-digest` |
| **完全没声明域** | **不会** | 没有信号——注入里就是没有业务红线，看起来和别人一样 |
| **`stage.md` 缺失或 marker 写错** | **不会** | 静默当 legacy，收不到阶段路由清单 |

所以真正不可见的只有后两行。可接受的理由：现状一样（索引里写着 2600 字节的说明，也没人能保证被读），而新方案至少省了 3.3 KB 且消除了三处重复。

**后续可加的可见化信号**（本 change 不做）：`doc-impact-applies` 路径命中（说明编辑了某域代码）但该域未声明 → `spec-gate` warn 一行。
