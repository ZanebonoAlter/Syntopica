# 设计 — 原型阶段的 slop 过滤

## 1. 判断：能接，但要先做减法

`antislop` 是一套完整的交付前门禁（core 40 条 R 规则 + 4 个子 skill + Delivery Gate），设计前提是「从零做一个营销页/产品页」。本仓库的处境不同：原型是**可丢弃的、给一个人看的、用来定交互方向的**东西。所以直接套用会撞两堵墙：

| 撞墙点 | 说明 |
|---|---|
| Delivery Gate 要 20+ 项 PASS/FAIL 报告 | 本仓库 2026-11-15 刚用 R0–R2「禁止业务文案」+ 原型预算「≤12 短语/屏」把文字膨胀压下去。再引入一份长报告，等于把刚关上的门重新打开 |
| 部分规则是为「从零设计品牌」服务的 | `DESIGN.md`、ENERGY/RHYTHM/MOTION dials、R-30「不许模仿 Linear/Vercel」——本仓库是内部工具且已有 `theming.md` 的双主题 token，再引一套方向声明 = 双权威 |

反过来说，有三块是**真空白且高价值**的，因为它们在原型阶段被决定、到实现阶段改就贵。

## 2. 决策

### D1 — 吸收「占位 vs 伪造」三档判定

**决定**：界面/原型里的每一处数据，只允许两档，第三档禁止：

| 档 | 例子 | 判定 |
|---|---|---|
| 真实值 | 从 api / 表 取到的真数 | 允许，须在 provenance 表有行 |
| 诚实占位 | `Your Name`、`email@example.com`、`[REAL DATA]`、`—`、`示例` 明确标注 | 允许 |
| 伪造内容 | `John Doe`、`johndoe@example.com`、无对照期的 `+12% this week`、编造的动态流/ testimonials | **禁止** |

**理由**：伪造的"真实感"数据比视觉 slop 更危险——它让**评审误以为有数据支撑**，从而批准一个后端根本喂不出的设计。现有 `Data Provenance` 只堵住了「字段没有来源」，没堵「来源有了但数字是编的」。实例：`add-home` 原型 `fake` 命中 163 处。

**判据可核性**：`John Doe` / `johndoe@example.com` / `lorem ipsum` / 无来源的百分比 delta 是可 grep 的字符串，这条天然适合后续脚本化（D6 钩子）。

### D2 — 状态「存在」升级为「说原因 + 说下一步」

**决定**：四态齐全只是及格线。每种态 MUST 说清两件事：

| 态 | 必须说清 | 反例 |
|---|---|---|
| 空 | 为什么空 + 填满它的那一个动作 | 「No data available」+ 插图 |
| 加载 | 在加载什么 | 裸 spinner / 全页骨架 |
| 错误 | 什么失败 + 下一步 | 「出错了」 |
| 无权限 | 与「空」「首次」是**三种不同空态**，不得共用 | 三者共用一句「暂无数据」 |

**理由**：R0–R3 评审阶梯里，人判的是「这条操作路径顺不顺」。一个说不出下一步的空态，让人只能回一句「这里没东西」，浪费掉一轮宝贵的反馈。

### D3 — 视觉与动效的最低否决项（六条）

**决定**：以下六条为原型阶段 MUST，因为实现阶段改要重做配色/重排布局：

| # | 项 | 下限 |
|---|---|---|
| V1 | 文字对比度 | 正文 ≥4.5:1；大字（≥24px 或 ≥19px 粗体）≥3:1 |
| V2 | 非文字对比 | 图形/边框/焦点环 ≥3:1 |
| V3 | 焦点可见 | 键盘 Tab 到任何可交互元素，必须看得见 focus；原型 SHALL NOT 画成 `outline: none` |
| V4 | 键盘可达 | 主链路 Tab / Enter / Esc 可走通（画布类必须回答 Esc 做什么） |
| V5 | 动效 | MUST respect `prefers-reduced-motion`；禁无尽循环脉冲；>5s 动效须有暂停控制 |
| V6 | 剂量与装饰 | glass ≤2 处、glow ≤2 处、同页 radius ≤3 档、shadow 只用来标 elevation；禁装饰性 emoji、禁无含义彩色左条、禁无状态装饰点 |

**理由**：这六条的共同点是「原型里画错，实现就照抄」。V3/V4 尤其是画布类的高发区——画布原型常用「点节点选中」表达交互，键盘用户完全没有路径，但没人会在批准时想到。

**不采纳**「引入 antislop-ui 的全部 30+ 条 Tell」（渐变/图标库/字体/decorative 元素等）：那些主要针对营销页的辨识度，本仓库是数据工具，视觉基线由 `theming.md` 的 token 决定。只吸收「无障碍 + 动效 + 剂量」这三组可机械核对的。

### D4 — 不采用 em dash 禁令（review R-4 后从「限定」改为「删除」）

**决定**：**不写入** em dash 禁令。

**理由**：初版拟「仅限英文整句文案」，review 用实测推翻了立论前提——本仓库确有英文界面文案（`API Key`、`stale`、`Board Dynamics`），且产品代码里已存在 `direct_hit — 精确重叠` 这类「英文标识 + 单 `—`」写法，规则一生效就判定存量违规，而本 change 明示不改产品代码。这条规则对我们的收益接近零（无英文营销文案），误伤面确定存在。故删除，`—` 只保留「诚实占位」这一个语义。

### D5 — 不引入 Delivery Gate 报告，改用既有载体

**决定**：判据吸收，**报告形态不吸收**。验收证据落既有的 `ui-verification/report.md` 判定条目（`### A-<N> <场景>【pass|fail|未覆盖】`），不新增长报告。

**理由**：报告形态本身会变成新的文字膨胀源；而 `ui-verification/report.md` 已经是归档门禁的单一事实源（`ui-verification-trace.sh`），复用它是零成本。

### D6 — 后续脚本化钩子（本 change 不实现）

D1 的三档判定里，「伪造内容」档几乎全是可 grep 的字符串：

```
John Doe | johndoe@ | jane@example | lorem ipsum | +12% this week
```

D3 里 V3/V5 也可机械核（原型 CSS 是否 `outline: none`、是否缺 `prefers-reduced-motion` 查询）。这些留给 `add-ui-stage-accounting` 之后那条 `ui-contract-check.sh`，不在本 change 实现。

## 3. 文档预算：拆文件，不放宽预算

初版把三节塞进 `interaction.md`，实测 146 → **216 行**（+70，而非估算的 45），距自设上限 220 只剩 4 行——下一个 change 只要再加一节就必然触顶。

review R-11 指出这点后改为**拆文件**：三节移入新文件 `docs/reference/standard/frontend/prototype-content.md`（117 行），`interaction.md` 回到 **146 行**（预算 ≤180 保持不动）。理由：`interaction.md` 管「用什么形态交互」，新文件管「填进去的内容真不真」，本来就是两件事；硬塞在一起会让 180 行预算变成装饰。

拆分的连带改动：`standard/README.md` 表与目录树、`constraints-index.md` 执行规范表各加一行；`theming.md` 与 `loading-experience.md` 各补一条互指（消除 R-7 的双权威真空与 R-8 的两套加载口径）。

## 4. 风险

| 风险 | 处理 |
|---|---|
| 三张表让文档变长，反而没人读 | 每节以表为主、无论证段；总行数设硬上限 220，超了就必须拆文件而不是继续加 |
| 视觉六条被 agent 当成「再加一轮检查」 | 明确写：这六条是**原型画的时候就要满足**的，不是交付前补的清单 |
| `John Doe` 类判定误伤正当示例 | 诚实占位档已列出白名单写法（`Your Name` / `[REAL DATA]`），并提供「明确标注 `示例`」这一出口 |
| 与 `theming.md` 冲突（token 管颜色，V1 管对比度） | 分工写明：`theming.md` 管「颜色值从哪来」，V1/V2 管「这个组合够不够看清」；冲突时以 V1/V2 的对比度下限为准 |
