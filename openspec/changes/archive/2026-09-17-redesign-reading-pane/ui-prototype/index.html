从流水线到地铁网：为什么复杂 AI 都要拆成多 Agent（上）

LangGraph Multi-Agent LLM
之前学 LangChain 时做过不少线性工作流，一步接一步像流水线。但今天要拆解的现实是： 复杂的 Agent 产品基本都是多 Agent 架构——单 Agent 把什么都扛在身上，太累了。
AI 整理稿

本文用「中央厨房」类比讲解为什么复杂 AI 要拆成多 Agent，并以 LangGraph 为例演示网状协作编排：LangChain 是线性编排（传菜流水线），LangGraph 是网状编排（中央厨房分工协作）。

先看单 Agent 架构的痛点：所有 tool 的描述、每个功能的 prompt 都堆进 system prompt——这次只是问天气，它却背着另外 9 个技能的说明书在思考。

单 Agent 架构下，每个功能的 prompt 都要带上，token 消耗更高，无关信息干扰思考， 思考效率低且容易出错。
代价说明
token 浪费无关的 prompt 每次都算钱
干扰思考无关信息多了，LLM 容易"想歪"，准确率下降

把流水线改成地铁网

LangGraph 的解法是显式建模「状态机 + 网状协作」：chain = prompt | model | parser 变成一张可循环、可分支、可并行的工作流图。

状态与边

节点是函数，边是流转关系。条件边让工作流具备「问天气走 A 路、写代码走 B 路」的动态路由能力。

from langgraph.graph import StateGraph, END

graph = StateGraph(State)
graph.add_node("router", router_node)
graph.add_node("coder", coder_node)
graph.add_conditional_edges("router", pick_branch, {"code": "coder", "END": END})
