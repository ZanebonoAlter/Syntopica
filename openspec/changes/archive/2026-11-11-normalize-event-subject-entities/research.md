## 2. 研究小测（run `qwen-eval-20261109-181947`，2026-11-09 18:19）

- **预算已消耗完**：chat provider 尝试 **25/25**（上限 25）、embedding HTTP **6/12**、embedding 提交文本 **152/160**；审计 31 行（失败 0、fallback 0）。**本 change 不得复用该授权，不得自动扩额**；真实评测需**另一次有界授权**。
- **被测模型**：只测打标模型（capability `topic_tagging` → 本地 Qwen）；**未借 `digest_polish`**（用户 2026-11 决策：润色能力语义不符，借道会污染「被测模型」判定）。
- **受控条件（不可外推）**：固定 60 候选池；候选侧 **11 条描述经人工修订**；查询侧短说明是**研究者人工撰写的理想输入**（未验证第一轮能否自动产出）。因此本结果是**带理想输入的受控测试**，**不是生产准确率**。
- **结果**：已有实体题 **15/15** 语义正确；none 题 **4/5**（Q20「影子公开市场委员会」误选 `Federal Reserve`）；换序 5 题 **4 题答案一致**，Q09 从「唐纳德·特朗普」变成「特朗普」（两者在 gold 集合内都算语义正确 → **身份却变了**）。
- **三个必须随结论引用的限制**（`main-review-qwen-eval-20261109-181947.md`）：
  1. **不是生产准确率**：非自命中主组仅 6 题；候选仅 60 条；none 只表示「固定候选池内不存在」。
  2. **prompt 有强选倾向**：system 规则 4 是「只有在确认没有任何候选与该提及对应时才输出 none；如果存在可能对应的候选，就选最可能的那一个」——把**相关性当身份对应**；Q20 误选不能单独归因于模型能力，prompt 是混杂因素。本 change 的第二轮 prompt 必须把「相关 ≠ 同一实体」写死。
  3. **语义选对 ≠ 身份稳定**：Q09 两个不同 aux_id 均算语义正确 → 直接拿 aux_id 当主体 ID 仍会身份漂移。**这正是本 change 建独立实体层的直接依据。**
- **未触发的路径**：gold 全部进 Top-10 → 「不在 Top10 → 合法 none → 判重复新建」路径本轮**未实测**；不得以「重复新建 0」宣称该风险已消除。

## 3. 召回口径重算与作废声明（**必读**）

- **作废**：早期 pin 的 Recall@1=42% / @5=84% / @10=89% / @50=100% —— 分母错误（有向测量行当独立样本 + 3 个非同一实体对计入正例），**整体撤回**。
- **重算口径**：池 = 全量 22,268 行 active auxiliary（全池名次），自匹配占 rank1 并折算 RANK-1；剔除 4 个非同一实体对（Apple Silicon→苹果、央行分析职能→央行、中国人民银行上海市分行→总行、NVIDIA USD→英伟达）；2 个不可判对不计分母（字节↔字节跳动、沃尔沃↔沃尔沃汽车）；有效无向配对 = **11 对 / 18 个有向测量行**。
- **重算结果**：保守（取较差方向）hit@1 = 1/11 (9%)、@5 = 8/11 (73%)、@10 = 10/11 (91%)、@50 = 11/11；乐观 hit@1 = 2/11 (18%)、@5 = 11/11 (100%)；有向行口径 @1 = 3/18 (17%)、@5 = 15/18 (83%)。
- **口径边界**：这是**人工抽样 11 对的「样本对」Recall，不是全库 Recall@K**，抽样不完整 → **不可外推**。跨语言伙伴名次除苹果↔Apple 外**从未进过第 1**（被同语种兄弟标签压过）→ 必须有人（模型）判「是不是同一个」，而 embedding 只能当候选生成器。

## 5. 评审（R-1..R-11）带来的口径更正与追加事实

> 本节记录**评审核对后被撤回/修正的结论**，避免旧数字或旧公式再次流入制品。

### 5.1 撤回：预算公式里的「32 条一批」不存在

- **原写法**（本 change 第一版 design D9 / tasks T9.2）：embedding HTTP 次数 = `ceil(文本数 / 32)` × 重试系数。
- **核实事实**：`Router.Embed` 只在 operation 属 `embeddingCacheOperations` 白名单时才批量（`backend-go/internal/platform/airouter/router.go:446-451`，现仅 `tagmanagement.embedding` 与 `article_search_query`），否则**一条输入一次 HTTP**（`router.go:502`）；代码中**不存在 32 条一批的切分**。首次研 runner 的「chunk 32」是**那支一次性 runner 自己实现的批处理**，不是生产路由行为。
- **更正**：预算清单改为按**真实阶段**分列（文章抽取次数 / 二判次数与实际重试 / embedding **实际提交文本数** / 发送前 HTTP 计数），并注明路径不支持批量时按单条实际计、结构化输出降级链与客户端多次 HTTP 尝试一并计入。见 `design.md` D11、tasks T11.2。
- **同时撤回**：「提及数 × 2」这个固定倍数——重试是**实际发生**才计数，不按上限预估。

### 5.2 技术反驳：名字/别名精确命中 ≠ 身份（评审 R-5 建议部分不成立）

- **评审建议**：「`entity_mentions` 规范化提及文本精确/别名命中即入候选」若被读成「命中即身份硬复用」，不成立。
- **理由**：① 裸「苹果」既可能指公司也可能指水果，名字命中不消歧；② 辅助标签的 alias 是 L2 相似度自动写入的产物（`英伟达GPU` 挂在公司行 240 上，指 GPU 产品 ≠ 公司），拿 alias 做同体证据是把相似度产物升级成事实；③ 冷启动期没有已登记叫法可命中，名字命中**不覆盖**首次提及。
- **更正后的口径**：名称登记命中只提供**候选入口**（与两路向量候选 union、按 `entity_id` 去重），**判定仍归第二轮模型**（结合当次上下文）；同一叫法可对应多个实体 → 多个 ID 选项。见 `design.md` D4、delta spec「候选构造由两路向量与名称登记命中合并而成」。
- **评审的**事实缺口**（确实成立）**已按此修：候选构造此前**只有向量召回**一条通道、名称与证据层没有检索入口 → 已补名称登记命中入口；但**未**采纳「名字命中即身份」的硬复用。

### 5.3 追加事实：并发必须跨进程串行，且必须「取得后重读」

- **事实**：仅按（来源标签, 提及键）加锁**不覆盖**跨来源并发；两篇不同文章各自首次提到「特朗普」时，两进程各判 `none` 会各建一行。锁键改为「规范化提及名」也**防不住跨写法**（Trump / 特朗普键不同），且同名不同实体又不可强合。
- **更正后的机制**：单一**全局解析闸门**（PostgreSQL 会话级咨询锁，独占独立连接、不跨 HTTP 持事务）串行化「重读池 → 二次模型选择 → 原子登记/新建」全过程；**取得闸门后必须重读**已登记提及与候选池，闸外取得的旧 `none` 作废。见 `design.md` D6、delta spec「跨进程全局实体解析闸门」。
- **不承诺的部分**：不同写法未被召回或模型误选造成的重复**不可能靠锁消灭**，归为效果指标；跨进程并发只保「同一提及键只建一个」。

### 5.4 追加事实：关闭态必须连第一轮提示都不变

- **事实**：第一轮提取提示的任何改动都会改变模型对既有字段的产出（研究已证 prompt 改动会改判定，`main-review-qwen-eval-20261109-181947.md` 限制 2），而第一版把 `subject_desc` **无条件**加入线上提示，等于默认部署即改生产链路且无回退开关。
- **更正**：`subject_desc` **只在影子模式请求**；关闭态下第一轮提示与 schema **逐字不变**、零新增请求、零实体层写入。见 `design.md` D2/D10、delta spec「第一轮同次调用产出稳定短身份说明」与「影子模式与生产开关边界」。
