# design: 主体实体归一（全局稳定实体 ID）

> 决策 D1–D12 供 review 的「落点复核」逐条核对：每条给出 **落点**（本 change 任务 id / delta spec 的 Scenario 标题 / 无代码落点：<承接制品>，因为 <理由>）与 **取舍**。评审处置见 `review.md`；事实来源见 `research.md`；改动边界见 `proposal.md`。
> 交付按 4 个核心任务（`tasks.md` T1 实体存储与证据层 / T2 完整解析链 / T3 并发闸门与影子接入 / T4 效果评测入口）+ T5 review 组织。

## Context

- **主体身份今天是模型现编的字符串**：`EventFingerprint.SubjectKey` 由模型在同一次提取里现编（`backend-go/internal/tagmanagement/service/core/extractor_enhanced.go:310`、`:369`）；真库 910 条事件线 / 495 个 distinct key 里 `person:特朗普`(23) 压过 `person:trump`，`company:deepseek` 与 `product:deepseek` 指同一主体却分属两型。
- **辅助标签池是「提及池」不是实体登记表**：`semantic_labels`（`backend-go/internal/models/semantic_label.go:9`）active auxiliary 22,268 行里苹果散成 20+ 行；另有 190,396 行被 GC 置 disabled 且向量清空（`auxiliary_label_service.go:792`）。其身份判据是 0.95 余弦，而实测**同实体不同写法落在 0.79–0.94、跨实体共享 token 反而 0.9648**；且该表**没有 model/维度列**，存量向量来源不可证。
- **事件线身份判定是既有三层规则**：`ResolveSubjectKey`（`backend-go/internal/topicgraph/service/story_subject_normalize.go:97`）按 subject_key 精确 → embedding ≥0.92 → 字面归一；`subjectPreFilter`（`backend-go/internal/topicgraph/service/story_assign.go:230`）以 subject_key 一票否决先于一切层。主 spec `event-story`「主体归一化」原写「本期不建独立实体表」。
- **研究已证明「模型选得对」≠「身份稳」**：Qwen 小测（60 候选、人工 query 短说明、11 条候选描述经人工修订）里已有实体 15/15 语义正确、none 4/5（Q20 误选 Federal Reserve），但换序题 Q09 从「唐纳德·特朗普」换成「特朗普」——两个 aux 行都算语义正确，身份却变了；prompt 含强选偏置。
- **路由与审计的真实形态**：`Router.Chat` 按 provider 列表降级并 `errors.Join`（`router.go:410`）；`Router.Embed` 仅在 operation 属缓存白名单（`router.go:446-451`，现仅 2 个 operation）时才批量，否则**一条输入一次 HTTP**（`router.go:502`）——**代码中不存在「32 条一批」的切分**。

## Goals / Non-Goals

**Goals**：① 全局稳定、可登记、可核验的实体身份层（ID 不随 aux GC 消失、规范名不唯一、检索表示自带 model/维度）；② 判定拆成「检索召回 + 模型判同一实体」，技术失败与 `none` 彻底分开；③ 同一提及键的跨进程并发**串行且按最新池重判**（不承诺消灭模型误选造成的重复）；④ 真实可评测：真实第一轮 + 真实第二轮，指标按**固定总 N + 覆盖率**与配对可比口径计算；⑤ 本期**不动**事件线身份判定与其余存量数据。

**Non-Goals**：不重算存量 tag/story、不批量归属、不迁移不推断存量实体身份；不建人工种子表、不做词表/后缀/长度阈值洗身份、不用相似度自动认同体、不设待处理队列或人工确认闸门；不改 object/date 归因与热度；**不把实体 ID 接入事件线判定**；不做界面；不新增 capability 枚举值；不改生产路由整体架构（硬预算拦截只在评测入口注入）；本期**不实现生产启用**（`active` 显式拒绝）。

## Decisions

### D1 实体身份独立建表（3 表）；不放类型字段；辅助标签只做溯源映射

**决策**：`entity_registry`（身份）、`entity_mentions`（名称与证据）、`entity_aux_links`（辅助标签溯源）三张表；实体 ID 用独立主键 + 短不透明 `entity_key`（供模型复述）；规范名**无唯一约束**；辅助标签级联方向为「删溯源行、不删实体」；**实体类型不入身份层**；溯源只记录「本次标签的辅助标签列表中规范化文本与本次提及相等的那一行」。

**落点**：任务 T1；delta spec「实体身份与证据存储」。

**取舍**：不扩 `semantic_labels`（其行会被 GC 置 disabled 并清空向量，拿它当身份会让 190k 历史行的 GC 直接改写身份）；不用名称唯一兜底（不同实体可同名）。**删掉类型字段**：唯一现成来源是模型现编的 `subject_key` 前缀，而它已实测分型漂移，让模型猜类型只会把漂移固化进身份；类型若未来保留只作第一轮可选输出、绝不参与判定。`entity_aux_links` 的**唯一写入方**是上述判据、**唯一消费方**是评测报告的「材料溯源」列与运维排查——有承接，不是无调用方的表。

### D2 第一轮同次调用产出「稳定短身份说明」，仅影子模式生效，不碰事件指纹

**决策**：事件提取调用的同一次响应里新增 `subject_desc`（与 `subject`/`action`/`object` 同批产出，零新增模型调用），落 `topic_tags.metadata.entity_subject` 独立键，**不写进 `event_fingerprint`**；该字段**只在影子模式请求**，关闭态第一轮提示与 schema **逐字不变**。

**落点**：任务 T2；delta spec「主体提及的完整解析链」+ aggregate-tagging 的 ADDED。

**取舍**：不写进 `event_fingerprint` 是为了**不碰并发 change 的 Requirement**（Change C 正在 MODIFIED「事件指纹结构化产出」并加 `object_type`），也让既有指纹完整性判定与关键词一致性校验逐字不变。字段挂模式开关是评审 R-10 的直接要求：默认部署即改线上第一轮 prompt 没有回退开关。说明必须由第一轮真实产出——研究里「人工理想 query 短说明」正是 name_desc 侧收益被高估的来源（Q05「老黄」name_only 只到 rank10）。

### D3 检索域 = 实体池；两套表示、两个空间，各自同模型/维度

**决策**：候选只来自实体池；两套检索表示（实体名向量、实体名+短说明向量）各自由**同一 model/版本/维度**生成与比较，跨空间不得比较或 fallback 混用；辅助标签存量向量因来源不可证**不混入**。名路径**始终存在**（短说明为空只降级为仅名，不隐形）；提及带说明时两路都检索；每路取前 K、并列按实体 ID 升序。

**落点**：任务 T2；delta spec「主体提及的完整解析链」。

**取舍**：不把 aux 存量向量拉进语料（两绑定同文本 cos 仅 0.5703–0.7639，混用会静默污染比较；22k 行重 embed 属独立预算作业）。K 与合并条数是**待评测可调的配置**，不是身份裁决阈值——任何阈值都不得直接判定两个提及同一实体。

### D4 候选 = 两路向量 ∪ 名称登记命中，按 entity_id 去重

**决策**：三路合并后按 `entity_id` 去重，同一实体只留一个选项；同名可对应多个实体 → 多个不同 ID 的选项，由第二轮结合上下文选；名称登记命中**只提供候选**，不判定身份。

**落点**：任务 T2；delta spec「后续跨叫法跨板块再次出现合为一个 ID 选项」「同名不同实体可并存」。

**取舍**：**不做**「名字/别名精确即身份硬复用」——裸「苹果」指公司还是水果无法由名字判定；aux 自动 alias 是 L2 相似度产物（`英伟达GPU` 挂在公司行），按名字硬复用等于把歧义焊死。代价要认：名称登记命中只在**名称被登记过**时有效，冷启动首次提及没有历史登记可命中 → 该缺口只能靠向量召回，召回率由效果指标如实呈现，**不作无条件保证**。

### D5 第二轮 = 纯选择题；技术失败与 `none` 严格分开

**决策**：输入 = 提及原文 + 短说明 + 上下文片段 + 候选列表；输出只允许候选内合法 ID 或 `none`；判据写死为「是否指向同一实体」，仅相关/隶属/上下游/产品-厂商/机构-成员判不同。非法 ID、不可解析、服务失败、超时 → **技术失败**：不降级 `none`、不新建、不留半实体；最多 2 次尝试，耗尽后保持「未归一」。调用经统一模型路由入口，capability=`topic_tagging`、operation 非空；每次尝试写审计。

**落点**：任务 T2；delta spec「合法 none 与技术失败是不同结论」。

**取舍**：不新增 capability（ai-summary 红线 2）；不借 `digest_polish`（研究里借道润色能力已被否决）。prompt 明确写「相关 ≠ 同一实体」，针对研究的 Q20 误选（其根因含 prompt 的强选偏置，不只是模型能力）。重试上限 2：技术失败多为服务侧问题，重复打模型只烧预算。

### D6 跨进程全局实体解析闸门（会话级咨询锁 + 独立连接）

**决策**：用一把**跨进程生效**的数据库级闸门（PostgreSQL **会话级咨询锁**，独占一条独立连接）串行化「最新池检索 → 二次模型选择 → 原子登记/新建」全过程；**第一轮文章抽取在闸外**；数据库**事务只包写库段**。取得闸门后**必须重读**已登记提及与候选池，闸外旧 `none` 作废；等待/总时长/模型调用**有界**，超时以明确技术失败结束；闸门在 `finally` 释放并**归还连接**。

**落点**：任务 T3；delta spec「跨来源并发在闸内重读最新候选再二判」「取消超时异常释放闸门与连接」。

**取舍**：**不采用**评审 R-1 建议的「锁键=规范化提及名」——Trump 与「特朗普」键不同，防不住跨写法；同名不同实体又不能强合。改用**单一全局闸门 + 取得后重读**：两个进程对同一提及键必然串行，后者按**最新候选**重判——新判定选中已登记实体则复用同一 ID，新判定为合法 `none` 则**允许新建**（重复由重复身份组率与覆盖率量化，**锁只防陈旧结论提交，不保证模型判别正确**，也不承诺实体全局不重）。用**会话锁 + 独立连接**而非长事务：模型调用耗时不该占着数据库事务。代价明写：闸门把归一串行化 → **吞吐与等待时长是本期明确代价**，先测出来，不承诺高并发；**不引入无界乐观重试**。

### D7 `none` = 直接新建；短事务原子

**决策**：`none` 直接新建（无待处理队列、无人工闸门）；身份行 + 名称与证据行 + 辅助标签溯源行在**一个短事务**内完成，任一步失败整体回滚；事务不跨模型调用。

**落点**：任务 T2；delta spec「新主体首次出现走完抽取到原子登记」。

**取舍**：不用名称唯一约束兜并发（会误合同名实体）；不用 Go mutex（跨进程无效）。**闸门管串行、事务管原子**。

### D8 幂等 = 同来源同提及；跨来源不得按名字跳过判别

**决策**：同一文章同一标签的同一提及重复处理 → **复用先前决策**（不再发起第二轮模型调用）；跨来源的同一次提及 → 按当次上下文**重新判定**。

**落点**：任务 T2；delta spec「同来源同提及重放幂等」。

**取舍**：幂等键用（来源标签, 提及键）而非（提及文本）：同文不同文的两次出现可能指向不同实体（裸「苹果」歧义），按文本做键会把它们焊死。跨来源不复用是评审 R-5 的要求：复用会让「跨来源同名」用例变假绿；跨来源并发是否双建，靠 D6 的闸门 + 重读解决，不靠复用。

**边界（评审 R-18 口径补充）**：**来源标签相同的跨文章复用视为同一来源**——`topic_tags` 行跨文章共享，两篇文章逐字同 label → 同一 `source_tag_id` → 同一幂等键（来源标签, 提及键）→ 第二篇幂等短路、不再二次判定。这是制品口径（来源 = 来源标签）与数据模型之间的已知缝隙；按**文章维度**重判属后续 change（需改 `entity_mentions` 的 partial 唯一索引 `uq_entity_mentions_source_key`，现为 `(source_tag_id, mention_key) WHERE source_tag_id IS NOT NULL`）。本期不改幂等键、不加迁移。

### D9 本期身份判定零改动；未来接线不写成本期规则

**决策**：实体身份层**不参与既有事件线身份判定**（实体层自身仍照常做身份判别）；事件线身份判定仍只走既有 `subject_key` 三层 + 一票否决；`subject_key`、事件线归属、人工归属、热度口径零改动；存量实体身份恒为空。「双侧都有实体 ID 时按 ID / 单侧回退 / 两侧无 ID 走既有路径」属**后续 change**，不写成本期现行规则。

**落点**：任务 T3；delta spec「事件线身份判定不读实体 ID」+ event-story 的 MODIFIED。

**取舍**：评审 R-8 指出的自相矛盾（同一段既写「本期不参与」又写「有 ID 按 ID 判」）成立——那三分支比较本期不可达，归档后会变成主 spec 的现行规则。保留的 event-story 场景额外断言**判定路径不读取实体 ID**，使它有回归信号而非恒真断言。

### D10 影子模式与生产开关边界（关闭态逐字不变）

**决策**：`off`（默认，2026-11-10 决策：影子实验结束，实体层不接入事件线判定，避免实体注册表只增不减成为黑洞）/ `shadow`（实验态，需显式配置开启）/ `active`；本期实现前两者，`active` **显式拒绝**。`off`：第一轮提示与 schema 与调用数**逐字不变**、零第二轮调用、零写入（含不写 `entity_subject` 键）。`shadow`：第一轮启用短说明，写入**限定三处**——实体层、正常 AI 审计、`topic_tags.metadata.entity_subject` 独立惰性键；不改 `event_fingerprint`、标签业务字段与归属、story/report/topic 与界面可见字段。评测入口走**显式影子路径**、不改应用全局配置；**评测 CLI 不写标签业务表**，其第一轮原始结果存评测产物与实体层证据。

**落点**：任务 T3、T4；delta spec「影子接入与既有判定零改动」。

**取舍**：`active` 做成「报错」而非「留个空开关」——空开关会让人以为生产归一已生效。评测必须走显式影子路径：它要的是「带新字段的第一轮」，走全局 `off` 就没有 `subject_desc`。评测与应用 shadow 的写库边界**分开写清**，避免评测入口被当成可写业务表的授权。

### D11 评测入口与预算清单：按真实阶段列，不用固定倍数

**决策**：评测吃**真实第一轮产出**（影子路径持久化结果或现场重跑），产出逐提及记录 + 盲标工作表 + 机械评分器。预算清单按**真实阶段**分列四项并机械可算：① 文章抽取次数 = 实际抽取文章数；② 二判次数 = 实际提及数 + 实际发生的有限重试；③ embedding 提交文本数 = 两路查询 + 实体创建 + 别名登记 + 材料读取（若需），**计入重复发送与模型降级重复**；④ HTTP 次数按**发送前计数**，不支持批量按单条实际计，结构化输出降级链与客户端多次 HTTP 尝试一并计入。

**落点**：任务 T4；delta spec「有界评测入口与效果口径」。

**取舍**：**删掉**上一版的「提及数×2」「ceil(文本/32)」——后者与真实路由行为不符（缓存白名单只有 2 个 operation，代码里根本没有 32 条一批的切分）。硬预算用**仅在评测入口注入**的 provider/transport 包装（研究 runner 已有同类 guard 经验），**不做生产路由整体重构**，并保持正常审计；无法建立发送前计数能力则**预先阻断**。当前无新额度授权：本期只产出预算清单与授权流程。

### D12 评测协议冻结、金标隔离与效果验收口径（固定总 N + 配对可比）

**决策**：运行前**冻结**协议要素（样本清单、文章快照、分组规则、模型与版本、预算清单、评分规则）；金标**在运行前**由与模型输出隔离的标注者按原文盲标形成，**运行器不读金标**，评测后由评分器 join；争议样本**运行前**预列为「不计身份分」并报数量。验收口径：固定总样本 N 为分母，同时报覆盖率、技术失败数、错误复用数与**按固定总 N** 的错误率；两套预测分组——既有身份（`subject_key`，**空键单列「缺身份」**）与实体 ID（**无决策单列「未归一」**）——在**同一「两套都有预测」的可比子集**上算 pairwise 误合 / 漏合 / 重复身份组率；**缺决策不以单元素组冒充正确**。冷启动段从全空顺序处理，首次自然新建不计重复，「金标实体当时已在池中」只由评分器依顺序历史金标**事后标注**；重放段冻结**未经金标修正**的池；统一 ID 稳定性按 ID 相等计。

**落点**：任务 T4；delta spec「有界评测入口与效果口径」。

**取舍**：**改成配对可比口径**，因为基线是组级、新系统是提及级，量纲不同直接比大小不可复算；同时把**覆盖率与既有身份并列成门槛**，堵住「多失败、少误合」的刷分路径（R-3）。技术失败数不为 0 即**阻断**该段并要求修复后重跑。冷启动段与重放段的「池中是否有金标实体」判定**只留在评分器侧**——归一器一旦看见 gold，评测即自证。**不设 95% 之类无依据目标**：门槛只写「误合不增加 / 重复身份减少 / 覆盖率不低于基线 / 技术失败为 0」；数据不足、基线分母 0 或某段未测 → **不判达标、任务保持未完成**。

## Out of Scope（后续接线，本期不写为现行规则）

- **实体 ID 接入事件线身份判定**（双侧有 ID 按 ID / 单侧回退并标「混合身份比较」 / 两侧无 ID 走既有路径）：本期不可达，归后续 change；本期只保证 legacy 判定逐字不变。
- **辅助标签存量向量重 embed 并进入检索语料**（22k 行、约 688 次 HTTP 量级）：独立预算作业。
- **ANN 索引**：本期实体池从零增长，沿用内存全量 + 余弦；规模超阈值后再做（与 `unify-vector-column-dimension` 的 halfvec 索引表达式耦合）。
- **实体类型提示**：本期不入身份层；若未来保留，只作第一轮可选输出，绝不参与身份判定。

## Risks / Trade-offs

- **[闸门串行化 → 吞吐下降]** → 评测记录闸门等待与单次解析总时长，作为本期明确代价报出；不承诺高并发。
- **[误合比漏合更贵]** → 判据只认「同一实体」；产品/公司、人物/政府、地区/国家在评测里单列分组。
- **[召回不足导致重复新建]** → 重复新建率与覆盖率单列并对照基线；「合法 none」不等于「检索正确」。
- **[名称登记命中在冷启动期无效]** → 冷启动段重复新建率单独报；不宣称名字命中能消除该缺口。
- **[模型调用成本]** → 影子态会把成本暴露在打标管线（每个 event 标签多 1–2 次二判 + 查询 embedding）；默认已是 `off`，成本不再默认发生（只在显式配置 `shadow` 或评测时发生）；需要零成本时保持 `entity_subject.mode` 为 `off`（连第一轮提示都不变）。
- **[评测依赖人工盲标]** → 工作表只给原文与提及上下文，不给候选描述与系统输出；争议项预列并报数。
- **[两个并发 change 同时改 `event-story` 与迁移注册处]** → 文件边界（新文件 + `postgres_migrations.go` 只加一行；不改 `board_stories` 结构与 `story_assign.go`/`story_fingerprint.go`/向量列 typmod；`event-story` delta 只改「主体归一化」一条）+ 归档顺序由主线程把关。
- **[本期不解决跨天 story]** → 本 change 的效果**不等同**「事件线跨天已修好」；也不宣称生产漂移已修好。

## Migration Plan

1. **建表**（AutoMigrate + 一条索引/约束迁移）：3 张空表，无历史回填、无存量改写；向量列无维度限定，维度写在行上。
2. **默认 `off`**（2026-11-10 决策：影子实验结束、实体层不接入事件线判定，避免实体注册表只增不减成为黑洞）：第一轮提示与 schema 与调用数逐字不变、零二轮调用、零写入，实体层三表与 `metadata.entity_subject` 惰性键**不再新增**。要跑影子实验把 `entity_subject.mode` 改成 `shadow`（提示与 schema 多一个 `subject_desc`，实体层三表与 `metadata.entity_subject` 开始写入；标签、事件线、日报、话题与界面可见字段仍**零变化**）。
3. **影子（可选、需授权）**：写入限定为实体层、正常 AI 审计与 `topic_tags.metadata.entity_subject` 独立惰性键；其余标签与事件线数据不变。
4. **评测（需单独授权真实模型调用）**：有界跑 → 逐提及记录 + 盲标工作表 → 人工盲标 → 机械评分 → 报告（含全部错例）。
5. **回滚**：把配置改回 `off` 即停止一切归一写入；实体层可整层删除（不被任何既有表引用），既有功能回到今天的行为。存量数据全程零改动，**不存在需要回滚的数据迁移**。
