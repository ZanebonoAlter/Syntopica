## 判定条目

### A-1 右轨结论进入问题处理区（1440×900）【pass】
依据：板块 `1974` 右轨「版块体检 72」→「完整评语与依据」打开工作面，顶部一行显示「本轮体检 / 本轮需核对 4 项」，左侧索引逐项给标签 + 结论 + 证据摘要（cosine_mean / low_sim_ratio / 近邻 / desc 预筛），未把评分做成主卡。截图 `real-1440-index.png`。

### A-2 单项核对：原描述、可编辑新描述、共享范围（1440×900）【pass】
依据：板块 `2197` 选择「CNN」，右区显示「当前描述：美国有线电视新闻网，美国主要新闻频道」、新描述输入框与 `26/500` 计数、共享标签声明「所有使用它的版块都会受影响」与「匹配更新覆盖全部活跃话题标签（20280 个）；旧体检快照与既有日报不改写」，主按钮唯一。截图 `real-1440-detail.png`。

### A-3 确认层 + 取消零写入【pass】
依据：点「修复描述并更新匹配」后在**同一处理区**出现确认块「确认更新这个共享标签？… 此操作不是只保存文字，还会生成向量并更新活跃话题标签的版块匹配」；点「取消」后 `SELECT count(*) FROM auxiliary_description_repair_jobs` 由 4 保持 4，零写入。截图 `real-1440-confirm.png`、`real-1440-after-cancel.png`。

### A-4 真实执行三阶段 + 再进入以服务端任务为准【pass】
依据：板块 `1974`「内塔尼亚胡」进入工作面即恢复真实任务进度——「生成新的语义向量 / 保存描述与向量（同一事务）/ 更新版块匹配」三阶段，范围 19881、已更新 5768、失败 0、已失效/删除被跳过 10、待处理 14103、状态「执行中…」，并非组件内本地标记；同时点 DB 对账 `auxiliary_description_repair_jobs` id=2 `stage=matching`、`processed=5784`、`total=19881`（含 `not_applicable=10`），与界面同源。后端两次停机后重进均从此接口恢复进度（GET `/api/auxiliary-labels/198276/description-repairs/2`）。截图 `real-1440-progress.png`。

### A-5 组合标签 rewrite 只读、证据不隐藏【pass】
依据：板块 `2197`「美联储沃什」（composite）显示「描述修复 · 只读」「组合标签暂不支持描述修复。分诊证据仍可展开核对；要处理这一项，可考虑从本版块摘除它」，无新描述输入框与修复主按钮，「为什么建议处理 · 展开证据」仍可用。截图 `real-1440-composite-readonly.png`。

### A-6 1920×1080 版式【pass】

### A-10 旧快照（无 triage）形态【未覆盖】
原因：当前 12 个活跃板块的最新快照全部含 triage 数组（2026-11-05），库里没有「最新即旧形态」的真实样本，不制造数据。兼容性由后端 PG 回归「历史快照缺分诊字段兼容」与「查询最新快照」覆盖。附带：`real-1440-no-issues.png` 记录的是板块 `2165` 的**合法空态**（最新快照 13 项全 keep/insufficient →「本轮需核对 0 项」），不是旧快照形态，不作 A-10 证据。

### A-11 摘除（次链）行内确认【未覆盖】
原因：各板块最新快照里 `remove` 项为 0（当前数据全是 rewrite/keep/insufficient），无法在不制造数据的前提下走真实摘除流程；摘除链路由既有手工 DELETE 与前端回归覆盖。

### A-12 匹配部分失败 / 完成 → 处理下一项【未覆盖】
原因：四个真实任务验收时仍在 `matching`（失败 0、未完成），未观察到真实 `completed` 或部分失败态；按「不冒充」原则不做伪造截图。该状态机由 PG 回归（部分失败恒 `matching_failed`、`retry` 只续匹配、完成后可下一项）覆盖。

## 与 ui-design 契约的对账说明

- 主链（索引 → 核对 → 编辑 → 确认 → 真实阶段 → 下一项）除「完成/部分失败」外全部在真机走到，且页面不冒充原型。
- 「仅摘除可处理」在真实数据里表现为组合标签只读提示（A-5），符合 Interaction Contract 第 7 条与红线 25。
- 计数口径「已失效/删除被跳过 10、跳过不计入已更新」在真机可见（A-4），与红线 26 一致。
- 旧快照、摘除确认、完成态三项未覆盖，原因如上；不阻断归档（本 change 的不变量由后端 PG 回归与前端组件回归覆盖）。
