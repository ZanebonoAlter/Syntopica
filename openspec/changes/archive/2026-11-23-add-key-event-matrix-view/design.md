## Context

- 版块态势页主舞台已是 `ObservationMatrix`（`front/app/features/tags/components/console/ObservationMatrix.vue`），行 = 话题、列 = 观察轴、格 = 当日非综合稿线索数；行序与休眠判定唯一实现在 `observationLanes.ts:buildObservationRows`。
- 矩阵数据来自 `GET /api/semantic-boards/:id/lane-dynamics`：`lanes[]` 带 `timeline[]`，`candidates[]` **只有汇总**（`topic_id/label/last_seen_date/recent_hint/clue_count/lane_heat`），没有逐日数据。
- 关键事件注记在 `topic_key_event_markers`：`persistent_topic_id` + `source_period_date`（date）+ `title_snapshot` / `summary_snapshot` / `topic_label_snapshot` + `state`（suggested/confirmed/dismissed）。人工确认口径只认 `confirmed`。
- 现有读端只有「按单个话题」：`GET /api/daily-reports/topics/:id/key-events`，矩阵级视图逐行拉不可行。
- 2026-11-21 实测：全库 confirmed 72 条 / 31 个话题，最早 2026-10-10、最晚 2026-11-22（确认功能上线才累积出这 44 天）；分布按周 6–15 条。某版块 44 天内 28 条、14 天窗口 12 条；另一版块 44 天 5 条、14 天 5 条；还有版块 14 天 0 条。
- 因此：「关键事件视图跟矩阵的 14 天共用」会让多数版块整屏无节点，跨度必须独立。

## Goals / Non-Goals

**Goals:**

- 一次请求取全观察窗内的 confirmed 事件，前端不再逐话题拉。
- 关键事件视图与矩阵**同轴、同行序、同选中态**，切换不重置。
- 标签完整可读、不重叠、不截断；长窗有明确降级。
- 空态与失败态诚实，不伪造 0 条。

**Non-Goals:**

- 不改变矩阵视图的任何格值 / 色深 / 行序 / 休眠 / 当日其他话题口径。
- 不做 `suggested`、不做系统派生的结构事件（突增 / 复苏 / 首次出现）。
- 不在本视图做注记写操作。
- 不做窄屏（<768px）形态。

## Decisions

### D1. 视图切换挂在页头分段组

- **结论**：`BoardConsoleHeader` 的 `.console-seg` 增加第四项「关键事件」，`activeView` 增加 `'events'`；`BoardConsoleShell` 用同一套切换逻辑渲染新视图。
- **落点**：`front/app/features/tags/components/console/BoardConsoleHeader.vue`
- **取舍**：放在矩阵内部工具栏（与「时间线 / 体量泳道」同级）被否——用户要的是与「矩阵 / 追踪」同级的读数视角；放进矩阵内部会暗示它是矩阵的子模式，也让"切换后矩阵消失"显得突兀。

### D2. 行集合复用现有行序，只取持久化话题

- **结论**：行集合只取 `buildObservationRows` 产出的持久化话题（active）行，沿用同一排序与休眠判定；候选话题（candidate）不占行、其事件不进入本视图。
- **落点**：`front/app/features/tags/components/console/observationLanes.ts:buildObservationRows`
- **取舍**：候选话题合并成一行被否——用户 2026-11-21「最下面那坨待添加候选画蛇添足没必要」；候选各占一行被否——行数会随候选数量膨胀，且与「行=持久化话题」的语义冲突。

### D3. 新增版块级批量读端点

- **结论**：`GET /api/semantic-boards/:id/key-events?days=N`，只返回 `state='confirmed'` 且 `source_period_date` 落在窗口内的注记，扁平列表（`id / topic_id / topic_label_snapshot / source_period_date / title_snapshot / summary_snapshot`）；前端按 `topicId + date` 聚合。
- **落点**：`backend-go/internal/topicgraph/handler/key_event_handler.go:RegisterKeyEventRoutes`
- **取舍**：在 `lane-dynamics` 的每个 `timeline.day` 内联 `key_events[]` 被否——382 行 × 14 天的响应膨胀，且事件是版块级资源，不该挂在泳道响应里；复用现有 topic 端点被否——矩阵行数不固定。

### D4. 标签两阶段布局（先量后排）

- **结论**：事件标签先以自然宽度渲染（`white-space: nowrap`，不加 `text-overflow`），再用 `offsetWidth` 实测宽度做贪心分层：按日期升序，每层记录已占右边界，放得下就复用该层、放不下就新开一层；靠近右边界时 `left = max(0, 容器宽 - 标签宽)` 左移贴边。行高 = 无标签 70px / 有标签 `46 + 层数 × 44`，封顶 246px（4 层）。
- **落点**：Scenario「标签不截断」
- **取舍**：按字符数估算宽度被否——中英混排误差大，实测会重叠；`ellipsis` 截断被否——用户明确要求「显示名称」；固定行高被否——同日多事件必然叠层。
- **校订（review R-2，2026-11-23）**：本条原写的「46 / 38+24L」是早期估值，实装与 ui-design Layout Contract 一致采用 **70 / 46+44L（封顶 246）**；以本行现文为准。

### D5. 新视图独立组件，不改造矩阵

- **结论**：新增 `KeyEventTimelineView.vue`（行 + 轴 + 标签）与 `KeyEventLabel.vue`（单条标签），复用 `observationMatrixRows.css` 的列宽、行头与选中态样式；`ObservationMatrix` 不动。
- **落点**：Scenario「候选话题不占行」
- **取舍**：在 `ObservationMatrix` 内加 `v-if` 分支被否——矩阵已有 loading / 首错 / stale / 无日报 / 无泳道 / 休眠折叠 / 当日其他话题等状态，塞入第二个视图会变成条件套条件。
- **校订（review R-5，2026-11-23）**：本条落点原写 Scenario「候选话题合并为一行」——那是 **D2 被否决的方案**，仓库里不存在同名 Scenario，语义相反。已改为真实存在的 Scenario「候选话题不占行」。

### D6. 视图状态走 URL query

- **结论**：`activeView` 写入 `?view=events|matrix`，刷新与分享保持；非法值回落 `matrix`。
- **落点**：`front/app/features/tags/components/console/BoardConsoleShell.vue`
- **取舍**：纯内存态被否——现有 `days/start/end/lane` 都走 URL 恢复，视图状态例外会让人刷新后回到矩阵。

### D7. 长窗降级按堆叠层数，不按天数

- **结论**：事件名称**不再因为观察窗天数长而整体收起**。行内标签照常显示（同一行内多条靠贪心分层避让，每层 +44px）；只有**堆叠层数超上限（4 层 / 行高封顶 246px）** 的行才退化为「节点 + 当日事件计数（`★N`）」，名称由选中日阅读区承担。
- **落点**：Scenario「层数超限才收起标签」
- **理由**：2026-11-23 用户实机反馈「超过 30 天啥都看不见」——原口径按「可见日数 > 31」一刀切收起，55 天窗口只剩光点 + ★计数，等于白屏。真正的拥挤来源是**标签互相重叠的层数**，不是天数：天数多只是列更宽更稀。
- **取舍**：不用「天数阈值」是因为它把「稀疏」误判成「拥挤」；改为层数上限后，365 天窗口靠层数封顶自然收敛（层数超限的行才退化），而不是整体无差别收起。

### D8. 本视图只读

- **结论**：不挂 `KeyEventMarkerActions`，不提供确认/取消/编辑入口。
- **落点**：无代码落点：`ui-design.md`「明确不做」与 `topic-graph` 约束 10，因为注记写动作的唯一归属是日报阅读台，矩阵级视图只做回看。

### D9. 时间视窗与矩阵共用

- **结论**：关键事件视图不维护第二套跨度状态，直接使用矩阵的 `visibleAxis`；要看某一时段 30 天，就在同一个时间视窗控件里切 30 天。
- **落点**：Scenario「时间视窗两侧共用」
- **取舍**：独立跨度控件（30/90/全部）被否——用户 2026-11-21「时间选择器和矩阵这边共用一个即可」；两套跨度会让两张表的时间尺度不一致，选中日也很难对齐。

### D10. 列宽固定 + 舞台横向滚动 【已作废，由 D11 取代】

- **结论（历史）**：列宽取舒适固定值（7 天 84px / 14 天 72px / 30 天 64px），总宽超出舞台时在**舞台容器内**横向滚动；行头 sticky，滚动时自动把选中日拉入视口。
- **作废说明（review R-2，2026-11-23）**：本条与 D11（均分 `max(64, 可用宽/可见日数)`）互斥，D11 为最终口径（用户 2026-11-21「2560 屏 14 天只占一半宽、右侧大片留白」的反馈）。**实装与验收都按 D11**，本条仅存档取舍过程。
- **落点**：Scenario「宽列横向滚动」
- **取舍**：压缩列宽把 30 天塞进一屏被否——实测 22px/列时 19 条事件堆到 8 层、单行高 350px+，反而比滚动更难读；缩小字号被否——事件名可读性下降，且与「名称要看得见」的诉求冲突。

### D11. 列宽均分 + 左键拖拽平移

- **结论**：列宽 = `max(64px, 主舞台可用宽 / 可见日数)` —— 超宽屏均分填满、窄屏守 64 下限后横向滚动；舞台空白处按住左键拖动平移，位移阈值 5px 内视为点选。平移与阈值判定复用新建泳道画布的 `panScroll` / `isDragBeyond`，不另写一套手感。
- **落点**：`front/app/features/tags/composables/laneComposeLogic.ts:panScroll`
- **取舍**：只靠原生滚动条被否——用户 2026-11-21「应该支持左键拖拽，就像新建泳道这里」，超宽屏上拖拽比抓滚动条自然；固定列宽被否——2560 屏下 14 天只占 1/2 宽，右侧大片留白。

### D12. 事件 → 文章 → 阅读的闭环复用既有链路

- **结论**：事件卡展开 `article_ids_snapshot` 对应的文章，点文章 `emit('open-article', id)`，由 `BoardConsoleShell` 已挂载的 `ArticlePreviewModal` 打开；文章元信息按需读取并复用既有文章缓存（≤20 FIFO、在途合乘、晚到隔离），不新造第二份阅读器或缓存。
- **落点**：`front/app/features/tags/components/console/BoardConsoleShell.vue`
- **取舍**：在阅读区自建内嵌阅读面板被否——与矩阵当日工作面、日报阅读台三处阅读器会各写一套缓存与关闭语义；新开路由页被否——用户会丢掉时间轴上下文，达不到「闭合回原卡」。

### D13. 双主题走语义变量

- **结论**：新视图（节点、标签、选中列、文章列表、未新增的预览层）一律用 `--color-*` 语义变量，不写死色值；暗色下单独复核对比度。
- **落点**：无代码落点：`ui-design.md`「Layout Contract · 双主题」，因为这是实现约束而非行为决策。
- **取舍**：固定亮色原型色值被否——项目已有 editorial/dark 双主题（`theme-system`），硬编码会在暗色下打脸。

### D14. 右轨选话题 → 切回矩阵 / 追踪视图

- **结论**：从**右轨**发起的话题选中（当日其他话题 / 话题条目），一律把主舞台切回「矩阵 / 追踪」视图，并把该话题泳道**滚入视野 + 高亮**。
- **落点**：`front/app/features/tags/composables/useBoardConsole.ts`（`activeView` 切档入口）+ 右轨选中的既有落点逻辑（滚入视野 + 高亮）
- **理由**：2026-11-23 用户实机反馈「我选了右侧的泳道等应该跳转回矩阵追踪视角」——候选话题在关键事件视图里**不占行**（D2 / 红线：候选不占行），右轨选中在事件视图里是**死选择**：无视觉反馈、无处可落，用户以为点了没反应。
- **取舍**：本视图**内部**的选中（点行头、点节点）仍留在本视图，不打断当前时间轴上下文；只对「从右轨发起」的动作切视图。若一律对所有选中动作切视图，用户在事件视图里点行头就会被踢走，丢失时间轴上下文。

## Risks / Trade-offs

- **[事件稀疏，视图看起来"没做"]** → 空态文案点明「在日报阅读台标记」，并在 proposal / 验收里写明当前数据量（某版块 14 天 0–5 条、30 天 23 条），避免误判为故障。
- **[候选话题事件不可见]** → 明说：候选话题的确认事件不在本视图呈现，等它转正后自然出现在对应行；不另造合并行。
- **[标签层数失控导致行高爆炸]** → 改为固定宽列 + 横向滚动后，30 天密集行降至 3–4 层（行高 ~200px）；层数上限 4 层（行高封顶 246px），超限的行才收成节点 + 计数。
- **[横向滚动后选中日在视口外]** → 切换跨度/视图时自动把选中日拉进视口；行头 sticky 保证扫行不丢上下文。
- **[文章缓存被大批事件撑爆]** → 只按需读取用户实际展开的那几条，沿用既有 20 条 FIFO，不预载。
- **[超宽屏列宽过大显得散]** → 列宽上限由「可用宽/天数」自然约束（14 天 165px、30 天 77px）；若嫌散可在验收后加 `max-width` 封顶，但不阻塞本 change。
- **[右边缘标签左移后与节点错位]** → 标签保留节点色点，`title` 带日期；必要时在任务里加一条「右边缘标签加连接线」的可选优化。
- **[事件话题被改名/归档]** → 只用确认时快照，不反查实时话题名；归档话题的事件仍显示（历史事实不随归档消失）。
- **[长窗事件名被一刀切收起 → 白屏]** → 收起判据从「观察窗天数」改为「堆叠层数上限」（用户 2026-11-23 实测 55 天窗口啥都看不见）。
- **[右轨选中在事件视图里是死选择]** → 右轨发起的话题选中一律切回矩阵 / 追踪视图再落点（见 D14）。

## Migration Plan

1. 后端先上端点（只读、无 schema 变更、无迁移）。
2. 前端上视图与切换；`ui-approval` 批到 `approved` 后才进实现。
3. 部署：`bash scripts/dev/deploy-frontend.sh`（构建静态产物 → 铺盘 → 重启后端 → 健康检查）。
4. 回滚：移除视图入口即可，后端端点可保留（无副作用）。
