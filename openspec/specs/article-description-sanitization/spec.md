# article-description-sanitization Specification

## Purpose

文章摘要字段（`articles.description`）的内容来源是第三方 RSS/站点，不可信且体积不可控——部分源把整篇文章的 HTML 塞进摘要。本能力定义摘要字段的纯文本化入库契约、第三方 HTML 的安全渲染契约、刷新判重契约与存量数据的回填契约，使摘要既能作为导语展示，又不会把第三方 HTML 直接带进 DOM 或把数据库撑成百 MB 级。

## Requirements

### Requirement: 文章摘要入库即纯文本化

RSS 条目入库时，文章摘要 MUST 被收敛为**纯文本摘要**：移除脚本与样式内容、剔除隐藏节点（声明 `display:none`、`visibility:hidden`、`opacity:0`、`font-size:0` 的元素及其子树）、去除标签、还原 HTML 实体、折叠连续空白；纯文本摘要长度 MUST ≤300 字符，超长时截断并以省略号收尾。清洗 MUST 幂等（对已清洗结果再清洗结果不变）。

清洗顺序 MUST 为「**先还原实体 → 再按 HTML 解析 → 取文本**」：该顺序保证清洗幂等（输出中残留的尖括号不会在二次清洗时被当作标签吞掉），代价是源里写成转义形式的标记（`&lt;b&gt;`）会被当作标签丢弃——此取舍 MUST 在实现与文档中一致体现。

文章正文源字段（`articles.content`）MUST NOT 因本要求被改写——它继续保留源站原文，供正文源切换与整理稿兜底使用。

摘要清洗口径 MUST 与列表导语（`excerpt`）的清洗口径**同源同实现**（同一实现、同一顺序、同一实体集合、同一隐藏判定），仅允许长度上限与既有的「实质文本地板」不同（`excerpt` ≤200 字符且无字母数字时为空串；摘要 ≤300 字符）。两侧实现 MUST 用同一组固定样本断言**逐字相同的输出**，作为防漂移锚。

#### Scenario: 整篇 HTML 型摘要入库为纯文本

- **WHEN** 某订阅源的 RSS 条目摘要是一篇完整文章的 HTML（含大量内联样式与图片），长度 66 KB
- **THEN** 入库后的摘要 MUST 为不含任何标签的纯文本，长度 ≤300 字符，超长处以省略号收尾

#### Scenario: 隐藏节点内容不进入摘要

- **WHEN** 摘要 HTML 中存在 `style="opacity: 0"` 的根节点包裹整篇文章正文
- **THEN** 该隐藏子树的内容 MUST NOT 出现在摘要中（隐藏即视为不可见内容，与渲染层的可见性判定一致）

#### Scenario: 纯文本摘要不被改写

- **WHEN** 某订阅源的 RSS 条目摘要是不含任何标签标记的普通文本（≤300 字符）
- **THEN** 入库后的摘要 MUST 与源文本一致（仅空白折叠），MUST NOT 被截断或改写

#### Scenario: 清洗幂等

- **WHEN** 对已入库的摘要再次执行同一套清洗
- **THEN** 结果 MUST 与已存值逐字相同（重复回填不产生二次改动）

#### Scenario: 正文源字段不被改写

- **WHEN** 一篇文章的摘要与正文源字段内容相同（部分源两字段同源）
- **THEN** 正文源字段 MUST 保持原样（仍为源站全文 HTML），MUST NOT 被摘要的清洗规则改写

#### Scenario: 前后端清洗口径一致

- **WHEN** 同一段输入（含实体、含隐藏节点、含普通文本）分别经过服务端清洗与前端清洗
- **THEN** 两侧产出的纯文本 MUST 逐字相同（由同一组固定样本的跨实现断言锁定）

### Requirement: 第三方 HTML 渲染前必须经清洗

任何来自订阅源的文章内容在进入 DOM 之前 MUST 经过清洗，且**两类隐藏 MUST 分开处理**：

- **视觉隐藏声明**（`visibility:hidden` / `opacity:0` / `font-size:0`）→ MUST 剥离该声明、**保留元素与其内容**（内容本身有效，只是被视觉藏起来，剥声明后重新可见）；
- **语义不展示**（`display:none` / `hidden` 属性）→ MUST 移除该元素**连同其子树**（内容本不参与展示，且此类块常藏 SEO 关键词堆砌）。

脚本与样式元素、事件处理属性（`on*`）MUST 被移除；**可执行嵌入元素**（`iframe` / `object` / `embed` / `form` / `applet` / `base` / `frame` / `frameset`）与 `srcdoc` 属性 MUST 被移除；**危险 URL 方案**（`javascript:` / `vbscript:` / `data:`，`data:image/*` 除外）出现在 `href` / `src` / `xlink:href` / `action` / `formaction` / `poster` / `data` 属性上时 MUST 移除该属性。其余结构与排版 MUST 保留。

摘要导语 MUST 以纯文本渲染（不得作为 HTML 注入），且**纯文本摘要侧取更严口径**：任一隐藏声明包裹的子树内容整体不进入摘要（摘要不重复正文，不做「解隐藏」）。正文源切换渲染时 MUST 施加上述保守清洗（保留可见正文结构）。

清洗 MUST 在渲染路径上生效，即**不依赖数据是否已被回填清洗**——存量未清洗数据同样 MUST NOT 以未清洗 HTML 进入 DOM。

#### Scenario: 摘要导语以纯文本呈现

- **WHEN** 文章摘要字段仍是含内联样式的整篇 HTML（存量数据）
- **THEN** 导语段 SHALL 呈现其去标签后的纯文本，MUST NOT 出现空白占位，也 MUST NOT 把该 HTML 作为标签注入 DOM

#### Scenario: 不可见内容不占位

- **WHEN** 文章 HTML 的根节点声明 `opacity: 0`（内容整体不可见）
- **THEN** 渲染结果 MUST 剥离该隐藏声明并保留其内容（正文重新可见），MUST NOT 为其保留不可见但占位的空间，页面首屏 MUST 直接可见正文

#### Scenario: 语义不展示的隐藏块被剔除

- **WHEN** 文章 HTML 含 `display: none` 或带 `hidden` 属性的块（常见于 SEO 关键词堆砌的藏身处）
- **THEN** 该块连同其子树 MUST NOT 出现在渲染结果中

#### Scenario: 事件属性不被执行

- **WHEN** 文章 HTML 含 `onerror`、`onload` 等事件处理属性
- **THEN** 清洗后 MUST NOT 保留这些属性，渲染出的 DOM MUST NOT 绑定对应处理器

#### Scenario: 可执行嵌入与危险 URL 方案被剔除

- **WHEN** 文章 HTML 含 `<iframe srcdoc="<script>…">`、`<form>` 或 `href="javascript:…"` 之类可执行内容
- **THEN** 清洗后 MUST NOT 残留这些嵌入元素与危险 URL 属性

#### Scenario: 正文源切换后正文可见

- **WHEN** 用户在内容源切换中选择原始内容（源站全文 HTML）
- **THEN** 渲染结果 MUST 为清洗后的可见正文，隐藏节点 MUST NOT 造成空白占位

### Requirement: 刷新判重 MUST 比较清洗后的摘要与正文源字段

订阅源刷新时判定「内容未实质变化」MUST 比较**与入库时同口径**的值：入库存储的摘要是清洗后的纯文本，判定时 MUST 同样使用清洗后的摘要与未改写的正文源字段，**MUST NOT** 用未清洗的源站原文与库内清洗值直接比较。

否则「摘要即整篇文章 HTML」的源永远判为「内容已变」，导致每轮刷新都重置处理状态、删除既有标签并重跑抓取/总结/打标链，违反「内容未变时不得触发任何处理链」的既有契约。

判定 MUST 同时包含正文源字段（源站原文）——清洗后的摘要只有 ≤300 字符，正文的变化无法再从摘要检出。

#### Scenario: HTML 型摘要的连续刷新不重跑处理链

- **WHEN** 某源的条目摘要是整篇文章 HTML，连续两轮刷新之间源站文章未变
- **THEN** 系统 MUST 判定内容未变并直接跳过，MUST NOT 重置处理状态、删除标签或重新入队处理

#### Scenario: 正文变化仍被检出

- **WHEN** 两轮刷新之间源站文章的正文源字段发生变化（摘要被截断后看不出差异）
- **THEN** 系统 MUST 判定内容已变并走更新分支（更新内容字段、重置状态位、重跑处理链）

### Requirement: 整理稿兜底 MUST 使用正文源字段的文本投影

Firecrawl 抓取失败时，整理稿生成 MUST 降级使用**正文源字段**的纯文本投影（去脚本/样式/去标签/还原实体/折叠空白，**保留隐藏子树的文本**——被视觉藏起来的正文对「总结正文」这个用途是有效内容），MUST NOT 直接使用可能为空或过短的清洗后摘要。

该投影 MUST 只用于整理稿兜底路径，MUST NOT 改变「展示层正文优先级」与「内容补全只用 firecrawl_content」的既有契约。

#### Scenario: Firecrawl 失败时仍能生成整理稿

- **WHEN** 文章的 Firecrawl 抓取失败、摘要因整篇隐藏而为空、但正文源字段含完整文章
- **THEN** 整理稿生成 MUST 以正文源字段的文本投影为输入并成功产出，MUST NOT 以「无可用内容」失败

### Requirement: 存量摘要字段可一次性回填

系统 MUST 提供一次性回填命令，对历史文章摘要按同一套清洗口径处理：默认只统计不写库（dry-run），显式开启写入后才更新；处理 MUST 幂等且可重复执行；MUST NOT 修改正文源字段与其它文章字段；回填 MUST 报告受影响行数与释放的存储体积。

回填候选 MUST 与「是不是 HTML」的真实判定对齐：含真实标签标记的行 MUST 被清洗；**不含真实标签标记的行 MUST NOT 被改写**（避免把正常纯文本摘要里出现的尖括号当成标记清理掉）；超长纯文本行 MAY 按长度上限截断以对齐摘要长度不变量。

#### Scenario: 默认不写库

- **WHEN** 不带写入开关运行回填命令
- **THEN** 数据库 MUST NOT 被修改，命令 MUST 输出待清洗行数与预计释放体积

#### Scenario: 显式写入后摘要为纯文本

- **WHEN** 带写入开关运行回填命令
- **THEN** 含真实标签标记的历史摘要 MUST 被更新为清洗后的纯文本，正文源字段 MUST 保持不变

#### Scenario: 正常纯文本摘要不被改写

- **WHEN** 某行摘要含尖括号但不构成真实标签标记
- **THEN** 回填 MUST NOT 改写该行

#### Scenario: 重复执行无二次改动

- **WHEN** 回填命令在已清洗的数据上再次执行
- **THEN** 受影响行数 MUST 为 0（或仅统计无实质改动的行），数据 MUST 保持不变
