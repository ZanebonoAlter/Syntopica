# analysis-method-library Specification

## Purpose
全局分析方法卡库：存放具有明确适用条件、禁用条件、证据要求、分析步骤和失败模式的方法，而不是作者人格或文风画像。系统只在具体调查问题适配时选择少量方法，并与事实简报阶段隔离。

## Requirements

### Requirement: 分析方法卡模型

分析方法卡 SHALL 包含名称、标题、摘要、适用条件、禁用条件、所需证据、常见失败模式、操作指引、enabled 开关及创建/更新时间。方法卡 SHALL 为全局库但 MUST 经问题适配选择后才能使用，不得因全局可用便注入所有分析。

#### Scenario: 方法卡声明适用边界

- **WHEN** 用户创建或编辑一张方法卡
- **THEN** 卡片可明确填写 applicable_when、avoid_when、required_evidence 与 failure_modes，不能只有一段无边界的作者画像

#### Scenario: 停用即时生效

- **WHEN** 用户将方法卡设为 disabled 后发起新调查
- **THEN** 该卡不参与选择且无需重启服务，既有结果中的 method_refs 保持不变

### Requirement: 分析方法 CRUD

系统 SHALL 提供方法卡列表、详情、创建、更新、软删除与启停能力。单用户系统 MUST NOT 引入权限体系。管理界面 SHALL 使用“分析方法”而非“参考角色”作为用户术语。软删除的方法不再参与选择，但历史结果 SHALL 通过固化的方法标题、内容 hash 与 input snapshot 保持可追溯。

#### Scenario: 手工创建因果检验方法

- **WHEN** 用户录入一张包含适用边界和反证要求的“因果链检验”方法并启用
- **THEN** 方法入库，可供后续适配的问题选择，但不会自动影响所有简报和调查

### Requirement: 按问题选择零到两张方法卡

系统 SHALL 在深度调查开始时，先根据“用户问题 + 父简报观察/未知项”读取 enabled 方法卡的名称、摘要与选择元数据，选择 0-2 张最适配的方法；此时尚未生成候选假设。只有选中后才加载完整操作指引，并用其证据检查清单辅助假设生成。`avoid_when` 命中 SHALL 优先阻止选择。没有适配方法时 SHALL 选择 0 张并正常调查。

#### Scenario: 没有适配方法

- **WHEN** 所有 enabled 方法都与调查问题不匹配或命中 avoid_when
- **THEN** method_refs 为空，调查继续使用基础多假设与反证流程，不强塞最接近的方法

#### Scenario: 多张方法同时可用

- **WHEN** 三张以上方法都可能适配
- **THEN** 系统最多选择两张，并记录选择理由与 method_refs，防止 prompt 膨胀和方法互相冲突

#### Scenario: 方法删除后历史仍可追溯

- **WHEN** 用户删除一张已被历史调查使用的方法卡
- **THEN** 卡片软删除且不再参与新调查，历史 result 仍保留方法标题、content hash 与当时实际注入快照

### Requirement: 方法卡与事实阶段隔离

版块简报、态势卡和事实观察提取阶段 MUST NOT 注入任何方法卡。选中方法仅可约束调查的假设生成、证据需求和最终综合；研究 agent 只接收由方法导出的核查任务，不接收作者人格与修辞模板。

#### Scenario: 简报不受方法卡文风影响

- **WHEN** 库中启用了结构性分析方法卡后生成版块简报
- **THEN** 简报 prompt 与输出不包含该卡全文，不因此强制产生结构命题、历史类比或固定句式

#### Scenario: 方法只影响调查步骤

- **WHEN** 某调查选择“历史对照”方法卡
- **THEN** 系统要求核查相似机制与差异条件；若材料不足则记录方法不适用，不得为满足方法而编造历史案例

### Requirement: 方法提供过程而非事实或文风

方法卡 MUST NOT 作为 evidence source，也 MUST NOT 要求模仿具体作者的人格、立场、情绪、金句或固定“不是…而是…”等句式。卡片中的示例仅用于解释步骤，不得被当作当前问题的事实。最终报告事实仍须来自 lane/news/web/page 证据。

#### Scenario: 方法卡不进入证据链

- **WHEN** 调查使用一张方法卡完成
- **THEN** 报告可记录 method_refs，但 evidence_chain 不出现 source_type=method，事实性结论不得引用方法卡示例

#### Scenario: 固定修辞被拒绝

- **WHEN** 方法内容要求每个问题都用固定反转句或金句收束
- **THEN** 系统将该要求视为不合规方法内容，不把它注入调查 prompt

### Requirement: 方法注入可追溯且受预算控制

每次调查 SHALL 记录候选方法摘要、最终 method_refs、选择理由及实际注入内容。完整方法正文的总注入量 SHALL 受预算控制；超限时 MUST 按卡片整体舍弃，不得撕裂单卡内容，并在调用日志留痕。

#### Scenario: 两张方法正文超限

- **WHEN** 两张选中方法的完整内容超过注入预算
- **THEN** 系统按相关性保留更适配的一张，记录另一张未注入及原因，调查继续

### Requirement: 旧参考角色非破坏迁移

既有参考角色文档 SHALL 保留原文并迁移为默认 disabled 的 legacy 方法记录，MUST NOT 自动继续参与 prompt。系统不得自动把作者风格画像宣称为合规方法卡；用户需补齐适用边界并人工启用。

#### Scenario: 迁移内部看美国画像

- **WHEN** 数据库存在 enabled 的《内部看美国·方法论画像》并完成升级
- **THEN** 原文仍可在方法管理界面查看，但默认 disabled 且标注需人工整理，新简报与调查不会自动注入它

#### Scenario: 空方法库行为正常

- **WHEN** 没有任何 enabled 方法卡
- **THEN** 版块简报与深度调查均可正常执行，不报错、不降级为失败
